## Context

Ревью 2026-09-17 (`10fb970`) нашло четыре дефекта корректности и несколько
сопровождающих проблем; proposal называет их с точными местами. Все
затронутые capabilities уже перенесены в OpenSpec (`SOURCE-OF-TRUTH.md`),
поэтому правятся их main specs через дельты этого change. Существующие
механизмы, на которые опирается дизайн: `versionContracts` как единая
лестница версий (internal/runtime/versions.go:20), savepoint-откат бюджета
команды (internal/local/store.go:1072), cut-фильтрация событий в мониторе
(internal/runtime/monitor.go:177), `mutatingCommands` как таблица фактов
(cmd/prifly/main.go:309).

## Goals / Non-Goals

**Goals:**

- Read view и телеметрия на фиксированном cut видят только переходы своего
  среза — без изменения read-версий и сохранённых байтов.
- Ошибка наблюдения workspace перестаёт означать «изменений нет»; оба случая
  («не наблюдаемо», «наблюдение сломалось») получают именованные отказы.
- Телеметрия команды не может пережить COMMIT при превышении allowance.
- `claim create-set` открывается на запись и проходит сквозную проверку.
- Сопровождающие правки: честные бенчмарки, граница процессов preflight,
  N+1 в `SessionTasks`, лестница `Next`, типизированные коды проекта,
  один `schema-gen` на гейт.

**Non-Goals:**

- Не переписывать канонические state bytes, packer или схему pinned_bytes:
  стоимость мутации растущих Run — сначала измерение, отдельный change.
- Не удалять и не ослаблять `foreign_key_check`/max-cut верификацию; только
  измерение их стоимости при инкрементальном открытии.
- Не менять published schemas, read-версии, `Next`-контракты существующих
  состояний и тексты замороженных runner-ов.
- Не закрывать формальную приёмку P1/P2 и не трогать historical evidence.

## Decisions

1. **Верхняя граница гидрации — snapshot `EventSeq`.** `hydrateTransitions`
   принимает параметр `through int64`, а запрос `ReadEventsOfType` получает
   `seq <= through` на каждой странице. `View` передаёт `read.Snapshot.EventSeq`,
   телеметрия — `snapshot.EventSeq` среза; снапшот-переходы legacy-Run
   остаются как были. Альтернатива — читать «до текущего» и фильтровать
   после: отвергнута, потому что отфильтрованный на Go уровень опять
   полагается на читателя, а не на хранилище. Существующие тесты
   `TestTelemetryExactDistributionAndFixedKnowledgeCut` и
   `TestTelemetryReadOnlyFixedCutWhileControlWriterCommits` уже гоняют
   фиксированный cut — регресс добавляет коммит перехода *после* среза.

2. **Два именованных исхода наблюдения workspace.** Ошибка `workspaceMark`
   до исполнения на claimed git-worktree — отказ с кодом (наблюдение
   сломалось), а не `measured=false`; «не репозиторий» остаётся отдельным
   осознанным случаем, но больше не ловит произвольные ошибки Git: claim
   всегда worktree (worktrees.go:190). После исполнения ошибка сравнения
   НЕ читается как «пусто»; result отклоняется именованным отказом, как
   malformed report. Коды отказа — через типизированный `runtime.Fault`;
   текст — объяснение, не носитель кода (refusal-check).

3. **Savepoint вокруг сэмплов команды.** `recordCommandSamples` оборачивает
   `insertSamples` в `SAVEPOINT command_samples`; при `ErrSampleLimit` —
   `ROLLBACK TO`, сэмплов нет, команда и её receipt сохраняются. Паттерн уже
   есть для storage-бюджета (store.go:1072). Альтернатива — предвычислять
   размер пакета до вставки: отвергнута, потому что allowance проверяется по
   фактически выделенным страницам SQLite, а не по размеру входа.

4. **Режим открытия рядом с фактом, а не во второй таблице.** Минимальная
   правка — добавить `create-set` в `mutatingCommands` и в
   `TestEveryMutatingCommandOpensForWriting` оба направления. Долгосрочная —
   деривация режима из регистрации команды; это отдельная задача того же
   change, без смены публичного поведения остальных команд.

5. **Бенчмарки создают реальные Runs.** Фикстуры используют CAS-создание с
   версией 0 (как store_test.go:37), ассертят количество событий и объём
   байт до `b.ResetTimer()`. Старые числа бенчмарков не переписываются
   задним числом: корректное измерение записывается новым срезом.

6. **Один бинарник `schema-gen` на гейт.** `check-schema.py` собирает его
   один раз во временный каталог и вызывает на каждый выбор; сравнения байт
   и immutable-хэши не меняются. Замер warm-cache до/после — часть задачи,
   не обещание ускорения.

7. **Preflight — процессная группа.** `setpgid` + завершение группы по
   таймауту/отмене и ограничение дренирования вывода; `WaitDelay` не
   останавливает выживших потомков. Managed-контракт движка это уже делает
   для рабочих процессов (local/process.go); preflight приводится к тому же
   правилу.

## Risks / Trade-offs

- [Верхняя граница может скрыть события, если снапшот и граница взяты из
  разных чтений] → граница берётся только из того же `ReadView`, что и
  снапшот; регресс гоняет коммит между двумя чтениями одного cut.
- [Отказ при «наблюдение сломалось» может остановить легитимные шаги на
  машинах с деградировавшим Git] → это требование честности: приемка без
  измерения хуже остановки; код отказа попадает в troubleshooting.md.
- [Savepoint добавляет накладные расходы на каждый командный telemetry-batch]
  → замер в тесте границы; savepoint пуст при отсутствии сэмплов.
- [`Next`-лестница в таблице — риск задеть action-логику `Next`] → правится
  только выбор версии; таблицный тест сравнивает результат старой и новой
  ветвления на каждом состоянии.
- [Процессная группа меняет поведение preflight для программ, порождающих
  демонов] → демоны и так вне контракта managed-процессов; отказ с tail'ом
  вывода называет причину.

## Migration Plan

Без миграции данных: state/read-версии не двигаются, схемы не меняются.
Внедрение по порядку дельт: срез → эффекты → сэмплы → CLI-режим →
сопровождающее. Откат — обычный revert коммитов; Runs, записанные между
правками, читаются прежними контрактами.
