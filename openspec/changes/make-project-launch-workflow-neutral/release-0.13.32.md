# Выпуск Pri-Fly 0.13.32

Тег на `df4e2f7`. Одно OpenSpec-изменение
(`name-the-work-the-next-action-would-do`) и одна починка внутри уже
объявленного обещания, обе — по наблюдениям пилота с боевых заходов.

## Что было

- `run drive` исполняет программу шага внутри вызова (так задумано и написано
  в справке), но узнать это **до** вызова было нечем: `run next` называл
  `action: stage` и `stage_id`, и молчал о том, что за работа за этим стоит.
  Пилот сцепил `run drive --next` после submit и получил семнадцатиминутный
  прогон тестов внутри харнеса вместо фонового драйвера — правило он знал,
  предупредить было нечему.
- `project workflows update` обещает сохранить `extend.yaml` и папку
  `project/` «byte for byte», и байты сохранял, а бит исполнения — нет: три
  воркера пилота (`gate.sh`, `merge-request.sh`, `tests.sh`) вернулись после
  обновления пакета неисполняемыми (`old mode 100755 / new mode 100644`).

## Что стало

- Ответ о следующем действии несёт `stage_work` при `action: stage`:
  `assisted_session` — драйвер выдаст задание хосту; `program` — исполнит
  программу внутри вызова; `control` — только продвинет граф. Род выводится из
  закреплённого определения шага этой стадии; сборка, которая определить его
  не может, поля не присылает (догадка здесь и привела бы к той самой ошибке).
  Чтение остаётся чтением: `run next` и `run explain` ничего не исполняют.
  Флаг `--no-exec` у `drive` не добавлялся — команда, которая не действует,
  уже есть и называется `run next`.
- Новое семейство read-контрактов 31 (`core-state/31`, `core-read/31`,
  `core-next/31`, `core-preview/31`, `core-step-read/31`), bundle
  `stage-work`; /30 и старше — байт в байт прежние.
- Перенос папки `project/` при обновлении сохраняет бит исполнения; файлы из
  upstream-папки пакета по-прежнему кладутся `0644` — скачанное дерево не
  приносит исполняемых файлов само.
- Обе записи добавлены в `examples/troubleshooting.md`.
