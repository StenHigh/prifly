## 1. Отношение конфликта

- [x] 1.1 Конфликт определяется занимаемым рабочим деревом. Проверка: два
      `worktree` claim одного репозитория выдаются оба, с разными путями и
      разными ветками; первое дерево переживает выдачу второго.
- [x] 1.2 `checkout` исключает и исключается всем на репозитории. Проверка:
      `checkout` отвергается при активном `worktree` claim; прежний тест на
      исключительность checkout не менялся и проходит.
- [x] 1.3 Счётчик поколений считает повторные захваты одного дерева, а не всё,
      что с ним конфликтует.

## 2. Отказ называет отношение

- [x] 2.1 `claim_conflict` называет дерево как предмет конфликта и говорит, что
      Run в другом worktree того же репозитория не конфликтует, а два Run на
      одном checkout — конфликтуют.
