## Context

Отчёт assisted-сессии — `SessionSubmission` (`internal/runtime/sessions.go`).
Прецедент того же рода — `model_profile` (0.13.4x): host говорит о себе, движок
проверяет только форму, запись хранится типизированно на Attempt
(`ModelProfileReport`), требуется с версии состояния 34, опубликована отдельным
bundle `model-profile.schema.json`. Объявленные runtime-решения уже идут через
Decision Bridge и журнал; спецификация `run-decisions` запрещает выдавать
native-диалог за DecisionRecord.

## Goals / Non-Goals

**Goals:** каждый Attempt assisted-шага в новом Run несёт явный список вопросов
и ответов с основанием; чтение Run показывает его в мониторе и `run status`.

**Non-Goals:** перехват native-диалога; проверка, что ответ правдив;
program-шаги (у программы нет диалога); переписывание прошлых Run.

## Decisions

1. **Обязательное поле, пустой список — утверждение.** Необязательное поле
   нельзя отличить от «host забыл», а цель — не оставлять оператора в
   неведении. Как у `model_profile`: молчание не ответ. Отказ
   `answered_questions_missing` с текстом, который называет форму и
   `project runners update`.
2. **Отдельная запись на Attempt, не DecisionRecord.**
   `Attempt.QuestionReport{schema_version: question-report/1, questions[]}`.
   Журнал решений остаётся журналом того, что Pri-Fly сам передал и принял.
3. **`basis` — закрытый список, ссылки проверяются.** `decision` требует
   `decision_id` из каталога Run, `input` — `port` из входов шага; остальные
   (`instructions`, `person`, `judgement`) полей-ссылок не имеют. Проверяется
   то, что движок может проверить; правдивость — нет.
4. **Пределы.** ≤32 вопросов, `question` ≤2000, `answer` ≤4000, `asked_by`
   ≤200, `options` ≤16 по ≤200 символов. Отказ называет превышенное поле.
5. **Версия состояния `core-state/41`** — для Run проекта (scoped), где есть
   хотя бы один шаг с `executor.operation: session`. Run без проекта и Run
   только из программ остаются на прежней версии: протокол для них не
   меняется. Read — `core-read/41`, next — `CoreAwaitingHostNextVersion`.
6. **Host узнаёт из задачи.** `SessionTask.question_report: "required"` в
   задаче Run на 41 — опубликовано в новом bundle вместе с полем отчёта и
   записью Attempt; прежние bundles не меняются.
7. **Инструкции runner — новый слой шаблона.** Текст о вопросах добавляется
   слоем поверх `projectRunnerSkillTemplateBeforeAwaitingHost…`, прежние
   варианты закреплены digest'ами и не меняются (как в 0.13.68).
8. **Шаблон отчёта (`session submit --template`) поле не заполняет.** Какие
   вопросы были, знает только host; пустой список, подставленный шаблоном, был
   бы ответом, которого никто не давал.
9. **Проверка контракта по bundle своей версии.** Имя `SessionTaskV7` есть в
   каждом bundle с routed-сессий, `PublicSchema` отвечает первым; тесты значений
   состояния 41 валидируют по `questions.schema.json` (`validateInBundle`).
10. **Отчёт с `decision_request`** вопросов не несёт: это не завершение
   Attempt. Вопросы приходят в итоговом отчёте после повторной выдачи.

## Risks / Trade-offs

- [Host со старым `prifly-run` на 41 получит отказ] → текст отказа самодостаточен
  (что прислать и как обновить); пилот и пакет уведомляются после релиза.
- [Агент может занизить список] → движок не может это проверить; монитор
  называет запись «заявлением исполнителя».
- [Потолок числа версий состояния] → снят владельцем 2026-09-19; стоимость —
  новые строки в `versions.go` и тестах версий, прецедент 34.
