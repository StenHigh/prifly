# Сохранять bindings и feature declarations при variant lowering

**Date:** 2026-11-01 17:45
**Files:** cmd/prifly/project_unified_variants.go, cmd/prifly/project_unified_options.go, schemas/authoring/project-workflow-folder-v3.schema.json
**Severity:** high

## Проблема

Unified compiler отвергал внешние schema refs в root bindings. Два variants одного source с features давали duplicate declaration. Exclude молча перекрывал explicit true setting.

## Причина

Variant builder принимал каждый placeholder за owned component. Package-wide feature collector считал source clones независимыми declarations. Scoped settings исчезали из options до проверки exclude. Новый closed folder reader также не разрешал существующие package profiles.

## Решение

Builder перестраивает только owned/imported component aliases. Обычный resolver получает внешние refs и late-bound values. Feature policy применяется к каждому variant; origin определяет уникальность declaration. Explicit variant settings сохраняют конфликт с exclude. Новая folder /3 schema разрешает прежнюю форму profiles; старые схемы не меняются.

## Предотвращение

Проверять одинаковый source под разными settings и aliases. Разные source declarations должны сохранять duplicate refusal. Проверять exclude с true, false и отсутствующим setting. Проверять literal bindings с external schema refs и profile values через полный compile. Не считать каждый placeholder ссылкой на исходный component.
