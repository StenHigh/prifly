## Purpose

Определяет единый локальный интерфейс наблюдения за всеми сохранившимися Run пользователя ОС: полноту обнаружения, понятную навигацию и отображение записанных фактов без вмешательства в исполнение.

## Requirements

### Requirement: Общий список охватывает сохранившиеся локальные Run
Монитор SHALL объединять Run из обнаруженных и зарегистрированных локальных хранилищ текущего пользователя ОС, включая старые и тестовые. Поиск MUST выполняться фоном с видимой областью, прогрессом и ошибками; неполное обнаружение не называется полным. Один физический источник не дублируется из-за альтернативного пути. Недоступный, повреждённый либо несовместимый источник MUST быть видим отдельно и не скрывать здоровые источники. Удалённые Run восстанавливать не требуется. Источник истины — существующая authority; каталог монитора не создаёт право управления.

#### Scenario: Несколько проектов и старые запуски
- **WHEN** пользователь открывает монитор с несколькими локальными authority, в том числе нестандартно расположенными
- **THEN** найденные Run доступны в одном списке, новые источники появляются по мере поиска, а область и неполнота поиска видны

#### Scenario: Источник недоступен
- **WHEN** один источник не удаётся прочитать
- **THEN** монитор показывает ошибку этого источника и продолжает показывать остальные

### Requirement: История имеет поиск и постраничную навигацию без общего предела
Монитор SHALL предоставлять поиск по задаче, Run и сценарию, фильтры проекта, состояния, исполнителя и периода, сортировку и постраничную загрузку. Число Run больше 200 MUST NOT приводить к отказу либо скрытому обрезанию. Прямая ссылка SHALL восстанавливать выбранные источник, Run и узел. Фильтрация применяется ко всей доступной истории, а неполный индекс отмечается.

#### Scenario: История больше одной страницы
- **WHEN** в хранилище есть более 200 Run и искомый запуск не находится на первой странице
- **THEN** он доступен поиском и переходом по страницам без обхода лимитов полного telemetry scan

### Requirement: Обзор и схема отражают закреплённый сценарий Run
Обзор SHALL показывать задачу, проект/рабочую область, сценарий, состояние, итог, причины ожидания, решения и диагностику. Читательская подпись сохранённого состояния SHALL объяснять его жизненный этап, не меняя код или семантику состояния: `ready` MUST явно означать подготовленность к выдаче Attempt, а не завершение; `pending` MUST отличаться от запущенной работы; `running` MUST означать фактически начатое исполнение. Схема SHALL показывать все узлы и соединения закреплённого workflow, развилки, параллельные пути и предстоящие стадии, а дерево — реальные WorkflowInvocation, StageActivation, StepInstance и Attempt. Схема выбранного WorkflowInvocation SHALL выделять фактический путь, текущую работу и достижимое продолжение; исключённые ветви остаются видимыми, но отличаются рамкой и подписью причины. Причина исключения MUST опираться на записанное решение маршрутизации, terminal outcome либо иной сохранённый факт; при отсутствии такого факта монитор MUST показывать состояние как неизвестное, а не придумывать причину. Соединения SHALL иметь различимые каналы, а основной путь не должен смешиваться с исключёнными, return и terminal routes. Выбор узла SHALL открывать карточку с закреплённым описанием, входящими и исходящими переходами, доступными записанными данными и причиной его фактического состояния или отсутствия исполнения. Будущий узел определения не является созданной Attempt; невыбранная ветвь отличается от предстоящей, ошибочной и завершённой работы. Неизвестное число будущих итераций не изображается выполненной работой.

#### Scenario: Шаг создан, но не передан агенту
- **WHEN** StageActivation или StepInstance имеет записанное состояние `ready`
- **THEN** монитор показывает, что работа подготовлена к выдаче Attempt и ещё не означает ни запуск, ни успешное завершение

#### Scenario: Задание передано до запуска процесса
- **WHEN** Attempt имеет записанное состояние `pending`
- **THEN** монитор отличает переданное агенту задание от фактически начатого исполнения

#### Scenario: Сценарий изменили после старта
- **WHEN** установленная версия сценария изменилась после создания Run
- **THEN** схема Run по-прежнему строится из его закреплённых определений

#### Scenario: Плотная развилка выбранного исполнения
- **WHEN** выбранный WorkflowInvocation содержит несколько ветвей или соединений у одного узла
- **THEN** фактический путь, достижимое продолжение, return/terminal routes и исключённые альтернативы различимы, а соединения не накладываются на основной путь

#### Scenario: Исключённая ветвь
- **WHEN** сохранённое решение маршрутизации исключило стадию закреплённого Workflow
- **THEN** стадия остаётся на схеме с подписью «Пропущен» и записанной причиной выбора

#### Scenario: Карточка будущей либо исключённой стадии
- **WHEN** пользователь выбирает узел без созданной StageActivation
- **THEN** монитор показывает закреплённое описание и переходы узла, а также явно отделяет отсутствие исполнения от отсутствия определения

#### Scenario: Вложенные сценарии и параллельные попытки
- **WHEN** Run содержит несколько включений, ветвей или попыток
- **THEN** их identities сохраняются в дереве и выбранные подробности не смешиваются
### Requirement: Подробности показывают переданное задание и сохранённые результаты
Монитор SHALL человекопонятно показывать записанное задание попытки, инструкции и контекст, входы, сведения об исполнителе, полученный кандидат и принятый результат, проверки, выходные артефакты и журнал Pri-Fly. Полные структурированные данные остаются доступны для разбора. Просмотр содержимого артефакта SHALL явно сообщать объём и обрезание предпросмотра. Список файлов SHALL опираться только на сохранённые manifests/evidence и не выдавать текущие изменения рабочей папки за исторический результат шага. Diff, переписка чатов, вызовы инструментов и stdout/stderr не входят в этот срез.

#### Scenario: Задание выдано, результат не поступил
- **WHEN** Attempt передана внешнему исполнителю
- **THEN** пользователь видит переданное задание и ожидание результата, без утверждения о живом процессе агента

#### Scenario: Список файлов не записан
- **WHEN** сохранённые данные не позволяют установить изменения файлов
- **THEN** интерфейс обозначает сведения как недоступные, а не показывает ложный пустой список

### Requirement: Метрики и обновления сохраняют достоверность и место чтения
Монитор SHALL показывать записанные время, стоимость, tokens/model/reasoning, когда такие сведения действительно присутствуют. Неизвестное не заменяется нулём, а сообщения стоимости разных источников/валют не складываются в выдуманный счёт. Русский интерфейс SHALL поддерживать системную светлую/тёмную тему, клавиатурную навигацию и явные состояния загрузки/ошибки. Изменения доступного источника SHALL проверяться каждые 1–2 секунды; длительная загрузка обозначается, запросы не накладываются бесконечно. Обновление MUST сохранять выбор, раскрытые подробности и позицию чтения.

#### Scenario: Пользователь читает подробности работающего Run
- **WHEN** источник обновился во время чтения
- **THEN** данные обновляются без сброса выбранного шага и места чтения

### Requirement: Монитор остаётся локальным наблюдателем
Монитор MUST слушать только loopback, проверять Host, не давать CORS-доступ произвольным сайтам и не исполнять содержимое Run/артефактов как HTML. Обычные HTTP endpoints SHALL принимать только операции чтения. Исключение — явно подтверждённое локальное обслуживание завершённых Run: отдельный POST с проверкой Origin, случайного same-origin token, владельца, текущих прав и идентичности источника. GET MUST NOT удалять данные. Произвольный путь из HTTP запроса не открывается как новый источник. Разрешения чтения и проверка владельца authority сохраняются; опубликованные контракты и историческое evidence не переписываются.

#### Scenario: Посторонняя web-страница или вредоносный текст
- **WHEN** приходит запрос с чужим Host либо записанное задание содержит HTML/script
- **THEN** запрос отклоняется либо данные отображаются текстом без выполнения и внешних запросов

### Requirement: Подробности Run открываются отдельным экраном
Монитор SHALL при выборе Run скрывать длинный список и сразу показывать подробности. Возврат SHALL сохранять фильтры, страницу и позицию списка. Прямая ссылка и кнопки истории браузера SHALL работать; опрос MUST NOT прокручивать страницу повторно.

#### Scenario: Выбор Run внизу длинной страницы
- **WHEN** пользователь выбирает Run в списке
- **THEN** подробности открываются вверху отдельного экрана, а возврат восстанавливает место списка

### Requirement: Объём найденных хранилищ измеряется фоном
Монитор SHALL показывать выделенное файловой системой место для каждого доступного authority и общий объём без повторного учёта одного inode. Измерение SHALL включать SQLite и sidecars, configured artifact/state/workspace roots и служебные файлы .prifly; внешние рабочие репозитории не считаются хранилищем. Символические ссылки не раскрываются. Недоступные источники, незавершённый обход и время измерения SHALL быть видимы. Значение MUST NOT называться точным физическим расходом APFS clones/snapshots или гарантией освобождения этого объёма.

#### Scenario: Несколько authority и повторный путь
- **WHEN** один физический файл встречается под несколькими путями, а другой источник недоступен
- **THEN** итог учитывает inode один раз и явно показывает неполноту измерения

#### Scenario: Большое хранилище
- **WHEN** подсчёт размера ещё выполняется
- **THEN** просмотр Run и опрос исполнения продолжаются независимо

### Requirement: Очистка требует конкретного подтверждения
Монитор SHALL показывать полный список удаляемых и защищённых Run, объём содержимого кандидатов, сохраняемые данные и необратимость удаления. Пользователь SHALL выбирать удаление одного Run или очистку завершённых Run конкретного хранилища. Сервер MUST повторно строить план и отказывать при изменении его состава или версий. Результат SHALL показывать фактическую выполненную часть, предупреждения и последующий пересчёт размеров.

#### Scenario: Состояние изменилось после подтверждения
- **WHEN** состав или версии кандидатов изменились после preview
- **THEN** удаление не выполняется, требуется новое подтверждение

#### Scenario: Уплотнение базы не удалось
- **WHEN** история уже удалена, но VACUUM не завершился
- **THEN** результат явно показывает удалённые Run и предупреждение, не обещая отмену операции или освобождение размера файла базы

### Requirement: Пользователь явно выбирает тему монитора
Монитор SHALL предоставлять подписанный переключатель «Тёмная / Светлая / Системная». Выбор SHALL применяться до первого отображения и сохраняться в браузере, когда локальное хранилище доступно. Системная тема SHALL следовать изменениям предпочтения ОС, ручная — сохранять выбранную палитру. Отказ локального хранилища MUST NOT блокировать страницу или переключение темы. Схема, таблицы и диалоги SHALL использовать выбранную палитру; переключатель SHALL оставаться доступным на узком экране и с клавиатуры.

#### Scenario: Сохранённый ручной выбор
- **WHEN** пользователь выбирает тёмную тему и перезагружает страницу при светлой системной теме
- **THEN** монитор применяет тёмную палитру до первого отображения

#### Scenario: Системная тема и недоступное хранилище
- **WHEN** браузер запрещает localStorage
- **THEN** монитор открывается с системной темой и позволяет изменить тему для текущей страницы

### Requirement: Отказ очистки на ссылке называет проблемные метаданные
Если подготовка очистки обнаружила символическую ссылку в общих метаданных authority, монитор SHALL показать код `unsafe_path`, относительный путь ссылки и объяснение причины. Проверка SHALL действовать для адресной и общей очистки и повторяться перед удалением. Отказ MUST NOT удалять Run или следовать ссылке. Перенос тестовых файлов за пределы метаданных SHALL позволять повторить штатный предпросмотр без ослабления защиты.

#### Scenario: Тестовая ссылка мешает удалению завершённого Run
- **WHEN** метаданные `.prifly` содержат тестовую символическую ссылку
- **THEN** подготовка удаления отказывает, указывая эту ссылку, а Run и внешняя цель сохраняются

### Requirement: Список показывает происхождение связанных Run

Общий список монитора SHALL по умолчанию представлять сохранённую связь `fork.source_run_id` между Run одного authority как иерархию: исходный Run выше производных, каждый следующий уровень имеет больший отступ и читаемую текстовую подпись связи. Восстановление, записанное также в `recovery`, MUST NOT создавать второго родителя или изображаться как дочерняя WorkflowInvocation. Каждая строка SHALL сохранять собственные status, outcome, время и прямую ссылку; группа MUST NOT получать выдуманный общий outcome. Одинаковые названия задачи без записанной связи MUST NOT объединять независимые Run в одну цепочку.

Ветви SHALL иметь доступное с клавиатуры раскрытие и сворачивание с количеством скрытых Run; обновление SHALL сохранять раскрытие, выбранный Run, фильтры и место чтения. В иерархическом виде SHALL быть доступен выбор порядка корней и соседних производных Run по `created`: ранние сверху (по умолчанию) или ранние снизу, с устойчивым порядком по ID при равном времени; предок остаётся выше потомков, поэтому общий порядок разных ветвей не выдаётся за глобальную временную шкалу. SHALL быть доступен плоский хронологический вид. Поиск/фильтры MUST сохранять найденный производный Run и показывать его происхождение как контекст, даже если исходный Run сам не совпадает с фильтром. Пагинация MUST охватывать полную доступную историю без скрытого обрезания и не оставлять строку производного Run без объяснения её родителя. При недоступном исходном Run монитор SHALL показать записанный `source_run_id` и обозначить, что исходный Run отсутствует в доступном каталоге; он MUST NOT угадывать связь по названию или связывать Run разных authority.

Строка ветви с производными Run SHALL отдельно показывать статус/итог самого позднего по `last_observed` доступного производного Run и прямую ссылку на него, даже когда ветвь свёрнута. Подпись MUST явно отличать этот факт от собственного status/outcome родительского Run и MUST NOT объявлять его общим итогом ветви. При равном времени выбор SHALL быть устойчивым по Run ID; фильтр MUST NOT превращать более старое совпадение в «последний Run» всей доступной ветви.

#### Scenario: Ветвящееся продолжение задачи #154
- **WHEN** один исходный Run имеет несколько прямых fork, а один из них породил восстановительные fork
- **THEN** список показывает исходный Run, прямые продолжения с одним отступом и восстановления с ещё большим отступом, с отдельным состоянием каждой строки и управлением раскрытием ветвей

#### Scenario: Последнее восстановление успешно после ошибки родителя
- **WHEN** исходный Run и промежуточное продолжение завершились с ошибкой, а самое позднее восстановление под свёрнутым продолжением завершилось с `outcome=succeeded`
- **THEN** строка продолжения сохраняет собственную ошибку и отдельно показывает «Последний производный Run: выполнен» со ссылкой на успешный Run; тот же факт доступен на строке исходного Run

#### Scenario: Чтение ветви по хронологии
- **WHEN** у исходного Run есть несколько продолжений и восстановлений, созданных в разное время
- **THEN** каждый уровень ветви располагает более ранние Run выше более поздних, а последний производный Run дополнительно виден на свёрнутом предке

#### Scenario: Чтение ветви с ранними Run снизу
- **WHEN** пользователь выбирает обратный порядок связанных Run
- **THEN** корни и соседние Run каждого уровня располагаются от поздних к ранним без потери пагинации, а исходный Run остаётся выше своих производных

#### Scenario: Та же задача запущена независимо
- **WHEN** другой Run имеет тот же заголовок `#154`, но не содержит fork provenance к этой цепочке
- **THEN** он остаётся отдельным корнем, а интерфейс не выдаёт совпадение задачи за продолжение

#### Scenario: Фильтр совпал только с производным Run
- **WHEN** поиск или фильтр выбирает производный Run, но не его исходный Run
- **THEN** найденный Run доступен, путь к нему показан как явно отмеченный контекст и счётчик результатов не считает контекст дополнительным совпадением

#### Scenario: Исходный Run недоступен
- **WHEN** `fork.source_run_id` указывает на Run, которого нет в доступном каталоге этого authority
- **THEN** производный Run остаётся в списке с подписью записанного источника и указанием недоступности, без фиктивного родительского статуса

#### Scenario: Большая история и обновление
- **WHEN** история содержит более 200 Run, одна ветвь длиннее страницы, а новые Run появляются при чтении
- **THEN** пользователь может добраться до каждого Run, раскрытие и место чтения сохраняются, а переходы страниц не теряют контекст цепочки
