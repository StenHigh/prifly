## Context

База планирования — `a8a7620c`, поставка `v0.13.93`. Браузерный аудит проверил ожидание ответа, истечение срока Attempt и успешное завершение. В Full причина ошибки была видна в обзоре, но отсутствовала в панели Attempt. Возврат с прямой ссылки на телефоне шириной 375 px оставлял дерево под схемой. В Light переполнение воспроизвелось на длинной строке стадии и ветви в истории задачи.

[Действующая спецификация Full](../../../specs/local-run-monitor/spec.md) определяет ссылки, свежесть и независимое наблюдение. [Общие UX-правила](../../../specs/control-security-ux/spec.md) определяют достоверность объяснений и мобильное чтение. [Действующий Light change](../../add-prifly-light-task-board/read-contract.md) определяет состав и доступность проекции. Дельта Light в `control-security-ux` уточняет браузерные действия поверх этой проекции.

## Goals / Non-Goals

**Goals**

- Использовать текущие GET-ответы и существующие границы чтения.
- Доводить явный переход от причины до точной записи или честно названного раздела.
- Сохранять выбор, фокус и технические сведения при переходах и обновлении.

**Non-Goals**

- Ответ на вопрос, возобновление или иная управляющая команда из монитора.
- Новые поля и версии JSON, Go endpoints, workflow mappings, изменения replay и миграции хранения.
- Изменение каталога Full, схемы выполнения, приёмки review или открытых выпускных ворот Light.

## Decisions

### D1. Один способ определить цель в Full

Обзор и наблюдение используют один разбор причины и один построитель перехода на данных текущего `/api/run`. Причина остаётся привязана к источнику, Run и сохранённой Attempt либо StageActivation. Для вложенного исполнения переход указывает на его WorkflowInvocation по сохранённой связи. Ссылка «Открыть Run» остаётся доступна отдельно.

Для ожидающего вопроса использовать `pending_decision` и уникальную запись `decision_ledger`. Сверять `definition_id`, `attempt_id` и `definition_digest` с записанными значениями. Параметры фрагмента адреса содержат только идентификаторы цели. При переходе Full повторно сверяет цель с прочитанным Run. Если ответ уже поступил, Full показывает эту же запись как отвеченную. При неоднозначности, устаревшей ссылке или неполных данных Full открывает раздел решений и объясняет ограничение. Текст, варианты и значения выводятся как данные, с существующими ограничениями раскрытия.

Для события нужен подтверждённый номер записи в этом Run. Если текущий ответ его не даёт, переход открывает журнал с соответствующей подписью. Для объяснений, которым нужен отдельный снимок ресурсов или допуска, наблюдение показывает только уже доступные факты. Бюджет остаётся прежним: до двух `/api/run` и двух `/api/progress` за цикл. Скрытые вкладки не опрашиваются.

### D2. Причина остаётся рядом с выбранной Attempt

В начале панели Attempt показывать её состояние и связанную диагностику. Сверять `attempt_id`, Run и `stage_activation_id`, когда последнее поле записано. При нескольких относящихся к Attempt записях показывать подтверждённые причины с их кодами. Исторические записи можно прочитать в их собственной Attempt. При недостаточной связи использовать существующий раздел диагностики и явное неизвестное.

На узком экране возврат использует сохранённый источник, Run, WorkflowInvocation и ID узла. Дерево раскрывает предков и переводит фокус к видимой строке. Для старой ссылки без доступного узла цель возврата — заголовок дерева. При переходе в другой Run прежняя цель возврата очищается. Polling сохраняет текущий фокус.

```text
Обзор или наблюдение
    ├── ожидающий вопрос → точная запись в решениях
    ├── ошибка Attempt   → сведения с причиной → узел дерева
    └── событие         → точная запись в журнале
```

### D3. Light читает до двух выбранных Run

Выбор начинается с конкретной записи Run на доске или в истории задачи. Если компактная карточка не содержит точного Run, она ведёт к списку записей задачи. В памяти вкладки сохраняются идентичность источника и Run, ключ задачи для повторного чтения и порядок. Снимки в постоянное хранилище браузера не записываются. Память выбора Light независима от Full.

На компьютере показать компактные строки. На телефоне перенести поля строки под названием. При возврате из наблюдения восстановить доску или задачу, фильтры, страницу и доступное место чтения. Истёкшая страница сохраняет фильтры и использует действующее обновление страницы.

Каждый цикл читает первую ограниченную страницу существующего относительного `api/light/task` один раз на пару источник и ключ задачи. Два Run одной задачи используют один ответ. Два разных чтения обновляются независимо. Выбранный Run принимается только по точной идентичности в странице или в доступной компактной проекции. Для сокращённой проекции явно обозначать недоступные детали. Пустой ответ, устаревший ответ и ответ по другому выбору обрабатываются раздельно.

Для временного сбоя можно показать явно устаревший снимок этой записи. При `light_access_denied` убрать содержимое снимка и сохранить место с сообщением об отказе. Если запись вышла из ограниченного окна, оставить ссылку на задачу для ручного перехода по её страницам. Автоматический опрос не обходит историю. Источник свежести — чтение Light и записанное наблюдение. Прогресс программы и драйвер читаются в Full. Ссылки строятся от настроенного Full URL и работают с существующим proxy prefix.

### D4. Длинные значения переносятся в месте чтения

Исправить перенос строки стадии и ветви в истории Light. Проверить также длинные названия, идентификаторы и раскрытые подробности. Ограничение ширины применяется к строкам и их текстовым дочерним блокам. Полные значения остаются доступными. При обычных коротких названиях обе строки наблюдения видны на 390×844, включая состояние, причину и переход. При длинных данных допустима вертикальная прокрутка.

## Risks / Trade-offs

| Риск | Проверяемое решение |
|---|---|
| В параллельных ветвях есть похожие вопросы и отказы | Сверять сохранённые идентификаторы. При отсутствии однозначной связи использовать названный раздел |
| Одна карточка Light вышла из первой страницы | Сохранить выбор, обозначить неполноту и дать переход в историю задачи |
| Переход или сбой чтения меняет фокус в соседней карточке | Связать ответ с точным выбором, отменять устаревшие запросы и проверять фокус в браузере |
| Наблюдение увеличивает стоимость чтения | Измерить GET-запросы. Для Light разрешить до двух ограниченных чтений задач за цикл. Для Full сохранить текущий бюджет |

## Migration Plan

Существующие адреса Full и Light сохраняют значения. Новый фрагмент точной ссылки относится только к представлению Full. При откате прежний Full открывает Run и известную вкладку по существующим параметрам. Закрепления Light живут в памяти вкладки. Изменение поставляется с обычной сборкой Pri-Fly.

При последующей синхронизации дельты идут в `local-run-monitor` и `control-security-ux`. Приёмка и перенос источника требований `prifly-light` остаются в `add-prifly-light-task-board`.
