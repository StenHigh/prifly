## ADDED Requirements

### Requirement: Срок Attempt не является временем жизни Run
Run MUST NOT иметь скрытый часовой срок жизни. Новый timed assisted contract
MUST сохранять конечный рабочий остаток, фазу и observations, необходимые
для продолжения после restart. При переходах между активной доставкой,
объявленным ожиданием и ожиданием повторного допуска остаток MUST не
увеличиваться. Клиентский timestamp, clock rollback и повторная команда MUST
не продлевать право. Assisted wall-clock qualification MUST оставаться
явной; режим не обещает измерение CPU-времени или контроль host process.

Новая доставка MUST связывать exact исходное задание, выбранный ответ,
актуальные сроки и поколение проверяемым digest. Старый envelope MUST не
переписываться. Новые поля и смысл MUST иметь versioned contracts; сохранённые
старые Runs сохраняют прежние bytes и absolute deadlines. Недели ожидания
MUST NOT объявляться поддержкой многонедельного managed OS-процесса.
Source set — `openspec/specs/runtime-resources/`, sync только при реализации.

#### Scenario: Восстановление ожидающего Run
- **WHEN** authority снова открыта после двух недель без процесса driver
- **THEN** ожидание, остаток, refs и история восстановлены без нового Run,
  автоматического запуска host или пересчёта бюджета от времени открытия

#### Scenario: Часы идут назад
- **WHEN** новое наблюдение противоречит сохранённой временной границе
- **THEN** чувствительное продолжение отвергается без добавления времени,
  а replay использует прежние принятые observations

### Requirement: Ожидание решения освобождает исполнение но сохраняет обязательства
Новый совместимый host MUST явно передать управление через DecisionRequest,
после которого прежняя доставка не даёт права продолжать работу. Принятое
безопасное ожидание MUST освобождать execution capacity и не учитываться как
исполняемая работа в workflow parallelism. Attempt, pins, outputs, claims и
неурегулированные обязательства MUST сохраняться; ожидание не является
settlement или доказательством остановки чужого OS-процесса. Наличие
незавершённого эффекта, препятствующего безопасной передаче управления,
MUST давать явный отказ до такого освобождения, а не потерю обязательства.

Повторный допуск той же Attempt MUST соблюдать обычные capacity/fairness,
current control, revocation и resource generation checks атомарно с новой
доставкой. Ожидание одной ветви MUST не скрывать отмену, готовую независимую
работу либо результат sibling. Поддержка одного pending question MUST не
выдаваться за несколько одновременных диалогов.

#### Scenario: Один Run ждёт человека а другой исполняется
- **WHEN** при capacity 1 Run A безопасно перешёл к вопросу без finite timeout
- **THEN** независимый Run B может получить slot; A сохраняет свой вопрос и
  не получает вторую исполняемую Attempt до разрешённого повторного допуска

#### Scenario: Ожидающий шаг удерживает checkout
- **WHEN** execution slot освобождён, но claim ещё принадлежит этому Run
- **THEN** другой Run не получает этот checkout по одному истечению lease;
  перед продолжением владелец видит и выполняет требуемый recovery

### Requirement: Истечение и отмена вопроса не создают ложный исход
Истёкшая доставка MUST NOT быть выдана как исполнимая новая задача. Read-only
представление MUST показывать причину и recovery, а не одно бессодержательное
idle. Cancel MUST обрабатываться и при открытом вопросе; отсутствие ответа
не блокирует управляющую команду. Уже переданная host работа MUST NOT получать
выдуманный ProcessOutcome или подтверждение отсутствия эффекта.

При неизвестном значимом исходе MUST сохраняться uncertain obligation и
положенный recovery. При доказанном отсутствии незавершённых значимых
обязательств отмена MUST завершаться без ответа на вопрос. Ни один путь не
должен скрыто повторять прежнюю работу или освобождать чужой claim.

#### Scenario: Отмена шага без значимых эффектов
- **WHEN** владелец отменяет ожидающий вопрос effects:none шага без иных
  неурегулированных обязательств
- **THEN** отмена завершается с сохранённой историей, без фиктивного process
  exit и без принятия позднего host result

#### Scenario: Host мог оставить неизвестный эффект
- **WHEN** ожидание или активная доставка истекли при таком обязательстве
- **THEN** Core сохраняет неопределённость и recovery, не превращает её в
  success, обычный retry или доказанное отсутствие работы
