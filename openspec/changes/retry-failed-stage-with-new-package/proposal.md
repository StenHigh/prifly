## Why

Технический отказ при приёмке результата поздней стадии заставляет запускать новый continuation с самого `verify`, хотя предыдущие `verify` и `review` уже приняты. На реальном Run тестовая программа завершилась с кодом 0, но схема пакета отвергла 58 `extra_filters` при лимите 20; повтор тяжёлых навыков и тестов не добавляет качества, если их точные результаты можно проверить и использовать повторно.

## What Changes

- Добавить явное восстановление технически failed Run через новый связанный Run с исправленным, заново закреплённым пакетом; исходный Run и его история остаются неизменными.
- Перед созданием нового Run показывать read-only план: точка отказа, старые и новые exact refs, доказуемо пригодный префикс завершённых стадий, состояние candidate результата и причины, по которым reuse запрещён.
- Разрешить reuse только принятых результатов с проверенными immutable bytes и неизменным предметом проверки (включая Git tree, inputs, context, executor и checks). Для технически отвергнутого результата разрешить повторную приёмку сохранённого candidate только при доказанных bytes, завершённом исполнении и совместимой новой схеме; иначе выполнить лишь отказавшую стадию заново.
- Начать новый Run на первой неперенесённой стадии, а не с entry workflow; сохранить source provenance, отдельные новые identities, решения допуска и объяснимый след каждого reuse. При несовместимости графа, незакрытом эффекте, stop или недостатке evidence — отказ до исполнения, без автоматического пропуска.
- Дать Project CLI команду для этого маршрута и отобразить связь source/recovery в чтении Run и локальном мониторе. Существующие `run reopen`, `run fork` и `project continue` сохраняют прежний смысл.

## Capabilities

### New Capabilities

- `failed-run-package-recovery`: проверяемое восстановление технически failed Run на новой версии пакета с переносом только пригодного evidence и точной точкой продолжения.

### Modified Capabilities

- `runtime-resources`: уточнить границу recovery/fork, закрепление нового Run и запрет reuse неурегулированных эффектов.
- `domain-execution`: определить совместимость старых и новых результатов, candidate и проверяемого Git tree.
- `cli-protocol`: добавить проверяемый Project prepare/start и объяснимые отказы/проекцию связанного Run.
- `local-run-monitor`: показывать новый Run как восстановление с указанием перенесённых и повторяемых стадий, не перекрашивая историю source Run.

## Impact

Изменение затрагивает product runtime, не процесс OpenSpec. Нормативные источники перечисленных capabilities остаются в текущих `openspec/specs/**` по `openspec/SOURCE-OF-TRUTH.md`; ownership не переносится. Реализация затронет `internal/runtime/`, `internal/local/`, `internal/flow/` при необходимости нового versioned state/protocol, `cmd/prifly/`, monitor, схемы и e2e/compatibility tests. Исторические Runs и release evidence не переписываются.
