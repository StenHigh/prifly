## ADDED Requirements

### Requirement: Full показывает текущие Run отдельно от истории

Full SHALL показывать в начале каталога доступные текущие Run и прямой переход к их списку. Текущие Run определяются по сохранённым статусам `running` и `stopping`. Run в `ready` SHALL оставаться доступным в истории, без утверждения, что исполнение началось. Ожидание хоста SHALL описываться по состоянию Attempt. Обзор текущих Run SHALL учитывать доступную область поиска и выбранные фильтры, кроме фильтра самого состояния. Он MUST NOT ограничиваться текущей страницей истории. Ограниченный обзор SHALL указывать свою область и давать переход к соответствующим отфильтрованным страницам. Ошибка одного чтения SHALL оставаться видимой в своей области.

Full SHALL давать видимые переходы к текущим, недавним и завершившимся с ошибкой Run. В режиме истории SHALL сохраняться связанный вид по умолчанию и отдельные исходы исходного и производных Run. В отборе текущих Run совпавший Run SHALL быть доступен без прохода через строки предков. Счётчики всей доступной области, совпадений и текущей страницы SHALL иметь разные подписи. Переход между страницами SHALL быть доступен перед длинным списком. Поиск, фильтры, вид, порядок и страница SHALL восстанавливаться из адреса каталога. Возврат SHALL сохранять позицию и фокус по существующим правилам.

#### Scenario: На первой странице истории только завершённые Run
- **WHEN** доступная история содержит более одной страницы, а текущий Run находится за пределами первой страницы истории
- **THEN** начало каталога даёт переход к этому Run через отбор текущих Run и не выдаёт счётчики первой страницы за всю область

#### Scenario: Текущий Run продолжает завершённый Run
- **WHEN** в текущий отбор попадает только производный Run
- **THEN** оператор видит совпавший Run без предварительного прохода через завершённых предков, а сведения о происхождении доступны из этого Run и в связанном виде

#### Scenario: Каталог открывается по сохранённому адресу
- **WHEN** оператор открывает в новой вкладке адрес с поддерживаемыми фильтрами, видом, порядком и страницей
- **THEN** Full запрашивает именно этот отбор, показывает применённые значения и корректно сообщает об ограничении страницы, если история сократилась

### Requirement: Full показывает свежесть выбранного Run и факты текущей работы

Страница Run SHALL перед техническими блоками показывать состояние и исход, известные текущие стадии или ожидание, свежесть чтения Run и последнее записанное наблюдение Run. Вкладки SHALL следовать сразу за этим обзором. Успех чтения списка MUST NOT подтверждать чтение Run. Full SHALL различать время успешного чтения, записанное наблюдение, наличие активности драйвера и свежесть прогресса программы. При отсутствии факта Full SHALL обозначать неизвестное. Состояние Run и состояние отдельной Attempt SHALL оставаться различимыми.

Если программа опубликовала прогресс, Full SHALL показывать доступную фазу и счётчик с их собственной свежестью. Последний отчёт после завершения Attempt SHALL быть помечен как исторический. Прогресс MUST NOT означать итог или активность хоста. При ошибке вспомогательного чтения Full SHALL обозначать его область и сохранить подтверждённые факты Run. Доступ к схеме, дереву, решениям, артефактам, диагностике, метрикам и выходу программы SHALL сохраняться.

#### Scenario: Чтение списка успешно, чтение Run прервалось
- **WHEN** открытый Run уже прочитан, следующее чтение Run завершилось ошибкой, а каталог читается успешно
- **THEN** статус чтения на странице Run сообщает об устаревании этого Run и показывает повтор чтения, сохраняя записанные состояние и исход

#### Scenario: Задание выдано, хост ещё не принял его
- **WHEN** Run содержит Attempt с записанным ожиданием принятия задания хостом
- **THEN** основной обзор и строка каталога объясняют ожидание согласованно и не обещают отчёт от уже работающего хоста

#### Scenario: Программа сообщила новый прогресс при прежней версии Run
- **WHEN** опубликован новый отчёт программы, а версия Run не изменилась
- **THEN** доступный прогресс обновляется с собственной свежестью без сброса выбранной Attempt, вкладки и раскрытых сведений

### Requirement: Full открывает выбранные сведения и недавние события

Full SHALL сохранять точные существующие ссылки на Run, вкладку, WorkflowInvocation и узел. Явный выбор стадии или Attempt SHALL показывать её сведения и делать положение панели понятным с клавиатуры и на узком экране. Автоматическое обновление MUST NOT менять фокус или место чтения. Если Full предлагает переход от известной причины к точной записи, он SHALL открыть связанную запись. Если точная связь не установлена, подпись SHALL назвать доступную область чтения.

Журнал SHALL предоставлять переход к недавним событиям и доступ к прежней хронологии. Область загруженной части и её неполнота SHALL быть видимы. Оператор SHALL управлять следованием за новыми событиями. Когда следование выключено, новое событие MUST NOT сдвигать открытую запись или сбрасывать её раскрытие. Полная история SHALL оставаться доступной через постраничное чтение.

#### Scenario: Оператор выбирает Attempt на телефоне
- **WHEN** оператор выбирает Attempt в дереве на экране 390×844
- **THEN** её панель появляется в области просмотра, фокус переходит к заголовку, а возврат к дереву восстанавливает выбранную строку

#### Scenario: Оператор читает прежнее событие
- **WHEN** оператор открывает старую запись и выключает следование за новыми событиями
- **THEN** запись остаётся на месте и раскрыта, а переход к недавним событиям доступен отдельным действием

#### Scenario: Старая прямая ссылка указывает на узел
- **WHEN** оператор открывает существующую ссылку Full на узел или вкладку без новых параметров
- **THEN** Full восстанавливает тот же источник, Run и выбранную область, если она доступна

### Requirement: Full независимо показывает два закреплённых Run

Full SHALL позволять закрепить два Run и наблюдать за ними на одном экране. Идентичность закрепления SHALL включать источник и Run. Повторный выбор той же пары MUST NOT создавать дубликат. При попытке закрепить третий Run Full SHALL объяснить предел и сохранить текущую пару. Закрепление SHALL сохраняться в той же вкладке при переходах и перезагрузке, если доступна память браузера. Ссылка на Run SHALL оставаться самостоятельной.

Карточки SHALL показывать отдельно состояние и исход, текущую стадию или известное ожидание, последнее записанное наблюдение и свежесть чтения. Доступный прогресс SHALL относиться к правильной Attempt. Карточка SHALL иметь переход к соответствующему Run. На широком экране карточки SHALL быть доступны рядом. На узком экране они SHALL читаться последовательно без горизонтальной прокрутки. Обновление, сбой чтения или завершение одного Run MUST NOT менять карточку другого. Завершённый Run SHALL оставаться закреплённым до явного снятия. Full MUST NOT обещать общий атомарный снимок двух authority.

#### Scenario: Два Run одновременно исполняются
- **WHEN** две закреплённые карточки читают два одновременно работающих Run, а программа первого сообщает прогресс
- **THEN** обновляется прогресс правильной Attempt, вторая карточка сохраняет собственные состояние и данные, и из обеих карточек открывается соответствующий Run

#### Scenario: Первый источник недоступен, второй Run завершился
- **WHEN** чтение одного закреплённого Run прервалось, а другой Run зафиксировал исход
- **THEN** Full помечает только первый снимок устаревшим, показывает сохранённый исход второго и сохраняет оба закрепления

#### Scenario: Третий Run и совпавшие идентификаторы
- **WHEN** оператор уже закрепил два Run и выбирает третий либо повторно выбирает закреплённую пару источник и Run
- **THEN** состав наблюдения остаётся прежним, а один Run ID в разных источниках сам по себе не считается совпадением
