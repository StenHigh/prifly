## Why

Владелец продукта хочет, чтобы Run, остановившийся на любом шаге, продолжался
тем же workflow с того места, где остановился, — без отдельного workflow
продолжения и без программ в пакете. Сейчас это невозможно:

- `continuation` (0.13.58) запускает **другой** workflow, и каждый его вход
  обязателен, поэтому один хвост продолжает только с одной точки. «С любого
  шага» требует хвоста на каждую точку или checkpoint, который пишет программа.
- `project recover` уже переносит доказанный префикс и исполняет стадию снова
  в дереве исходного Run, но принимает только технически упавший Run без
  исхода, возобновляет только упавший шаг и переносит только ассистируемые
  шаги.

Запрос пришёл от сессии пакета AI Factory и подтверждён владельцем.

## What Changes

- **Объявление `resumable`** в WorkflowRevision 8: `from_outcomes` и/или
  `from_cancelled: true` — при каких исходах Run этого workflow можно
  возобновить. Маппинга входов нет: входы — исходного Run, стадии после точки
  получают данные обычными привязками из перенесённого префикса.
- **Возобновление — обобщение восстановления.** Новый Run того же workflow
  (редакция пакета может быть новее) переносит принятые стадии до точки
  возобновления и начинает с неё; дерево исходного Run передаётся целиком.
  Источник — технический отказ (как прежде), либо, если workflow объявил
  `resumable`, завершённый с объявленным исходом или отменённый Run.
- **Точка возобновления**: у технического отказа — упавший шаг (как прежде);
  у завершённого — стадия, по чьему результату Run пришёл в finish; у
  отменённого — стадия корневого вызова, на которой его остановили;
  `--from-stage X` — любая более ранняя завершённая стадия корневого вызова.
  Стадия может быть `step`, `call` или `repeat`; вложенный вызов исполняется
  заново целиком.
- **Перенос принимает принятые программные шаги**, а не только ассистируемые.
- **Команда**: `project continue --source-run RUN` с launch **того же**
  workflow возобновляет его; с launch другого workflow — прежнее продолжение
  по `continuation`. `project recover` остаётся для технического отказа.
- `run next` завершённого или отменённого Run включает в `continuations` и
  его собственный workflow, если тот объявил `resumable`.
- Документация, пример и приёмка на настоящем Run.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `workflow-and-context`: объявление `resumable` в ревизии 8.
- `domain-execution`: возобновление Run тем же workflow с точки остановки.
- `cli-protocol`: `project continue` с launch того же workflow, `--from-stage`,
  `continuations` включает возобновление.

## Impact

Изменение затрагивает product runtime. Ownership нормативных источников не
меняется.

- Код: `internal/flow` (ревизия 8), `internal/runtime` (`recovery.go`,
  `start.go`, `next_handoff.go`), `cmd/prifly` (`project_start.go`,
  `project_recovery.go`, справка, инструкция раннера), схемы, примеры,
  руководства.
- Пакет AI Factory: после релиза объявляет `resumable` в aif-classic и
  aif-profiled и убирает continuation-пакеты и программу `resume`. Пилот
  продолжает свой Run тем же launch.
