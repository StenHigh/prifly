# Обзор ревью

Это change собрано из структурного ревью всего движка, проведённого 2026-09-17
на `10fb970` силами четырёх независимых обзорных проходов (границы пакетов,
хранилище, конкурентность/lifecycle, CLI/тесты). Ревью не меняло код; каждый
пункт ниже проверен по исходникам и цепочкам вызовов, а не по прогону.

## Состояние на 2026-09-19 (проверено по исходникам, не по прогону)

Проверил все четыре дефекта на текущем `main` после пяти выпусков окна
0.13.33–0.13.37. **Три живы, один закрыт попутно.** Владелец решил: зафиксировать
и вернуться после замера повтора #141.

- **Жив.** Граница эффектов молчит, когда не смогла прочитать:
  `processWorkspaceBoundary` при ошибке `workspaceMark` возвращает
  `measured=false` (`effects.go:187-190`), а `changes()` при ошибке сравнения
  возвращает пустую строку (`effects.go:198-205`) — то есть «дерево не
  изменилось». Отчёт шага принимается без проверки эффектов. Claim всегда
  git-worktree, поэтому «не репозиторий» здесь не легальный случай. Самый
  серьёзный из четырёх: мы объявляем границу измеряемой, а она при слепоте
  отвечает так же, как при чистом дереве.
- **Жив.** `claim create-set` всегда открывает authority read-only: операции
  нет в `mutatingCommands` (`cmd/prifly/main.go:313` — только `create`,
  `release`, `heartbeat`), команда объявлена в справке и всегда отказывает
  `ErrReadOnly`.
- **Жив.** `hydrateTransitions` (`engine.go:311`) читает `state.changed` без
  верхней границы; телеметрия на историческом cut подмешивает переходы,
  совершённые после него.
- **Жив.** `recordCommandSamples` (`store.go:1122`) гасит `ErrSampleLimit` без
  отката — пакет diagnostics сверх мягкого лимита уходит в COMMIT вместе с
  командой.
- **Закрыт.** Задача 5.7 (ранний выход watcher'а в драйвере) сделана в
  0.13.35: сторож останавливается и присоединяется на каждом выходе вызова;
  архив `2026-09-18-settle-the-driver-watcher-on-every-exit`.

Четыре находки признаны дефектами корректности:

1. **Гидрация переходов не ограничена срезом.** `hydrateTransitions` читает
   события `state.changed` без верхней границы (internal/runtime/engine.go:311,
   запрос без `seq <= cut` в internal/local/store_read.go:138). Телеметрия на
   историческом cut (internal/runtime/telemetry.go:727) подмешивает переходы,
   совершённые после него, и интервалы отчёта противоречат его заявленным
   `Cut`/`EventSeq`. Монитор уже делает это правильно
   (internal/runtime/monitor.go:177).
2. **Ошибка наблюдения workspace читается как «изменений нет».** До исполнения
   любая ошибка `workspaceMark` помечает шаг `measured=false`
   (internal/runtime/effects.go:187–190), после исполнения ошибка сравнения
   возвращает пустую строку (effects.go:202–204) — результат принимается без
   проверки эффектов. Claim всегда git-worktree
   (internal/runtime/worktrees.go:190), поэтому «не репозиторий» здесь не
   легальный случай; assisted-путь ошибки прокидывает корректно
   (effects.go:142–144).
3. **Команда коммитит пакет diagnostics, превысивший soft limit.**
   `insertSamples` вставляет пакет и только потом обнаруживает превышение
   (internal/local/store_samples.go:138–143); standalone-путь откатывается
   (store_test.go:778), а `recordCommandSamples` гасит `ErrSampleLimit` без
   отката (internal/local/store.go:1122) — сэмплы уходят в COMMIT вместе с
   командой.
4. **`claim create-set` всегда открывает authority read-only.** Операция
   отсутствует в `mutatingCommands` (cmd/prifly/main.go:313), а таблица
   определяет режим открытия (main.go:588); `ClaimWorktrees` сразу возвращает
   `ErrReadOnly` (internal/runtime/worktrees.go:164). Тест всей поверхности
   тоже не знает операцию (main_test.go:3055).

Остальные находки ревью — не дефекты, а сопровождающая работа: недействующие
фикстуры бенчмарков «10 MB» (internal/local/store_bench_test.go:28,66 —
`CommandGuarded` по несуществующим Run даёт 1200 отказов вместо событий),
таймаут preflight без границы дерева процессов
(cmd/prifly/project_preflight.go:107–112), N+1 загрузка Run в `SessionTasks`
(internal/runtime/sessions.go:549–564), дублирование лестницы версий `Next`
(internal/runtime/engine.go:653–747), семантические коды проекта внутри
`usageError` (project_start.go:337 → main.go:86–91), повторный `go run` в
`check-schema.py` (scripts/check-schema.py:79), ранний выход watcher'а
(internal/runtime/driver.go:1112–1114), гипотезы стоимости (упаковка
растущих Run, `foreign_key_check` при каждом открытии). Они входят в tasks
этого change как измерения и отдельные правки, не меняющие контракты.

## Why

Ревью выявило четыре дефекта, которые ломают заявленные инварианты продукта:
историческая телеметрия врёт про свой срез, программа может пройти приёмку без
измерения эффектов, диагностика переполняет allowance хранилища, а публичная
операция `claim create-set` не может выполниться вовсе. Исправления точечные,
но каждое касается нормативного требования, поэтому они оформляются одним
OpenSpec change и не теряются.

## What Changes

- Гидрация переходов принимает верхнюю границу последовательности
  (snapshot `EventSeq`) и читает только события `seq <= границы` на всех
  страницах; сохранённые в снапшоте переходы legacy-Run не трогаются.
- Наблюдение workspace-эффекта program-шага различает «не наблюдаемо»
  (осознанный refusal с кодом) и «наблюдение сломалось» (отказ приёма);
  пустое сравнение больше не означает «проверено без изменений».
- Необязательная телеметрия команды откатывает собственный пакет при
  `ErrSampleLimit` через savepoint; команда сохраняется, сэмплы не остаются.
- `claim create-set` объявлен мутирующей командой; тест поверхности покрывает
  его успех, а не только форму.
- Сопровождающие работы: честные фикстуры бенчмарков открытия/верификации,
  граница дерева процессов preflight, проекция задач без N+1 загрузок,
  `Next`-версии в `versionContracts`, типизированные коды вместо
  `usageError`-строк, один запуск `schema-gen` на гейт.

Изменение затрагивает продукт (runtime, хранилище, CLI), а не только процесс
репозитория. **BREAKING** нет: сохранённые JSON-поля, схемы и смысл Runs не
меняются; read-версии не сдвигаются.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `observability-publication-reactions`: read view на фиксированном cut
  показывает только переходы, совершённые к этому cut.
- `runtime-resources`: ошибка измерения workspace-эффекта не равна
  «изменений нет»; превышение allowance телеметрией откатывает пакет сэмплов
  внутри команды.
- `cli-protocol`: каждая мутирующая операция открывает authority на запись;
  `claim create-set` доступен и проверен как успех.

## Impact

- `internal/runtime/engine.go` (гидрация), `internal/local/store_read.go`
