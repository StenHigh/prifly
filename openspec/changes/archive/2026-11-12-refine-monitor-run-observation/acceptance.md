# Приёмка наблюдения за Run в Full и Light

## Браузерные сценарии

Проверять собранный кандидат на временных authority. Использовать Chromium на 1440×900 и 390×844. Для переполнения и фокуса добавить 375×812 и 320×740. Сравнивать состояние, известную причину, действие и фактическую цель ссылки. Сбой чтения имитировать только в контексте браузера.

| ID | Действие и данные | Результат |
|---|---|---|
| F01 | Открыть ожидающий вопрос из обзора и из закреплённого Run. Повторить после записи ответа | Переход раскрывает и фокусирует ту же запись. Формулировка и варианты доступны, когда записаны. После ответа показано фактическое состояние |
| F02 | Открыть legacy Run с неполными данными и случай с неоднозначной связью | Подпись называет раздел. Full показывает, что точная запись недоступна. Другой вопрос, Run или событие не подставляется |
| F03 | Открыть Attempt с истёкшим сроком, затем другую Attempt после retry или в соседней ветви | Видимая причина и код относятся к выбранной Attempt. Неизвестная причина отмечена. Исторический отказ не становится текущей причиной Run |
| F04 | Войти по прямой ссылке на вложенную Attempt, без предварительного выбора дерева. Нажать «Дерево исполнения» на телефоне | Выбранный узел раскрыт, находится в области просмотра и получает фокус. При недоступном узле виден заголовок дерева. Путь из дерева сохраняет исходный фокус |
| F05 | Закрепить ожидающий Run и Run с ошибкой. Открыть действия и вернуться. Проверить ссылку на событие, когда его номер известен | Открывается конкретная запись или названный раздел. Вложенная Attempt открывается в своей WorkflowInvocation. Пара, порядок и общий переход к каждому Run сохранены |
| F06 | Одновременно исполнять два Run. Обновить прогресс A, затем прервать чтение A и завершить B | Прогресс относится к нужной Attempt. Сбой и восстановление A не меняют карточку B. Завершение сохраняет закрепление и исторический прогресс |
| L01 | Закрепить один Run, второй, повторную пару и третий. Перейти с доски и с истории задачи. Вернуться и перезагрузить вкладку | Видны точные выбранные Run в том же порядке. Предел равен двум. Задача без Run остаётся доступна на доске. Фильтры и доступное место чтения восстановлены |
| L02 | Сравнить два Run одной задачи и два Run разных источников. Включить совпавшие title, разные ветви и одинаковый Run ID в разных источниках | У каждой строки свои состояние, причина и ссылка. Одна задача читается один раз за цикл. Два разных чтения независимы |
| L03 | Убрать выбранный Run из ограниченной страницы. Проверить 503, опоздавший ответ, восстановление и 403 | Закрепление остаётся на месте. Снимок помечен устаревшим только при доступных прежних данных. При 403 подробности скрыты. Другой Run не подставляется |
| L04 | Открыть переход Light за proxy prefix. Сравнить точную Attempt и случай без достаточных полей | Full получает правильные источник и Run. Ссылка называет цель или раздел. По возвращении доступны прежние выбор и страница |
| L05 | Открыть длинные строки стадии и ветви, длинный ID и раскрытые подробности на телефоне | Ширина документа не превышает ширину экрана. Полный текст доступен и копируется. На коротком наборе оба Run видны при 390×844 |

## Данные и бюджеты чтения

1. Для F01–F05 взять существующие native exports Full с параллельным ожиданием и ошибкой. Добавить проверки к сценарию `board`. Сохранить проверки прежних прямых ссылок, журнала, клавиатуры и возврата.
2. Для F06 использовать действующий сценарий `observe`. Перед изменением состояния подтвердить `running`, `driver_live=true` и незавершённую Attempt с отчётом прогресса у обоих Run. Снимки завершённых Run не подтверждают одновременную работу.
3. Для L01–L05 переиспользовать native task history, standalone Run и существующие stop fixtures Light. Проверить два Run одной задачи и два источника. Изолированная длинная строка проверяет перенос текста. Сценарий `baseline` продолжает проверять большой backlog и conditional polling доски.
4. Записать запросы и размеры области просмотра. Full наблюдение читает до двух `/api/run` и двух `/api/progress` за цикл. Light наблюдение читает до двух ограниченных страниц `api/light/task` за цикл и не опрашивает скрытую доску. Оба режима используют GET/HEAD. Артефакты, обзоры ревью и полная история не читаются фоном.

## Команды

`MONITOR_BIN` — собранный кандидат. `MONITOR_GO`, `MONITOR_PLAYWRIGHT` и `MONITOR_CHROMIUM` — фактические пути. `MONITOR_ARTIFACTS` — новый временный каталог вне Git checkout.

```sh
make ui-check
for mode in board observe; do
  python3 -B test/e2e/verify-monitor-board.py --scenario "$mode" \
    --binary "$MONITOR_BIN" --target "$MONITOR_ARTIFACTS/full-$mode" \
    --go "$MONITOR_GO" --playwright-module "$MONITOR_PLAYWRIGHT" \
    --chromium "$MONITOR_CHROMIUM"
done

PRIFLY_LIGHT_PERF_FIXTURE_DIR="$MONITOR_ARTIFACTS/light/authorities" \
PRIFLY_LIGHT_FIXTURE_DIR="$MONITOR_ARTIFACTS/light/authorities" \
  "$MONITOR_GO" test ./cmd/prifly ./internal/runtime -count=1 \
  -run '^(TestLightExportPerformanceFixtures|TestLightExportLongHistoryFixture|TestLightNativeTypedReviewRun|TestCLIProjectQueuePartialCancelContinueKeepsTaskAndRunHistory)$'

PRIFLY_MONITOR_FIXTURE_DIR="$MONITOR_ARTIFACTS/light-stop/authorities" \
  "$MONITOR_GO" test ./cmd/prifly ./internal/runtime -count=1 \
  -run '^TestMonitorBoardExportFixtures$'

python3 -B test/e2e/verify-light.py --scenario baseline \
  --binary "$MONITOR_BIN" --target "$MONITOR_ARTIFACTS/light" \
  --playwright-module "$MONITOR_PLAYWRIGHT" --chromium "$MONITOR_CHROMIUM"
python3 -B test/e2e/verify-light.py --scenario stops \
  --binary "$MONITOR_BIN" --target "$MONITOR_ARTIFACTS/light-stop" \
  --playwright-module "$MONITOR_PLAYWRIGHT" --chromium "$MONITOR_CHROMIUM"
```

## Неизменность контрактов

Сравнить итоговый снимок с фактическим базовым SHA реализации. Защищены `internal/`, Go-исходники `cmd/prifly/`, `schemas/`, `test/fixtures/`, существующие workflow и mapping, архив OpenSpec, выпущенные манифесты и release evidence. Проверить отслеживаемые и новые файлы, в том числе индекс. Действующие Light source set и main specs синхронизируются только по процедуре OpenSpec.

Выполнить `make test-changed` или `make check-fast` во время работы. Перед коммитом запустить `make ci-check-once CHECK_CONTEXT=<actual-profile> CHECK_FOR_COMMIT=1` и `git diff --check`. Полные ворота включают сравнение схем и существующие тесты сохранённых ответов replay. Расширенные браузерные проверки сохраняют прежние сценарии.

В evidence записать SHA кандидата, результат каждого сценария, фактические запросы и результат очистки временных процессов. Race и полный e2e остаются выпускными проверками. Выпускная и эксплуатационная приёмка Light ведётся отдельно.
