## ADDED Requirements

### Requirement: Workflow объявляет checkpoint и стадии, которые его сообщают
WorkflowRevision 7 SHALL позволять workflow объявить схему checkpoint —
авторского описания точки, с которой работу можно продолжить, — и для
step-стадий назвать выходной порт, который сообщает checkpoint. Компилятор
MUST отказывать, если порт не объявлен шагом, его схема не совпадает со
схемой checkpoint workflow, стадия не является step-стадией либо стадия
называет checkpoint в workflow без объявленной схемы. Вызываемый workflow,
объявивший checkpoint, MUST иметь ту же схему, что и вызывающий, иначе
компиляция отказывает. Обязательность checkpoint для вердиктов задаёт
`required_for` порта; Core не добавляет её сам. Содержимое checkpoint Core
MUST NOT интерпретировать.

#### Scenario: Шаг сообщает checkpoint и при отказе
- **WHEN** workflow объявляет схему checkpoint, а стадия `build` называет им
  выход `state`, обязательный для `pass`, `fail` и `blocked`
- **THEN** компилятор запечатывает объявление, и шаг, вернувший любой из этих
  вердиктов без `state`, отказывается при приёме результата

#### Scenario: Схема порта не совпадает
- **WHEN** стадия называет checkpoint порт с другой схемой
- **THEN** компиляция отказывает с указателем на стадию и порт

#### Scenario: Вызываемый workflow с другой схемой
- **WHEN** вызываемый workflow объявляет checkpoint другой схемы
- **THEN** компиляция вызывающего workflow отказывает с названием вызова

### Requirement: Workflow объявляет, от чего он продолжает работу
WorkflowRevision 7 SHALL позволять workflow объявить продолжение: непустой
список идентификаторов исходных workflow, список исходов исходного Run, при
которых продолжение допустимо, и/или `from_cancelled: true` для отменённых
Runs (у них нет исхода, поэтому это отдельное объявление, а не исход), — хотя
бы одно из двух, — и для входов, заполняемых из
исходного Run, ровно один источник каждому: вход исходного Run по имени
порта, принятый выход стадии корневого вызова по имени стадии, порта и
принятому вердикту шага или исходу вызова, либо последний принятый
checkpoint. Исход `failed` без outcome MUST NOT входить в список: это случай
восстановления. Входы без источника заполняет launch обычным образом.
Компилятор MUST отказывать на несуществующий вход, повтор входа, пустой
список, неизвестный вердикт или исход и на объявление в явной ревизии ниже
7. Ревизии 1–6 MUST компилироваться как прежде.

#### Scenario: Workflow продолжения объявляет свои источники
- **WHEN** workflow ревизии 7 объявляет продолжение от workflow `X` при
  исходах `partial` и `rejected`, берёт `task` из входа исходного Run,
  `handoff` из выхода `handoff` стадии `prepare`, принятой с вердиктом `pass`,
  и `resume_from` из последнего checkpoint
- **THEN** компилятор запечатывает объявление в WorkflowRevision, и оно
  входит в digest workflow

#### Scenario: Продолжение отменённых Runs
- **WHEN** объявление продолжения содержит только `from_cancelled: true`
- **THEN** компилятор принимает его; объявление без исходов и без
  `from_cancelled` отказывается

#### Scenario: Источник назначен несуществующему входу
- **WHEN** объявление продолжения называет вход, которого у workflow нет
- **THEN** компиляция отказывает с указателем на это место объявления

#### Scenario: Объявление в старой ревизии
- **WHEN** источник ревизии 6 содержит объявление продолжения или checkpoint
- **THEN** лестница авторинга поднимает ревизию до 7, а явно указанная
  ревизия 6 отказывает с названием поля
