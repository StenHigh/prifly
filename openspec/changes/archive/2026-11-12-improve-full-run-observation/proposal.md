## Why

Оператор Full следит за ходом работы, изучает конкретный Run и сверяет несколько Run. На v0.13.92 текущая работа теряется в истории, а шапка подробностей сообщает о чтении списка даже при сбое чтения выбранного Run.

## What Changes

- Показать текущие Run над историей. Дать прямые переходы к текущим, недавним и завершившимся с ошибкой Run. Сохранить связанный, плоский вид и доску.
- Вывести в начало страницы выбранного Run состояние, текущие стадии, свежесть чтения, последнее записанное наблюдение и доступный прогресс. Расположить вкладки перед техническими блоками.
- Открывать выбранную стадию, Attempt или запись диагностики по точному переходу, если их связь записана. В журнале дать переход к недавним событиям и возврат к истории.
- Разрешить закрепить до двух Run в одной вкладке Full. Показывать их состояния, наблюдения и сбои чтения независимо.
- Проверить оба Run в одном браузере во время фактического одновременного исполнения в двух изолированных authority. Зафиксировать смену прогресса, независимые исходы и сбой чтения одного из них.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `local-run-monitor` — наблюдение за текущими Run, выбранной Attempt и двумя закреплёнными Run.

## Impact

Изменится интерфейс Full. Runtime authority, исполняемые сценарии, хранилище, публичные JSON-контракты, HTTP endpoints и replay сохранятся. Light и общие требования `control-security-ux` сохранятся. Владение нормами остаётся в существующих источниках.

Реализация ограничена активами Full, целевыми тестами и справочником оператора. Изменение не добавляет команды управления Run и не затрагивает локальное обслуживание хранилища. Новые библиотеки не нужны.

Основание — расширенный браузерный аудит v0.13.92 на 1440×900 и 390×844. В проверенном каталоге было 1098 Run и одна активная Attempt. На первой странице доски было 50 завершённых Run. В сложных подробностях мобильные вкладки начинались на 1654 px. Одновременный ход двух Run остаётся новой проверкой.
