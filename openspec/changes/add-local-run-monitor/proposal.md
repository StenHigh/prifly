## Why

Текущий monitor показывает одно хранилище, отказывает при числе Run больше 200 и отдаёт большую часть сведений в техническом JSON. Владельцу нужен общий локальный обзор всех сохранившихся запусков своего пользователя ОС и понятная картина конкретного Run.

## What Changes

- Единый loopback monitor с автоматическим запуском при создании Run и регистрацией используемых authority roots; существующие хранилища обнаруживаются фоновым поиском с видимым состоянием полноты.
- Постраничная история без общего предела 200 Run, поиск и фильтры, независимые ошибки источников и прямые ссылки на Run.
- Русский интерфейс: обзор, схема закреплённого сценария с соединениями и будущими стадиями, дерево включений/стадий/шагов/попыток, задания и контекст, принятые результаты, артефакты, проверки, решения, диагностика и доступные измерения.
- Список файлов только из подтверждённых сохранённых данных, без diff; светлая/тёмная темы и обновления без потери места чтения.
- Переписка агентов, вызовы инструментов, stdout/stderr, подключение к журналам Codex/Claude и их дополнительный сбор явно отложены. Показывается то, что Pri-Fly уже передал исполнителю и принял обратно.

## Capabilities

### New Capabilities
- `local-run-monitor`: локальный обзор хранилищ и Run, полнота обнаружения, навигация и отображение сохранённых фактов.

### Modified Capabilities
- `cli-protocol`: общий monitor и его автоматический запуск после создания Run без влияния отказа наблюдения на исполнение.

## Impact

Изменение затрагивает продукт: CLI/web, read projections и регистрацию локальных хранилищ. Состояния сохранённых Run, pinned contracts и опубликованные schema bundles не меняются. Существующие нормативные источники остаются в своих capability; новая capability получает отдельную строку в SOURCE-OF-TRUTH. Не меняются права исполнения и lifecycle authority. Новые внешние зависимости и сетевые сервисы не нужны. Полная квалификация P2 и новый release не входят в изменение.
