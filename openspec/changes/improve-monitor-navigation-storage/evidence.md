## Наблюдение в браузере — 2026-09-08, вечер

Монитор `prifly monitor --addr 127.0.0.1:7788 --scan-root <scratchpad>` открыт
во встроенной панели браузера; 385 Run из 44 хранилищ, фикстура — 68 прогонов
демо-проекта во временном каталоге.

- **Длинный список.** `1 / 8`, ровно 50 строк на странице; «Далее →» доводит до
  страницы 3 без перезагрузки.
- **Возврат.** С page 3 при `scrollY = 4200` открыт экран Run
  (`#source=…&run=…`, отдельный экран с «← Все прогоны»), затем `history.back()`:
  вернулись `3 / 8`, 50 строк, `scrollY = 4200`. То же с фильтрами
  `status=completed` + поиск `transform` (`Найдено: 33`, `1 / 1`) — после
  возврата оба фильтра, счётчик, страница и позиция на месте.
- **Размеры.** По каждому хранилищу «Занято / артефакты / доступно на диске»,
  общий итог 279,9 МиБ, время измерения и оговорка про inode и APFS clones.
  Область поиска и исключения названы; хранилища вне scan-root показаны из
  запомненных источников, как и описано.
- **Предпросмотр.** Диалог называет путь, `Будет удалено Run: 32`, число файлов
  и каталогов, объём содержимого, полный список id и текст о том, что
  сохраняется. Защищённых Run в этой фикстуре — 0.
- **Отмена.** Закрывает диалог с `returnValue = "cancel"`; `total` остался 385 —
  не удалено ничего.
- **Подтверждение** (по тому же пути, который вызывает кнопка): устаревший
  digest → `409 cleanup_plan_changed`; действительный → `200`, удалено 32 Run,
  384 файла, 396 770 байт, без warnings. Список: 385 → 353, источник
  демо-проекта остался в списке хранилищ.

Что осталось не наблюдённым и почему: панель браузера в этой сессии — скрытый
документ (`document.visibilityState === "hidden"`), а скрытый документ не
доставляет задачу события `close` у `<dialog>`. Проверено прямо: `dlg.close(
"cancel")` выставляет `returnValue`, закрывает диалог и **не** вызывает
слушателя `close`, добавленного строкой выше. Продолжение обработчика
(`await confirmation` → удаление или «Очистка отменена.») поэтому не
наблюдалось нажатием кнопки, и повторное открытие диалога в скрытой панели
не проходит из-за незакрытого `maintenanceBusy`. **Это ограничение среды, а не
дефект продукта**: серверная часть подтверждения проверена по тому же
запросу, что шлёт кнопка. Остаётся один щелчок в видимом окне.

## Непроверенные границы

- Новые HTTP/runtime tests удаляют только данные во временных test fixtures. Реальные пользовательские хранилища не очищались.
- Полный release gate / `make check`, нагрузка на очень больших хранилищах, смешанная работа со старыми бинарниками и уникальное физическое потребление APFS clones/snapshots не квалифицированы.
- Блокировка действует между обновлёнными клиентами. Перед использованием очистки следует обновить все клиенты и закрыть старые процессы. Открытый Engine/driver удерживает хранилище; очистка отказывает и допускает повтор после его закрытия.
- Сканирование диска фоновое; показанный итог может быть неполным при ошибках и не является точным обещанием освобождённых физических блоков. SQLite VACUUM требует дополнительного места. Audit/receipts, настройки, пакеты, независимые imports и используемые данные сохраняются.
