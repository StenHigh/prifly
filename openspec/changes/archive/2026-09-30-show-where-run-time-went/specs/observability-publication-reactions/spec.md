## ADDED Requirements

### Requirement: Время assisted-сессии разложено по фазам
Отчёт о времени SHALL показывать у Attempt assisted-шага отдельно ожидание взятия задания host, работу host без ожидания ответов и ожидание ответа на runtime-решение, каждое с качеством и причинами, по записанным моментам Run. Момент, которого нет в Run, MUST давать unavailable с причиной, а не ноль или растянутый интервал. Интервалы, чьи концы принадлежат разным сессиям часов, MUST публиковаться как оценка по часам authority с указанием этого. Прежние метрики и их опубликованные значения MUST оставаться неизменными.

#### Scenario: Агент работал семнадцать минут и ждал ответа пять
- **WHEN** Attempt выдан, взят host через минуту, запросил решение, получил ответ через пять минут и отчитался через семнадцать минут после взятия
- **THEN** отчёт показывает ожидание взятия около минуты, работу около двенадцати минут и ожидание ответа около пяти, с качеством «оценка»

#### Scenario: Run запечатан до записи момента запроса
- **WHEN** в журнале решений Attempt нет момента запроса
- **THEN** ожидание ответа — unavailable с причиной, а работа host не уменьшается на выдуманную величину

### Requirement: Свод времени Run называет категории и остаток
Отчёт о времени Run SHALL давать суммы по категориям — работа агентов, работа программ, проверки, ожидание взятия задания, ожидание ответа, приёмка и переходы движка — и остаток времени, когда Run не работал. Сумма категорий MUST NOT выдаваться за elapsed: при параллельных ветвях отчёт MUST говорить, что интервалы пересекаются.

#### Scenario: Run стоял ночь между остановкой и продолжением
- **WHEN** Run остановился, а продолжен утром
- **THEN** ночь попадает в остаток «Run не работал», а не в работу какого-либо шага
