Давай подготовим OpenSpec change и план по расширенному аудиту Full. Опиши наблюдение за одним и несколькими прогонами и проверку на двух одновременно работающих прогонах. Сохрани runtime, JSON-контракты и replay. Пока без правок кода.

## Requirements Reconciliation

Источники — [дельта Full](../../openspec/changes/improve-full-run-observation/specs/local-run-monitor/spec.md) и [решения D1–D4](../../openspec/changes/improve-full-run-observation/design.md). Они уточняют [local-run-monitor](../../openspec/specs/local-run-monitor/spec.md). Общие UX и границы безопасности остаются в [control-security-ux](../../openspec/specs/control-security-ux/spec.md).

Связанный порядок остаётся исходным для истории. Текущая выборка лежит над историей. Состояние Attempt объясняет ожидание хоста, а записанный статус Run остаётся отдельно. Существующие ссылки на Run и область разбора работают. Снимки разных authority не объединяются в один момент времени.

| Сочетание | Данные и поведение | Приёмка |
|---|---|---|
| История, текущие Run, отбор по проекту | История сохраняет связанность. Текущий отбор читает доступные страницы для своих состояний. Фильтры и страница восстанавливаются по адресу | O01–O03 |
| Выбранный Run, свежий или устаревший ответ | Снимок связан с источником и Run. Прогресс сверяется с Attempt. Прочитанный каталог не подтверждает свежесть Run | O04–O05 |
| Run, вкладка, узел или событие | Клиент восстанавливает поддерживаемый маршрут. Явный переход показывает область и сохраняет обратный фокус. Polling остаётся чтением | O06–O09 |
| Два закрепления и разные исходы | До двух пар в памяти вкладки. У каждой свой снимок, таймер и ссылка. Ошибка одной карточки не меняет другую | O10–O12 |

Штатные экспортированные данные Full проверяют историю, происхождение и глубокие ссылки. Два настоящих программных Run в отдельных временных authority подтверждают одновременную работу и независимые изменения.

## Tasks

Команды браузерного replay, границы чтений и условия приёмки приведены в [acceptance.md](../../openspec/changes/improve-full-run-observation/acceptance.md).

### Этап 1. Эталон и каталог

- **1.1** Зафиксировать эталон по затронутым сценариям и базу для сравнения защищённых файлов. Выполнить `make ui-check` и прежний `verify-monitor-board.py`.
- **1.2** Добавить обзор и видимые переходы, сохранив связанный вид истории. Проверить `make ui-check` и O01/O03.
- **1.3** Подключить адрес каталога и верхнюю пагинацию. Проверить `make ui-check` и O02.

### Этап 2. Один Run

- **2.1** Перестроить обзор и развести признаки чтения, наблюдения, драйвера и прогресса. Проверить `make ui-check` и O04/O05/O09.
- **2.2** Сделать видимым выбор Attempt и сохранить прямые ссылки. Проверить `make ui-check` и O06/O09.
- **2.3** Добавить недавние события, следование и точные переходы к причине. Проверить `make ui-check` и O07/O08.

### Этап 3. Два Run

- **3.1** Добавить два закрепления и экран наблюдения. Проверить `make ui-check` и O12.
- **3.2** Добавить независимые чтения состояния и прогресса. Проверить `make ui-check`, O10/O11 и журнал запросов.
- **3.3** Добавить браузерный replay `observe`. Запустить обе команды `verify-monitor-board.py` из приёмки и проверить O01–O12.

### Этап 4. Справочник и приёмка

- **4.1** Обновить существующий справочник оператора. Выполнить `git diff --check` и сверить описанные действия с O01–O12.
- **4.2** Проверить защищённые пути и replay. Выполнить `openspec validate improve-full-run-observation --strict`, `make ci-check-once CHECK_CONTEXT=<actual-profile> CHECK_FOR_COMMIT=1` и проверки из приёмки.
