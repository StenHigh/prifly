# Выпуск Pri-Fly 0.13.33

Тег на `1de9f3d`. Два OpenSpec-изменения одним выпуском
(`let-a-clone-join-an-existing-project`, `take-a-secret-without-copying-it`):
владелец решил, что отдельный выпуск ради первого не окупает времени, раз
инструмент между ними никто не берёт.

## Что было

- Пароль объявленной программы можно было задать одним способом:
  `project local set --env DB_PASSWORD=…`. Значение ложилось в `local.yaml` и
  запечатывалось в конфигурацию исполнителя Run, то есть жило в состоянии, в
  его digest'ах и в каждом документе, сделанном из них. Владелец, которому
  нужен просмотренный перед стартом запуск, выбирал между просмотром и тем,
  чтобы секрет не попал в состояние.
- `project questionnaire --prepare` печатал **значения** окружения программ —
  в терминал и в журнал хоста, — хотя README обещал только имена.
- Клон общего проекта не подключался: `project init --host claude-code`
  отказывал `project_runner_missing` из-за отсутствия раннера **чужого** хоста,
  и `project runners add --host codex-cli` отказывал тем же по той же причине.
  Выхода из тупика в ответе не было.
- Путь рабочей копии в ответе запуска читался как относительный к репозиторию,
  а был относителен authority; хост искал дерево `git worktree list`.
- `session task --all` перечислял выданные задания, но `task.json` в рабочей
  папке появлялся только у запроса одной попытки — справка обещала больше.
- `run drive` исполняет программу шага внутри вызова, и остановиться перед
  этим было нечем: хост, ведущий Run в своём процессе, получал многоминутный
  прогон внутри собственного цикла.

## Что стало

- `project local set --env-from NAME=SOURCE` объявляет **место**: переменную
  окружения вызывающего (`env:VAR`), файл целиком (`file:/path`) или один ключ
  файла `NAME=value` (`dotenv:/path:KEY`). Запечатывается только объявление.
  Движок читает значение в момент отправки шага, непосредственно перед
  запуском, и отдаёт его этому процессу. Отсутствующий или пустой источник —
  отказ `execution_environment_unavailable` **до** запуска, с именем
  переменной и местом, вместо падения программы на аутентификации через
  несколько минут. Грамматика файла с ключом объявлена и дословна: первая
  строка `KEY=`, значение до конца строки, строки с `#` пропускаются,
  значение в кавычках — именованный отказ, а не молча снятые кавычки.
  Литеральный `--env` остаётся для того, что секретом не является.
- Объявление лежит внутри запечатанной конфигурации исполнителя, а это
  состояние Run, поэтому у него своё семейство контрактов: `core-state/32` и
  `core-read/32`, bundle `environment-source`. Версия ставится только Run'у,
  который действительно несёт объявление; всё опубликованное раньше — байт в
  байт прежнее, а ответ о следующем действии, предпросмотр и чтение шага
  остаются на 31: конфигурации исполнителя они никогда не несли. Полезная
  нагрузка запуска получила `execution-bindings/2` по той же причине: версия 1
  закрыта, и нагрузка, объявляющая 1 и несущая новое поле, отказывается, а не
  повышается. Плоский Run отказывает объявлению целиком
  (`unsupported_environment_source`).
- `--prepare` печатает `environment_names` (имена) и `environment_sources`
  (места), значений не печатает; квитанция `project local set` —
  `prifly-project-local/3`, тоже место, а не значение.
- Клон подключается: присутствие раннера требуется только у хоста, названного
  `--host`; остальные отсутствующие перечислены в `missing_hosts`;
  `project runners add --host NAME` отказывает лишь из-за конфликта самого
  названного раннера. Отказ, который всё же случается, называет выход в
  `safe_next_actions`.
- `project start` отдаёт абсолютный `workspace_path`; `repository_workspace`
  приходит любому шагу, который держит рабочую копию, а не только пишущему —
  право писать определяет `permitted_effects`, не наличие пути.
- `session task --all` вручает каждую перечисленную попытку: `task.json`
  лежит в рабочей папке каждой. Монитор по-прежнему ничего не пишет.
- `project runners update --check` печатает тот же результат и не трогает ни
  одного файла.
- `run drive --stop-before-program` проходит управляющие стадии и вручения и
  возвращает управление перед запуском программы; без флага поведение прежнее.
- Записи в `examples/troubleshooting.md`, README, `examples/README.md` и
  `.prifly/local.example.yaml` названы обе формы окружения с оговоркой
  «литерал — для несекретов».

## Ворота читали половину дерева

Этот выпуск уходил поверх красного `main`, и я узнал об этом только после
тега. `a2f0699` ввёл staticcheck в ворота утром 2026-09-17 и закрыл его
находки — на darwin. `internal/local/process_linux.go` собирается только для
linux, поэтому ни один локальный прогон его не читал, а CI падал на `ST1005`
в нём одиннадцать часов: одиннадцать коммитов и три выпуска подряд, при
зелёных локальных воротах. Ворота не врали — они читали половину дерева.

Исправлено в `ebda8ae`, после тега, поэтому в 0.13.33 не входит: строка
поправлена, а `go vet` и `staticcheck` теперь читают обе выпускаемые
платформы с выключенным cgo плюс host-проход с cgo, и каждый проход печатает,
какую платформу прочитал (vet 12 с на обе, staticcheck 21 с на обе).
Проверка доказана обратной правкой: возвращённая заглавная строка валит
linux-проход на darwin. `verify` на `ebda8ae` — success, первый зелёный на
`main` с 10:50.
