## ADDED Requirements

### Requirement: Роль исполнения и владелец видимы у узла
Монитор SHALL у выбранного узла показывать его записанную роль: управляющий узел workflow, вложенный workflow, локальная программа либо Attempt, выданная внешнему host. Для Attempt монитор SHALL показывать записанные adapter, executor и host identity, когда они присутствуют. Если сохранённые факты не позволяют установить роль, executor или наличие живого процесса, монитор MUST назвать это неизвестным, а не обозначать исполнителя субагентом, host или fork по эвристике. Fork SHALL отображаться только как записанная provenance целого Run, с доступной навигацией к исходному Run.

#### Scenario: Attempt ожидает отчёт host
- **WHEN** выбранная Attempt имеет записанные session и host identity, но результат ещё не поступил
- **THEN** монитор показывает выданную host Attempt, identity и ожидание отчёта, не утверждая, что host или субагент сейчас выполняет работу

#### Scenario: Вложенный workflow не является fork
- **WHEN** выбранный узел является вызовом вложенного workflow, а Run не содержит fork provenance
- **THEN** монитор называет узел вложенным workflow и не показывает fork

#### Scenario: Run создан как fork
- **WHEN** Run хранит fork provenance и исходный Run доступен этому локальному монитору
- **THEN** монитор показывает, что Run создан как fork, и даёт переход к исходному Run

### Requirement: Экран Run показывает текущую записанную активность и ожидания
Экран Run SHALL показывать отдельную сводку текущего снимка: активные Attempt и их узлы, выданные host Attempt в ожидании отчёта, готовые к выдаче стадии, а также записанные ожидания решения, сигнала, capacity либо terminal state. Каждая строка MUST опираться на факты текущего read cut и иметь навигацию к соответствующему узлу. Монитор MUST отличать «исполнитель работает» от «задача выдана и ожидается отчёт»; отсутствие записанного активного процесса обозначается явно. Сводка MUST обновляться вместе с Run без потери выбранного узла и оставаться read-only.

#### Scenario: Одновременно выданы две Attempt
- **WHEN** Run содержит две незавершённые Attempt, выданные разным host
- **THEN** сводка показывает обе Attempt, их host identity и ссылки на их узлы

#### Scenario: Run ожидает решение
- **WHEN** Run содержит записанный pending decision и не имеет активной Attempt
- **THEN** сводка показывает ожидание решения как причину отсутствия дальнейшего движения

#### Scenario: Нет записанного активного процесса
- **WHEN** у выданной Attempt отсутствует факт начала исполнения или живого процесса
- **THEN** сводка показывает «ожидается отчёт исполнителя», а не «исполнитель работает»
