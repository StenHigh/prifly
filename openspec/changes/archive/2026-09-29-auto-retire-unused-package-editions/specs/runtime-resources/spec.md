## ADDED Requirements

### Requirement: Освобождение бюджета Registry и установка редакции согласованы

Pri-Fly SHALL считать local и resolvable trusted definitions одним существующим бюджетом Registry. План автоматического вывода editions SHALL быть детерминированным для фиксированного snapshot authority, новой package identity и точного состава definitions. Применение MUST повторно проверить бюджет, package trust/dependencies, держателей и версии затронутых authority records в одной сериализованной границе с установкой; параллельный старт Run или смена trust MUST приводить к отказу устаревшего плана, а не к снятию доверия с используемой редакции. Сбой MUST NOT оставлять частично выведенные editions либо принятую новую edition без заявленного освобождения места.

#### Scenario: Параллельный Run начинает использовать кандидата
- **WHEN** после preview, но до применения новый Run закрепляет старую редакцию-кандидата
- **THEN** изменение отклоняется как устаревшее и этот Run не теряет необходимое разрешение

#### Scenario: Бюджета всё ещё недостаточно
- **WHEN** после защиты держателей, зависимостей и предыдущей редакции сумма definitions превышает лимит
- **THEN** установка возвращает `dependency_limit` с текущим бюджетом и причинами защиты, не меняя packages или Runs

#### Scenario: Повтор команды после сбоя ответа
- **WHEN** клиент повторяет тот же command ID и тот же reviewed план после успешной транзакции
- **THEN** он получает прежний receipt без дополнительного изменения статусов
