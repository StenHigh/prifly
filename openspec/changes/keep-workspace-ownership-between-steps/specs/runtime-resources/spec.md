## MODIFIED Requirements

### Requirement: Claim остаётся исключительным ресурсом своего Run
Выдача claimed рабочей копии MUST атомарно закреплять её использование за
одним Run и проверять его при дальнейших admissions и повторных deliveries.
Свободный execution slot, pending decision, restart и истечение lease MUST
NOT передавать тот же ресурс другому Run. Уже существующие legacy holders
MUST не переатрибутироваться; неоднозначность требует recovery. Новые допуски
старых шагов MUST соблюдать текущую защиту без переписывания прошлых Runs.

Истёкший lease MUST NOT отказывать владельцу в допуске работы, пока claim
остаётся привязан к тому же Run и запрашивает его тот же actor. Такой допуск
MUST продлевать lease в той же транзакции. Право продлить lease MUST
принадлежать actor, а не отдельному процессу: владелец, ведущий Run
последовательностью коротких команд, MUST мочь подтвердить, что он жив.
Пауза владельца между шагами MUST NOT требовать отмены Run.

Истечение lease MUST оставаться свидетельством присутствия, а не правом на
ресурс: другому actor и другому Run оно ресурс не передаёт.

Release MUST отвергать незавершённого либо uncertain владельца. Для допустимого
освобождения MUST сначала фиксироваться fence новой выдачи, затем выполняться
cleanup вне write-транзакции; прерывание cleanup MUST сохранять recoverable
состояние. Явное освобождение checkout MUST не менять пользовательские файлы.

#### Scenario: Другой запуск хочет папку ожидающего
- **WHEN** A освободил execution slot при вопросе, а B запрашивает тот же claim
- **THEN** B получает явный отказ владения до выдачи файлов, даже при capacity 1
  и истёкшем lease; независимая работа без этого claim остаётся допустимой

#### Scenario: Освобождение конкурирует с новой выдачей
- **WHEN** release и admission адресованы одной generation claim
- **THEN** атомарный fence оставляет одного допустимого владельца либо отказ;
  filesystem cleanup не выполняется над ресурсом, который уже выдан работе

#### Scenario: Владелец вернулся после паузы длиннее lease
- **WHEN** тот же actor допускает следующий шаг того же Run через время,
  превышающее lease, и другого claim на ту же копию нет
- **THEN** допуск проходит и продлевает lease, а Run не требуется отменять

#### Scenario: Владелец подтверждает присутствие между шагами
- **WHEN** он продлевает lease из нового процесса под тем же actor
- **THEN** lease продлён; идентификатор процесса или сессии часов основанием
  для отказа MUST NOT быть
