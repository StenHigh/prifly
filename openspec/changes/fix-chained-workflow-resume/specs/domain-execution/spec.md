## ADDED Requirements

### Requirement: Перенос принятых стадий сохраняется через цепочку возобновлений

Authority SHALL строить проверяемый префикс восстановления или возобновления из собственных принятых стадий source Run и стадий, доказуемо унаследованных им при предыдущем восстановлении или возобновлении. Повторное возобновление MUST NOT отказывать только потому, что до точки остановки нет собственных исполнений source Run. Число предыдущих возобновлений MUST NOT менять смысл переноса; недостаток доступного evidence или поддерживаемого контракта MUST оставаться явным отказом.

Для каждого переноса MUST сохраняться исходные identities WorkflowInvocation, StageActivation, StepInstance и Attempt, когда они существуют, а также происхождение ArtifactRevisions. Проверка MUST учитывать закреплённые определения, bindings, inputs, решения, профили и routes всего переносимого префикса. Доказательства вложенных `call`/`repeat` MUST проверяться в их исходном контексте. EventSequence разных Runs MUST NOT сравниваться как общий порядок исполнения. Унаследованный результат MUST NOT представляться новым исполнением или переносить прежние права.

Префикс SHALL ограничиваться выбранной точкой возобновления: она и её вложенное исполнение выполняются заново, последующие стадии не переносятся. При явном `--from-stage` Authority SHALL разрешать ранее принятую корневую стадию из доказанного унаследованного префикса на тех же основаниях, что и собственную принятую стадию. Вложенная стадия MUST NOT становиться корневой по совпадению имени. Действительно пустой префикс MUST сохранять отказ `resume_prefix_empty`.

Передача MUST брать claim непосредственного source Run с текущим поколением и сохранять дерево целиком, включая tracked и untracked незакоммиченные изменения. История предков MUST NOT давать право забрать дерево у прежнего владельца. Prepare MUST оставаться read-only; start MUST повторно проверять evidence, source version, review digest и ownership до создания нового Run. Source Run, его outcome и исторические результаты MUST оставаться неизменными.

Current source set остаётся `openspec/specs/domain-execution/spec.md` с delta этого change до sync. Старые Runs и published editions читаются с прежним смыслом; новые обязательные wire-поля, если потребуются, публикуются отдельной edition, без переписывания сохранённых состояний.

#### Scenario: Повторная остановка на том же quality frontier
- **WHEN** A принял ранние стадии, B перенёс их и завершился `partial` после вложенного verify → fix → verify на той же корневой стадии
- **THEN** prepare от B доказывает унаследованный префикс, а start создаёт C в текущем дереве B с неизменным dirty diff и снова начинает корневой verify целиком

#### Scenario: Цепочка длиннее двух возобновлений
- **WHEN** C снова допустимо остановился и оператор возобновляет его в D
- **THEN** перенос сохраняет доказанные ранние результаты и их происхождение без повторного исполнения и без ограничения на глубину два

#### Scenario: Source прошёл дальше прежнего frontier
- **WHEN** B перенёс ранние стадии A, принял собственную следующую стадию и остановился позднее
- **THEN** новый Run получает как совместимый унаследованный префикс, так и допустимые собственные результаты B, со всеми требуемыми bindings

#### Scenario: Выбрана унаследованная корневая стадия
- **WHEN** оператор указывает `--from-stage implement`, а implement доказуемо принят предком как корневая стадия и находится до текущего frontier
- **THEN** prepare переносит только стадии до implement и назначает implement и последующие стадии к исполнению заново

#### Scenario: Вложенный fix не является корневой стадией
- **WHEN** оператор указывает имя fix, принятого только внутри quality workflow
- **THEN** выбор отказывает `resume_from_stage_invalid`, объясняя корневую границу, без создания Run или изменения дерева

#### Scenario: Изменилось основание унаследованного результата
- **WHEN** эффективный контракт, input, decision, profile или route переносимой стадии изменился либо нужные pinned bytes или ArtifactRevision недоступны
- **THEN** prepare отказывает с точной причиной и стадией, не выдавая недостаток evidence за пустой префикс и не подставляя другой результат

#### Scenario: Утрачен claim или изменился source после prepare
- **WHEN** claim непосредственного source Run отсутствует или released при требуемом дереве, generation или source version изменилась, либо source содержит active/unresolved execution
- **THEN** start или prepare отказывает по соответствующему основанию до создания нового Run, без передачи claim предка и без нового эффекта

#### Scenario: Источник создан прежней edition
- **WHEN** source содержит валидное recovery provenance прежней поддерживаемой edition
- **THEN** reader проверяет его исходный смысл и использует доступные доказательства без преобразования historical state; неполное evidence даёт объяснимый отказ
