## ADDED Requirements

### Requirement: Устаревшие редакции package выводятся из доверенного разрешения без потери истории

При установке новой exact compiled edition того же package Pri-Fly SHALL переводить в существующий `PackageStatus=Removed` только минимальное число более старых trusted editions, необходимое для соблюдения бюджета Registry. Кандидат MUST не быть выбранной новой редакцией, единственной предыдущей доступной редакцией, dependency другого установленного package или редакцией, которую держит незавершённый Run. Порядок редакций MUST определяться подтверждённым временем импорта и exact identity, а не лексической сортировкой compiled version. При недостатке безопасных кандидатов установка MUST отказать без изменения прежнего доверия.

Автоматическое изменение статуса MUST сохранять sealed bytes, запись package lifecycle, pinned definitions и evidence исторических Runs. Оно не является security revocation, удалением Run или очисткой диска. Явный `package remove`/`restore` остаётся отдельным действием владельца.

#### Scenario: Несколько старых сборок занимают лимит
- **WHEN** новая сборка не помещается в Registry и две более старые редакции того же package не имеют держателей или зависимых packages
- **THEN** минимально достаточное число старых редакций получает `Removed`, а новая сборка устанавливается с сохранением одной предыдущей доступной редакции

#### Scenario: Старый Run ещё использует редакцию
- **WHEN** единственную подходящую старую редакцию удерживает незавершённый Run
- **THEN** Pri-Fly не выводит её из доверия и отказывает в установке с указанием ограничивающей причины

#### Scenario: Историческая проверка после вывода редакции
- **WHEN** terminal Run, исполнявшийся на автоматически удалённой из разрешения редакции, открывают позже
- **THEN** его pinned definitions и evidence читаются без переписывания, а статус package остаётся аудируемым
