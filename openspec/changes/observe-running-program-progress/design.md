## Context

См. proposal.md и delta specs. Сейчас локальный driver собирает stdout/stderr в памяти с жёсткими лимитами, а program StepResult приходит отдельно на fd 3. SMSPlace tests-worker перенаправляет PHPUnit output в scratch `tmp/*.out`; до settlement в Run нет сведений о фазе. Монитор — отдельный процесс, поэтому не может безопасно читать буфер driver или произвольный scratch path. Source sets: `domain-execution`, `runtime-resources`, `cli-protocol`, `local-run-monitor` из `openspec/SOURCE-OF-TRUTH.md`.

## Goals / Non-Goals

**Goals:** дать наблюдаемый переход фаз и, при явном opt-in шага, ограниченный live-вывод любой программы во время одной Attempt, не ослабляя приёмку результата, бюджеты процесса и read-only границу монитора.

**Non-Goals:** полный terminal transcript, tail произвольных файлов, PTY/stdin или контроль процесса из web, remote agents, доказательство отсутствия зависания или пересчёт тестов как StepResult.

## Decisions

### Отдельный необязательный канал прогресса

Добавить программе fd 4 с line-delimited закрытым JSON `program-progress/1`; fd 3 остаётся единственным каналом result candidate. Старые программы fd 4 не используют и работают без изменений. Driver ставит Run/Attempt identity по своему допуску, валидирует фазу/счётчики и не доверяет тексту как команде. Сообщения ограничены длиной и частотой; недействительные/лишние диагностические сообщения учитываются как неполнота, но не останавливают program Attempt. Альтернативы: парсить stdout/stderr (их лимит мог бы прервать 20-минутный тест) или tail scratch (монитор получил бы доступ к произвольным путям).

### Хранить последнюю запись отдельно от Run state

В authority держать ограниченную projection по Attempt: последний валидный progress, отметка времени, процесс-владелец и счётчик отброшенных сообщений. Обновление не увеличивает Run version/event count и не влияет на admission, deadlines или verdict. После settlement запись остаётся как «последняя наблюдавшаяся» до обычной retention; после перезапуска без подтверждённого владельца читается `stale/unavailable`. Чтение доступно по тем же проверкам доступа, что Run. Альтернатива — event на каждую строку — раздувает историю и придаёт диагностике ложный статус evidence.

### Разрешать live-вывод только закреплённым opt-in шага

Новая редакция StepDefinition и её YAML authoring позволяют явно включить раскрытие stdout/stderr для program step; отсутствие поля, старый контракт и иные executors означают «выключено». Разрешение закрепляется в package/Run до запуска. Не использовать `required_capabilities`: это запрос исполняемой возможности, а не согласие раскрыть текст в мониторе. Не вводить переключатель в web, который задним числом открыл бы вывод уже работающей программы.

Driver уже читает оба потока. Для разрешённой Attempt он передаёт ограниченные фрагменты в отдельную read-only projection с Run/Attempt identity, порядком/offset, отметкой времени и признаком потерянных bytes; для остальных web-readable копия не создаётся. Это bounded tail, не полный transcript и не event history. Клиент не влияет на чтение pipe. После потери владельца fragment остаётся последним наблюдением, а не текущим live-статусом. Применяются те же права доступа, что к Run, и только loopback monitor; HTML/ANSI/control bytes не исполняются.

Размер tail независим от бюджета stdout/stderr процесса. Нынешний лимит 64 КиБ на поток и техническая ошибка при его превышении остаются для старых definitions; opt-in сам по себе не делает output безлимитным. Для более разговорчивых программ отдельным явным versioned полем задаётся конечный process-output budget в пределах безопасного максимума driver; monitor показывает limit/overflow. Не использовать произвольное чтение scratch files или внешнюю terminal-трансляцию.

### Показывать качество наблюдения, а не угадывать состояние

Versioned CLI/read DTO различает `reported`, `not_reported`, `stale`, `unavailable`; потерянные обновления и settlement показывает отдельными признаками. Отдельная projection вывода доступна только для opt-in Attempt и различает stdout/stderr и gap. Монитор использует обе в выбранной карточке и не меняет закреплённую диаграмму. UI экранирует текст, показывает `current/total` только при валидном total и давность последнего сообщения. SMSPlace worker будет посылать редкие фазовые сообщения и короткие stdout summaries, не полный PHPUnit output.

## Risks / Trade-offs

- [Worker может молчать долго] → явно `not_reported`/давность, без заявления о зависании.
- [Враждебные или частые сообщения] → closed schema, ограничение поля, rate limit и bounded storage; никакого HTML.
- [Программа печатает секреты или ANSI escapes] → web-раскрытие только по закреплённому opt-in, проверка доступа, ограниченный tail и безопасный текстовый рендеринг.
- [Долгий/шумный вывод переполняет 64 КиБ] → отдельный конечный process-output budget; tail overflow отмечается как gap, process budget overflow остаётся явной технической ошибкой.
- [Отключился host/driver] → `stale/unavailable`, не продление lease или автоматический retry.
- [Fd 4 наследует дочерний процесс] → группа процессов и settlement применяют существующие ограничения; открытый канал не делает результат принятым.

## Migration Plan

1. Добавить новый необязательный канал прогресса, versioned opt-in/budget в определении шага и две bounded projections; старые программы и сохранённые Runs читаются без конвертации.
2. Выпустить новые read/monitor projections с тестами доступа, скрипта и браузера; старые JSON editions оставить прежними.
3. Обновить SMSPlace tests-worker на фазовые сообщения и короткий видимый вывод; проверить также нейтральную программу вне SMSPlace. Rollback — не включать opt-in и не передавать fd 4; StepResult и история Run не меняются.
