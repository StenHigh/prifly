## Context

Запрос владельца через сессию пакета (proposal.md). Механика почти вся есть в
восстановлении (`internal/runtime/recovery.go`): план читает журнал Run,
переносит принятые активации до точки отказа, сверяет эффективный контракт
каждой перенесённой стадии со стадией новой редакции, запрещает изменение
привязок и маршрута точки; новый Run стартует с точки
(`startStage = FrontierStageID`), а привязки к стадиям корневого вызова,
которых в новом Run нет, разрешаются из `Recovery.RootOutputs`. Дерево
исходного Run передаётся (0.13.58).

Ограничения восстановления, которые мешают:

| Место | Сейчас | Нужно |
|---|---|---|
| `recoveryFrontier` | только `failed` без исхода, точка — упавший `step` | + завершённый/отменённый по `resumable`; точка — стадия finish-ребра, отменённая стадия или `--from-stage`; `step`, `call`, `repeat` |
| `recoveryTrace` | все активации, кроме точки, обязаны быть завершены | переносятся завершённые активации **до** точки по журналу; после — отбрасываются |
| `recoveryTrace` | «reused quality gate must be an accepted assisted session» | принятый программный шаг переносится так же |
| проверка формы точки | только `step` | `call`/`repeat` без `workflow_ref`/`body_workflow_ref` |

## Goals / Non-Goals

**Goals:** возобновить Run тем же workflow с любой стадии корневого вызова, не
повторяя принятое до неё, в том же дереве; без маппинга входов и без программ
в пакете.

**Non-Goals:**
- Гранулярность внутри вложенного вызова: `call`/`repeat` исполняется заново
  целиком.
- Проверка дерева против артефактов: свежесть — дело шагов workflow.
- Изменение решений анкеты или профиля модели при возобновлении: отказ, как у
  восстановления.

## Decisions

### Команда — `project continue` с launch того же workflow

Оператор и пилот продолжают «тем же launch». Если workflow launch совпадает с
workflow исходного Run, `project continue` идёт путём возобновления (план
восстановления), иначе — путём `continuation`. `project recover` остаётся
для технического отказа и принимает те же расширения точки. Отдельной команды
`project resume` нет: `run resume` уже значит «снять паузу», и два «resume»
с разным смыслом путали бы.

### Объявление — ревизия 8

`resumable: {from_outcomes: [...], from_cancelled: true}`, хотя бы одно поле.
Ревизия 7 опубликована в 0.13.58, поле в неё не добавляется. Технический
отказ объявления не требует — как и сейчас у `recover`.

### Точка возобновления

- Технический отказ: `brokenStage()` — как сейчас.
- Завершён с исходом: стадия, чей принятый результат привёл в finish,
  выводится тем же правилом, что `finish.from_stage_id` (`runFinish`);
  неоднозначно — отказ с просьбой указать `--from-stage`.
- Отменён: стадия корневого вызова со статусом `cancelled`; несколько — отказ
  с просьбой указать `--from-stage`.
- `--from-stage X`: стадия корневого вызова, завершённая и исполненная раньше
  точки по журналу; иначе отказ.

Перенос — активации с порядковым номером в журнале меньше номера активации
точки. Для `call`/`repeat` точки её дочерние вызовы созданы позже и не
переносятся. Пустой перенос — отказ: это новый запуск.

### Происхождение

Нового поля состояния нет: `RecoveryProvenance` (`recovery/2`) уже хранит
источник, точку, действие `execute` и перенесённое. `fork.reason` различает
`recover_failed_stage` и `resume_stopped_run`, чтобы монитор и `run list`
показывали, что это.

### `run next`

`continuations` завершённого или отменённого Run включает его собственный
workflow, если тот объявил `resumable` и допускает этот исход — тот же
индекс по установленным пакетам.

## Risks / Trade-offs

- [Перенос стадии, чей результат устарел, пока Run стоял] → свежесть проверяют
  шаги workflow (мосты гейтов пакета); движок переносит только по совпадению
  контракта, входов и решений.
- [Неоднозначная точка у сходящихся рёбер] → отказ с `--from-stage`, не
  догадка.
- [Изменение правила «переносится только ассистируемый шаг»] → переносится
  только принятый результат с запечатанными выходами; программа не
  перезапускается.

## Migration Plan

1. Движок: ревизия 8, возобновление, `run next`, документация, пример,
   приёмка; релиз.
2. Пакет: `resumable` в aif-classic/aif-profiled, удаление continuation-пакетов
   и программы `resume`.
3. Пилот: обновить движок и пакет вместе; продолжать Run тем же launch.
