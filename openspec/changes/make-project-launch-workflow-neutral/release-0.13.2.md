# Выпуск Pri-Fly 0.13.2

Патч к 0.13.1: тот же отказ, следующий слой. Правки только текстовые.

## Предел считает попытки, а владелец считает прогоны

0.13.1 научил `capacity_conflict` называть числа и команду. Зависимая сессия
прочитала его и задала следующий вопрос: предел считает **попытки**, а
оператор — **заходы**. Совпадают они только пока ничто не запускает стадию с
`kind: parallel`: такая стадия занимает слот **на ветку**.

Владелец, поднявший предел до двух ради «двух задач», на пакете с параллельной
стадией упёрся бы снова — и на этот раз читать было бы нечего, потому что
числа он уже поднял.

Отказ теперь говорит это прямо:

```
this authority admits 1 attempt at a time and 1 is already admitted;
one attempt is not one Run, because a parallel stage takes a slot per branch;
raise the limit with capacity set --capacity N --reason TEXT,
and capacity show names what is held
```

Та же оговорка добавлена в `examples/troubleshooting.md`: считать предел надо по
худшей одновременности маршрута, а не по числу задач.

## Число склоняется словами

`1 attempt(s)` и `1 are already admitted` были единственным местом, по которому
видно, что текст собирали, а не писали — в сообщении, вся работа которого
состоит в том, чтобы быть прочитанным. Сборка сообщения вынесена в именованную
функцию и покрыта тестом на единице и на множественном числе.

## Что осталось абстрактным намеренно

`--capacity N` не заменено на конкретное `--capacity 2`, хотя занятое и предел
известны. Совет «поднять на единицу» верен ровно тогда, когда заход занимает
один слот, — а это и есть предположение, которое снимает первая правка этого
выпуска.
