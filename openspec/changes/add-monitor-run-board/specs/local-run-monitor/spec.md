## ADDED Requirements

### Requirement: Доска показывает категории сохранённого исполнения

Монитор SHALL предоставлять дополнительный вид доски наряду с таблицей и
существующими подробностями. Карточка SHALL показывать сохранённые названия
задачи и проекта, точные source/Run/workflow identities, все активные стадии
и ветви, status/outcome, причины ожидания или остановки и следующее доступное
действие. Отсутствующее название SHALL иметь явно помеченный fallback.
Набор колонок SHALL отражать работу, ожидание ответа/сигнала, ожидание ресурса,
остановленное/неопределённое исполнение, terminal результат и неизвестное.
Категории MUST NOT создавать новые runtime states, outcomes или verdicts.

Причины SHALL выводиться из сохранённых Attempts, StageActivations, decisions,
wait registrations, stops, unresolved effects и admission waiting authority.
Текст последнего лога MUST NOT определять категорию. При нескольких видах
работы карточка SHALL сохранять все их причины и использовать документированный
приоритет категории. Неизвестная причина SHALL быть показана явно.

Источник нормы — `openspec/specs/local-run-monitor/spec.md` с этим delta до
sync. Опубликованные versioned contracts и historical Run не меняются;
дополнительная проекция остаётся локальным read contract монитора.

#### Scenario: Два независимых читателя и ожидание владельца
- **WHEN** один Run имеет несколько активных parallel-ветвей и pending decision
- **THEN** доска показывает каждую активную ветвь и вопрос, относит карточку к ожиданию ответа и даёт переход к существующим решениям

#### Scenario: Admission ждёт ресурс
- **WHEN** authority зарегистрировала Run как ожидающий admission при нехватке capacity либо exclusive resource
- **THEN** карточка показывает ожидание ресурса, записанный источник ожидания и переход к подробностям, не объявляя работу запущенной

#### Scenario: Терминальные исходы и неопределённость
- **WHEN** доступны completed/partial, failed, cancelled и Run с pending/uncertain obligation
- **THEN** доска различает их сохранённые status/outcome; uncertain obligation остаётся остановленной работой и не попадает в безопасно завершённые

#### Scenario: Generic workflow и legacy Run
- **WHEN** workflow не содержит AI Factory имен, task title, Git или нового поля проекции
- **THEN** доска использует реальные стадии и identities, помечает fallback и неизвестное, не требует миграции Run

### Requirement: Карточка сохраняет происхождение и место чтения

Связи карточек SHALL использовать только записанное fork/recovery/continuation
provenance внутри одного source. Каждая карточка SHALL сохранять собственный
status/outcome; исходный partial не становится исходом его продолжения.
История SHALL оставаться доступной при нескольких последовательных продолжениях,
повторном continue, независимом fork и отсутствии legacy-связи. Одинаковые
title MUST NOT объединять Run; самый поздний потомок MUST NOT объявляться
единственным актуальным при разветвлении.

Доска SHALL использовать общие поиск, фильтры и постраничную навигацию по всей
истории без общего предела 200 Run. Карточки SHALL открывать existing graph,
checks/artifacts/decisions и журнал; возврат SHALL сохранять вид, фильтры,
страницу и позицию. Ошибка одного source MUST NOT скрывать остальные карточки.

#### Scenario: Partial и цепочка продолжений
- **WHEN** partial Run продолжен, продолжение отменено и создан новый continue
- **THEN** карточки сохраняют все самостоятельные исходы и точные связи, а последнее ожидание показано у соответствующего нового Run

#### Scenario: Большая история и возврат
- **WHEN** пользователь фильтрует более 200 Run, открывает карточку на дальней странице и возвращается
- **THEN** доска сохраняет фильтр, страницу, вид и позицию; для списка не загружаются все artifacts или полные подробности каждого Run

### Requirement: Обновление карточки использует согласованное чтение

Status, стадии, причины и версия одной карточки SHALL происходить из одного
согласованного чтения Run и admission waiting того же authority. Между
authority глобальный снимок не обещается. Независимое чтение подробностей
SHALL заменять карточку целиком и не дополнять её полями другой Run revision.
Смена страницы/фильтра SHALL отбрасывать опоздавшие ответы. При недоступности
источника последние данные SHALL быть явно помечены устаревшими.

#### Scenario: Изменение исполнения во время polling
- **WHEN** Run переходит от ожидания к исполнению во время обновления доски
- **THEN** каждая опубликованная карточка содержит согласованные version/event sequence и причины; прежний HTTP-ответ не перезаписывает новый выбранный фильтр
