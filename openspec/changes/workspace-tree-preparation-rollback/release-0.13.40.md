# Выпуск Pri-Fly 0.13.40

Тег на `e71d09a`. Один дефект, открытый в очереди поставки с 2026-09-06 как
известное ограничение выпуска 0.10.0.

## Что стало

Отказ допуска после подготовки возвращает рабочую папку в то состояние, в
котором её застал.

Подготовка кладёт объявленные input-деревья шага в репозиторий, в котором
работает человек, **до** того как применена команда, допускающая шаг. Если эта
команда отказывала, размещение оставалось: `prepareWorkspaceTrees` открывала
`os.Root` рабочей папки, ставила `defer root.Close()` и **возвращала**
замыкание отката, которое зовёт `root.Remove` на том же root. Все вызывающие
запускают откат из `defer` уже после возврата из подготовки — то есть на
закрытом root: каждый `Remove` падал с `ErrClosed`. А откат ошибку отбрасывал
(`_ = root.Remove`), поэтому снять ноль выглядело ровно как снять всё.

Это тот же класс, что и «граница, которая не смогла посмотреть, отвечает
„ничего не двигалось“» из 0.13.38: несостоявшееся действие молчит так же, как
состоявшееся.

Правка:

- root живёт столько же, сколько откат. Подготовка возвращает не команду
  «удали», а решение: «освободить, и откатить, если шаг не допущен».
  Освобождение происходит в обоих исходах, поэтому на допущенном шаге
  дескриптор не течёт.
- откат перестал отбрасывать ошибки и возвращает пути, которые не смог снять.
  Непустой остаток присоединяется к самому отказу через `errors.Join`: код
  отказа остаётся прежним — причиной, по которой шаг не допущен, потому что
  `ProblemFor` читает первое совпадение в цепочке. Диагностика для этого не
  годится: она живёт в состоянии Run, а отказанная команда его не пишет.
- откат снимает только то, что положила подготовка. Каталог, в котором лежат
  файлы владельца, не наш, чтобы его опустошать: `ENOTEMPTY` — не остаток и
  не ошибка.

## Проверка

`TestARefusedAdmissionTakesBackWhatPreparationPlaced` держит обе половины
требования и был красным до правки:

```
a refused admission left .ai-factory/PLAN.md in the owner's working folder
```

Вторая половина — файл владельца `.ai-factory/NOTES.md`, положенный в тот же
каталог до отказа, обязан уцелеть. Без неё откат «чинился» бы удалением
лишнего.

## Совместимость

Опубликованные контракты не менялись: ни новой state version, ни нового
семейства, ни нового кода отказа на обычном пути. Поведение меняется только
там, где раньше оставался мусор.

Одно наблюдаемое отличие: отказ допуска, после которого откат не смог снять
часть положенного, теперь несёт вторую ошибку в цепочке
(`workspace_tree_rollback_incomplete`) рядом с прежним кодом. Читатель,
берущий `code` из конверта, видит то же, что и раньше.
