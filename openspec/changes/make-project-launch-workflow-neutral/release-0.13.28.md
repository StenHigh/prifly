# Выпуск Pri-Fly 0.13.28

Заход #43 на 0.13.27: `tests`-программа отработала под движком до конца
(574 с, результат принят, `deadline_clock_rollback` не воспроизвёлся),
вернула честный `fail` → Run `rejected` по графу вставки. Два наблюдения
пилота, оба не блокирующие; одно — дефект.

## Снятое откатом издание старт берёт снова сам

Было: старт, отказавший после импорта (у пилота — `dependency_limit`),
откатывал своё издание в `removed`; следующий старт той же сборки — тех же
байт, которые он импортировал бы, не будь их — отвечал
`project_start_package_unavailable: declared package is not trusted`, и
оператор делал `package restore` руками.

Стало: `removed` — «закрыто для нового разрешения», а старт — новое
разрешение именно этого издания: он его re-trust'ит (`SetPackageStatus
trusted`, причина «project start declares this edition again`»). `quarantined`
и `revoked` — суждения о байтах, по-прежнему отказ, и он называет выход:
`… is quarantined, not trusted; package restore --id … --version … --reason
TEXT re-trusts it`. Тест: старт → `package remove` → старт снова проходит той же
сборкой; `quarantine` → отказ с командой. Разрез: `removed` снова отказ.

## Бюджет определений виден до отказа

`--prepare` показывает `registry_budget: {entries, limit: 512}` — как этот
запуск оставит бюджет (текущие записи плюс компоненты этого издания, если оно
ещё не trusted). Читается после review-digest'а и в него не входит, как
`admission`: другие запуски его двигают. Проект, который следует за каждым
выпуском, заполняет бюджет прилежанием — теперь это видно заранее, а не из
`dependency_limit`.

## `run drive` и программа шага — по замыслу, названо

`run drive` исполняет программу внутри вызова и возвращается после неё; хосту
с таймаутом на вызов инструмента такой Run вести в фоне или с таймаутом больше
`timeout_ms` привязки. Записано в help `run drive` и в `examples/README.md`.
