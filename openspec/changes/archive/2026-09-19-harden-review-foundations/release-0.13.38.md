# Выпуск Pri-Fly 0.13.38

Тег на `460cb82`. Четыре дефекта одного ревью, все — один класс: место, где
инструмент принимал собственное ограничение за свойство данных. Граница,
которая не смогла посмотреть, отвечала «ничего не двигалось». Чтение,
упёршееся в свой предел, отвечало «Run этого не записывал». Пакет
диагностики, не влезший в разрешение, коммитился вместе со своей командой, и
следующая команда мерилась против хранилища, которое бюджет считал
отклонённым.

## Что стало

- `workspace_mark_unreadable` — новый именованный отказ. Ошибка чтения метки
  claimed-воркспейса (`git rev-parse HEAD`, `git status --porcelain`) больше
  не означает «мерить нечего». Раньше такая ошибка выставляла
  `measured=false`: шаг шёл без измерения и его отчёт принимался — граница,
  которую мы называем измеренной, была слепа ровно там, где существует.
  Проверка стоит с обеих сторон программы: до старта и при сверке после.
  Репозиторий без коммитов остаётся отдельным случаем и проверяется явно
  (`headUnborn`), а не выводится из любой ошибки git.
- `claim create-set` внесена в `mutatingCommands`. Команда меняла состояние,
  открывая хранилище на чтение; тест теперь проверяет обе стороны
  соответствия, а не только одну.
- Чтение истории несёт верхнюю границу. `ReadEventsOfType` получил `through`,
  `hydrateTransitions` — срез вызывающего. Отчёт, снятый на cut, подмешивал
  переходы, закоммиченные после него; оба числа в таком отчёте выглядели
  правдоподобно, поэтому противоречие было невидимо.
- Диагностический пакет сидит в savepoint. Разрешение меряется только после
  записи строк, так что «отбросить пакет» означает откатить их.

## Что нашлось при правке

Собственная граница чтения проверялась только между страницами. Одна
страница в пятьсот событий перескакивала `maxRecordedTransitions` целиком,
то есть предел не ограничивал ничего — и это выяснилось лишь потому, что
тест на его поведение понадобился для другого дефекта. Теперь чтение
обрывается внутри страницы и говорит об этом: timing на таком чтении
называет `state_history_partially_read` вместо `state_history_not_recorded`.
Разница между «я не дочитал» и «Run этого не записывал» — это разница между
фактом о чтении и фактом о Run'е.

## Ворота

`make ci-check` rc=0, `make e2e` rc=0, `make race` rc=0 (`cmd/prifly` 189.9 с,
`internal/flow` 30.5 с, `internal/local` 7.7 с, `internal/release` 2.0 с,
`internal/runtime` 728.4 с, гонок нет) — всё на `460cb82`.
`openspec validate --all --strict` — 22 passed, 0 failed.

Каждая правка сначала была красной на прежней сборке, с числами:

- граница эффектов — два теста, оба красные на прежнем коде;
- срез чтения — `a read bounded by the earlier cut saw 23 transitions, the
  view at that cut saw 4`;
- предел чтения — `a read that stopped at its bound did not say so`;
- разрешение диагностики — `an over-allowance batch committed with its
  command: 10 samples kept`, 600 КиБ под разрешением в 256 КиБ.

## Чем это отличается от 0.13.37

Опубликованные контракты не менялись: ни одного нового state version, ни
одного нового семейства. `TransitionsPartial` помечено `json:"-"` — оно
описывает одно чтение, а не Run, и в состояние не попадает.
`state_history_partially_read` — строка в `reasons`, где словарь не объявлен.

**Строже прежнего поведения.** Шаг без `effects.class: workspace_write`,
работающий в воркспейсе, чью метку движок прочитать не может, теперь получает
отказ там, где раньше молча проходил. Это и есть цель правки, но для пилота
это изменение поведения, а не только исправление. Предупреждение отправлено
до выпуска.

## Проверка на чужом стенде

`~/.prifly/stands/0.13.38`, опубликованный darwin-arm64 из релиза; архив
сошёлся с манифестом (`sha256:5b1adae1…`). Рядом развёрнут 0.13.37 для
сравнения. Стенд-пакет `stand:package/boundary` написан для этого окна: шаг
`touch` — assisted с `effects.class: workspace_write` (он берёт claim), шаг
`gate` — program с `effects.class: none` под тем же claim'ом.

**Дефект 1, граница эффектов.** Один и тот же Run, один и тот же сломанный
воркспейс (`.git` переименован, `git status` → `fatal: not a git repository`),
шаг `gate` под активным claim'ом:

| Бинарь | Итог Run | Диагностика |
|---|---|---|
| 0.13.37 | `succeeded` | нет — программа выполнена и отчёт принят |
| 0.13.38 | `rejected` | `workspace_mark_unreadable: Process was not started; the admission and slot are settled` |

Контроль на целом дереве: тот же launch, `.git` на месте — `succeeded`. То
есть отказ приносит именно нечитаемая метка, а не сам стенд.

**Дефект 2, `claim create-set`.** Две repository, один набор, `--owner`:

| Бинарь | Ответ |
|---|---|
| 0.13.37 | `forbidden: The selected operation is not permitted for this authority or file.` |
| 0.13.38 | два активных claim'а, `schema_version: foundation-claims/1` |

**Слепой список стенда.** Дефекты 3 (верхняя граница чтения истории) и 4
(savepoint вокруг пакета диагностики) на стенде не проверяются: у первого
нужен второй писатель между двумя чтениями одного cut, у второго — команда,
чья диагностика перебирает разрешение, а стенд не приближается к нему. Оба
доказаны только красным-до-правки в `internal/local` и `internal/runtime`, с
числами выше. Если понадобится внешнее доказательство, стенду нужен Run,
который пишут снаружи между двумя `run view` на одном срезе.
