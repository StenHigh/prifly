## Why

Два живых pilot-прогона (2026-09-03) потратили заходы не на работу, а на
восстановление того, что инструмент знает и не говорит. Замеры исполнителей:
`--help` у любой подкоманды и `--version` отвечают `not_found` про ненайденный
объект; `help session` печатает всю справку целиком; `prifly schema` без
аргумента требует «точное имя контракта», но списка имён не выдаёт; неверный
`--project` неотличим от несуществующего Run; `session task` при живом Run без
удерживаемой передачи тоже отвечает `not_found`; `invalid_usage` не показывает
полученное значение, из-за чего путь с пробелом выглядит как дефект
инструмента; `run status` печатает `outputs=0` после проверенного захвата;
`run next` отвечает `idle`, пока задание держит host. Формы отправки
познаваемы, но не обнаружимы: имена контрактов подбирались перебором, а поле
`workspace_trees[].path` было восстановлено только из постороннего файла с
прошлого захода.

## What Changes

- Отказ различает отсутствующую authority (`authority_not_found`) и
  отсутствующий объект внутри неё; `session task` при живом Run без
  удерживаемой передачи отвечает `no_active_handoff`, а не `not_found`.
- `invalid_usage` глобальных флагов называет полученное значение.
- Отказ при запечатывании шага с недопустимым `effects.class` называет обе
  границы: квалификацию профиля и контракт assisted-шага.
- `--help` и `-h` у любой подкоманды печатают её строку использования, не
  открывая authority; `--version` работает как глобальный флаг; `help TOPIC`
  фильтрует справку по теме.
- `prifly schema` без аргумента печатает доступные имена контрактов и
  принимает declared reference form (`core:schema/step-result`) наравне с
  именем контракта.
- Generated JSON Schema несёт `description` для полей, которые исполнители
  восстанавливали догадкой: `WorkspaceTreeLocation.path`,
  `SessionSubmission.result` и `schema_version` результата шага.
- Handoff сам описывает, что требуется от host: закреплённые записи контекста
  идентифицируемы без опоры на порядок `skill_refs`, а выходные слоты
  разделены на те, что заполняет host, и те, что движок закрывает захватом.
- Read-only виды не занижают состояние: счётчик выходов в `run status` назван
  по тому, что считает, и дополнен счётчиком выходов шага; `run next`
  сообщает ожидание host через `safe_next_actions`; `prifly update` печатает
  адрес, по которому проверял release.
- Добавляется `project local set --executable PATH` для смены пути к binary
  без ручной правки `.prifly/local.yaml`.
- Authoring schemas перечисляются и отдаются той же командой, что и контракты
  обмена: сегодня их девять файлов существуют только для редактора и из
  инструмента недостижимы.
- Справка называет каталог authoring-примеров: полный пример непустого
  `extensions` уже есть, но из инструмента на него ничто не указывает.
- Отказ `validate` на пути вне authority называет команду, которой проверяют
  авторскую папку без создания Run (`project compile` во временный каталог).
- Вне scope: источник контекста в виде каталога для `references/**`
  (отдельный change), внешняя запись и доставка действий (веха P2-09).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `cli-protocol`: «Problem и exit code сохраняют safe meaning» — отказ
  называет, какой именно объект не найден, и повторяет полученное значение
  аргумента; «CLI exposes scoped commands without hidden mutation» — каждая
  команда читаема без authority, а публичные контракты перечислимы из
  инструмента. Добавляются требования о self-describing handoff и о read-only
  видах, не занижающих состояние.

## Impact

Изменение затрагивает product runtime только в диагностике, разборе флагов и
read-only видах; admission, sealing и persisted state не меняются. Опубликованные
контракты не получают новых обязательных полей и новых значений enum:
`safe_next_actions` уже свободный список строк, а `description` — аннотация,
не меняющая validation. Bundles `internal/runtime/*.schema.json` и `schemas/`
будут перегенерированы вместе с их immutability-тестами. Код: `cmd/prifly`
(разбор флагов, справка, `schema`, `project local`, рендер `run status`),
`internal/runtime` (`ProblemFor`, `SessionTask`, `Next`, handoff bundle),
`cmd/schema-gen` (описания полей) и их тесты. Normative source ownership ни
одной capability не меняется.
