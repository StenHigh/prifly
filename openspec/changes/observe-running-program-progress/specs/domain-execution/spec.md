## ADDED Requirements

### Requirement: Прогресс program Attempt не является её результатом

Исполняемая программа MAY сообщать ограниченные промежуточные наблюдения о собственной Attempt: именованную фазу, короткое пояснение и текущий/общий счётчик, если они известны. Pri-Fly MUST привязать принятое наблюдение к exact Run/Attempt и процессу-владельцу, но MUST NOT превращать его в StepResult, verdict, ArtifactRevision, продление deadline или доказательство живости всех дочерних процессов. Отсутствие наблюдений MUST быть допустимо для старых программ.

#### Scenario: Программа сообщает фазу и затем падает
- **WHEN** tests-worker сообщает `baseline`, а затем завершается с технической ошибкой
- **THEN** Run сохраняет фактический failed статус; фаза `baseline` остаётся только диагностическим наблюдением

#### Scenario: Программа ничего не сообщает
- **WHEN** программа использует прежний контракт и не отправляет прогресс
- **THEN** Attempt исполняется и принимается по прежним правилам без выдуманного нулевого процента

### Requirement: Вывод программы раскрывается в мониторе только по opt-in шага

Новая versioned StepDefinition MAY явно разрешить read-only live-вывод stdout/stderr конкретного program step и задать конечный бюджет вывода процесса в безопасных пределах driver. Отсутствие разрешения, legacy definition и непрограммный executor MUST означать отсутствие web-раскрытия; compiler MUST отвергать несовместимое применение. Отсутствие нового бюджета MUST сохранять прежний предел для legacy definitions. Разрешение и бюджет закрепляются с definition до RunStart и не изменяют уже принятый Run. Они не являются правом на stdin, PTY, выполнение команды, чтение scratch files или изменение StepResult. Вывод MUST оставаться недоверенной диагностикой: текст лога, в том числе похожий на verdict, MUST NOT определять исход Attempt.

#### Scenario: Два программных шага с разной политикой
- **WHEN** один program step явно разрешает live-вывод, а другой нет
- **THEN** монитор показывает tail только первого шага, хотя оба исполняются обычным способом

#### Scenario: Программа печатает слово pass
- **WHEN** opt-in программа печатает `pass` и завершается с ошибкой
- **THEN** Run сохраняет фактическую ошибку, а текст остаётся лишь диагностикой
