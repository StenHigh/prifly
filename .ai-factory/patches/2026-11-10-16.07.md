# Accepted start требует replay context в транзакции принятия Run

**Date:** 2026-11-10 16:07 UTC
**Files:** cmd/prifly/project_start.go, cmd/prifly/schema_migration_test.go, internal/runtime/start.go, internal/runtime/launch_schema_migration.go, internal/runtime/launch_schema_migration_test.go
**Severity:** high

## Проблема

Start принимал Run, затем Drive мог вернуть `driver_already_active` до записи готового ответа.
После clear повтор той же команды получал `project_start_stale_launch` вместо принятого Run.

## Причина

Completed response cache покрывал только успешный конец Project CLI.
CLI проверял текущий saved choice до обращения к исходному принятому receipt.
Run сохраняет migration binding, но не исходный launch review и generation выбора.

## Исправление

CLI подготавливает исходные response metadata до Start.
Start включает metadata, scope и fingerprint команды в защищённый payload.
Чистый reducer сохраняет metadata в открытом result принятого receipt вместе с Run.
Отказ транзакции не публикует эти metadata.
Ранний retry проверяет текущий read access, accepted receipt, intended Run ID, scope и fingerprint.
Он читает существующий Run и исходный review без нового admission или Drive.
Готовый response cache остаётся первым путём полностью завершённой команды.
Незавершённый queue intent направляет владельца к `project queue show`.
Run/read `/45` и прежние public bundles не меняются.

## Проверка

Regression удерживает driver lock, принимает Run, получает отказ Drive, затем выполняет clear.
До исправления повтор падал с `project_start_stale_launch`.
После исправления повтор возвращает тот же Run и исходную generation 1.
Новая команда со старым review получает отказ; количество Runs остаётся равным одному.
Runtime regression проверяет отсутствие результата до admission, atomic acceptance, scope/fingerprint conflict и отказ stale команды.
`[FIX:24]` находится в test log; production сохраняет штатный minimal logging.

## Предотвращение

Проверять retry после каждой границы durable acceptance, а не только после готового ответа.
Сохранять необходимый контекст в той же транзакции, которая принимает действие.
Не считать metadata доказательством принятия без проверки accepted receipt.
