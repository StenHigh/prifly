# Первый clear требует создания control plane без восстановления отозванных прав

**Date:** 2026-11-10 15:31 UTC
**Files:** internal/runtime/authority.go, internal/runtime/launch_schema_migration.go, internal/runtime/launch_schema_migration_test.go
**Severity:** medium

## Проблема

Первый clear отсутствующего выбора отказывал с `invalid_json` в свежей authority.
Команда должна вернуть успешный no-op receipt при expected generation 0.

## Причина

Read-only `readAccess` допускает отсутствие control plane без записи.
Новый owner guard затем декодировал пустой снимок AuthorityControlKey.
Основной fixture ранее импортировал package и скрывал отсутствие control plane.
Безусловный `ensureControl` также опасен: reconciliation восстанавливает права существующего owner.
Это обходит проверку утраты trust до commit.

## Исправление

Выделен `enrolControl`, который создаёт только первый control plane.
Существующий `ensureControl` сохраняет прежний путь reconciliation для своих callers.
Set/clear вызывает `enrolControl` после раннего receipt lookup и сохраняет transactional owner guard.
Существующее право trust не восстанавливается, включая конкурентное создание control plane.

## Проверка

Новая regression сначала упала с `invalid_json`, затем прошла после исправления.
Она проверяет read-only inspection, clear отсутствующего выбора, generation 0, replay и command conflict.
Существующая regression утраты trust остаётся обязательной.
`[FIX:24]` находится в test log; production сохраняет minimal logging и штатные receipts.

## Предотвращение

Проверять первую owner-команду на authority без предварительного import или admission.
Отделять создание control plane от compatibility reconciliation.
Проверять существующее право атомарным guard, а receipt replay выполнять до любых записей.
