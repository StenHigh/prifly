## ADDED Requirements

### Requirement: Claim завершённого Run передаётся связанному Run
Authority SHALL передавать активный claim рабочего дерева завершённого Run
новому Run, созданному продолжением или восстановлением от него, в той же
транзакции, что создаёт новый Run. Передача MUST допускаться только когда
исходный Run завершён без активных Attempts, ожидающей приёмки, решения и
неразрешённых эффектов, claim привязан именно к нему, а идентичность
каталога совпадает с записанной. Передача MUST NOT менять файлы, ветку и
index дерева, MUST увеличивать generation claim и MUST записывать, от
какого Run claim получен. Claim, освобождённый или привязанный к другому
Run, MUST NOT передаваться.

#### Scenario: Продолжение получает незакоммиченную работу
- **WHEN** исходный Run завершился `partial`, оставив незакоммиченные файлы в
  дереве claim, и создаётся Run продолжения
- **THEN** новый Run получает тот же claim, каталог и файлы, а запись claim
  называет исходный Run

#### Scenario: Claim уже освобождён
- **WHEN** claim исходного Run освобождён до продолжения
- **THEN** передача не происходит; продолжение создаёт новый claim по
  обычным правилам, а восстановление отказывает `recover_workspace_released`

### Requirement: Автоматическое освобождение не удаляет незавершённую работу
Освобождение claims завершённых Runs при создании нового claim того же
репозитория SHALL снимать claim в режиме `worktree` только если Run
завершился исходом `succeeded`, `completed_with_waivers` или `no_work`.
Claim Run с исходом `partial` или `rejected`, технически отказавшего без
исхода и отменённого MUST оставаться активным до передачи связанному Run
или явного `claim release`. Claim в режиме `checkout` MAY освобождаться
автоматически как прежде: его освобождение не удаляет файлы.

#### Scenario: Новый запуск после отменённого Run
- **WHEN** Run в режиме `worktree` отменён, а в том же репозитории создаётся
  новый claim
- **THEN** дерево отменённого Run остаётся с его файлами и веткой, а новый
  claim создаётся рядом

#### Scenario: Новый запуск после успешного Run
- **WHEN** Run в режиме `worktree` завершился `succeeded`
- **THEN** его claim освобождается автоматически, как прежде
