## ADDED Requirements

### Requirement: Предмет проверки определяет пригодность старого результата

Reuse принятого результата MUST проверять совпадение значимых оснований, а не один факт `pass`: exact inputs и bindings, effective StepDefinition, executor/tool, context, checks, decision values и требуемую freshness. Рабочее дерево не выбирается заново: восстановление получает дерево исходного Run передачей, в том состоянии, в каком его оставила упавшая стадия. Проверку дерева по существу, если она нужна, workflow объявляет своим шагом; Core не читает для этого содержимое артефактов и не сравнивает commit. Невозможность доказать хотя бы одно значимое совпадение MUST быть cache miss/refusal, не молчаливый перенос. Reuse не является новым execution и не может выдать новые права.

#### Scenario: Изменилась только схема результата упавшей стадии
- **WHEN** префикс workflow и его основания совпадают, а новая версия пакета меняет лишь схему результата технически упавшей стадии
- **THEN** прежние принятые стадии остаются пригодным evidence, а candidate упавшей стадии оценивается отдельно по новой схеме

#### Scenario: Изменилось определение перенесённой стадии
- **WHEN** новая версия пакета меняет эффективный контракт стадии, принятой в исходном Run
- **THEN** эта стадия не переносится даже при неизменном имени, и план называет несовпадение до запуска
