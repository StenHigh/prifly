## ADDED Requirements

### Requirement: Продолжение переносит только объявленное
Authority SHALL создавать Run продолжения только для workflow, объявившего
продолжение, и только от исходного Run той же authority, чей workflow входит
в объявленный список и который завершился объявленным исходом либо, если
объявлено `from_cancelled`, был отменён. Исходный Run с активной или
неразрешённой execution MUST давать отказ `continuation_source_unsettled`:
что там произошло, неизвестно, и продолжение действовало бы по догадке. Для каждого объявленного источника
authority MUST найти ровно указанный вход, принятый выход стадии корневого
вызова с объявленным вердиктом или исходом либо последний принятый
checkpoint; если стадия исполнялась в корневом вызове несколько раз,
берётся последний принятый по порядку settlement, а неразличимый порядок
MUST давать отказ. Последний принятый checkpoint MUST выбираться среди
принятых результатов всех вызовов Run по порядку settlement. Найденные bytes
MUST проходить схему соответствующего входа нового workflow. Отказ MUST
называть workflow, стадию и порт, которых не хватило, и MUST наступать до
claim и создания Run. Исходный Run, его исход и история MUST оставаться
неизменными; новый Run MUST хранить source Run ID/version и точные
перенесённые ArtifactRevision в fork provenance. Authority MUST NOT читать
содержимое перенесённых артефактов, кроме проверки схемы, и MUST NOT
вычислять входы за workflow.

#### Scenario: Исходный workflow не объявлен
- **WHEN** оператор продолжает Run workflow, которого нет в списке
  объявления
- **THEN** authority отказывает `continuation_source_ineligible` с
  идентификатором исходного workflow и списком допустимых

#### Scenario: Отменённый Run с незавершённой работой в дереве
- **WHEN** драйвер исходного Run убит, Run отменён без неразрешённых эффектов,
  а workflow продолжения объявил `from_cancelled`
- **THEN** продолжение получает объявленные принятые выходы и дерево
  отменённого Run с оставленными файлами

#### Scenario: Отмена оставила неразрешённый эффект
- **WHEN** отменённый исходный Run держит неразрешённую execution
- **THEN** authority отказывает `continuation_source_unsettled` до claim и Run

#### Scenario: Стадия не дала принятого выхода
- **WHEN** в исходном Run объявленная стадия не принята с объявленным
  вердиктом либо не дала объявленный выход
- **THEN** authority отказывает `continuation_source_incomplete`, называя
  стадию и порт

#### Scenario: Checkpoint не сообщён
- **WHEN** объявление требует checkpoint, а исходный Run не принял ни одного
- **THEN** authority отказывает `continuation_source_incomplete`, называя
  checkpoint

#### Scenario: Перенос между разными пакетами
- **WHEN** workflow пакета `A` объявляет продолжение от workflow пакета `B`,
  а исходный Run завершился объявленным исходом
- **THEN** новый Run получает объявленные входы с provenance исходных
  ревизий, а Core не содержит имён ни одного из пакетов

### Requirement: Восстановление работает в дереве исходного Run без условий на стадии
Восстановление технически отказавшего Run SHALL получать claim исходного Run
передачей и исполнять отказавшую стадию в том же дереве, как `run reopen`.
Условия на имя стадии, на содержимое артефакта и на commit рабочего дерева
MUST отсутствовать. Прочие условия переноса префикса — равенство
эффективного контракта, входов, решений и доступность bytes — MUST
сохраняться для любого workflow. Представление плана восстановления MUST
показывать последний принятый checkpoint исходного Run, если workflow его
объявил.

#### Scenario: Workflow без стадии review
- **WHEN** технически отказывает Run workflow, в котором нет стадии с именем
  `review`
- **THEN** план восстановления строится по общему правилу переноса префикса

#### Scenario: Исходный Run в режиме без рабочего дерева
- **WHEN** исходный Run не владел claim рабочего дерева
- **THEN** восстановление создаёт Run без claim и не требует commit
