Проверки каждого среза запускаются адресно по затронутым packages
(`.tools/go/bin/go test ./internal/runtime ./cmd/prifly -run '<точные имена>'
-count=1`), с записью команд и счётчиков. Дорогие ворота — один раз на
собранном кандидате, а не после каждой правки.

## 1. Владение переживает паузу владельца

- [ ] 1.1 Разрешить допуск работы при истёкшем lease, когда claim привязан к
      тому же Run и запрашивает тот же actor, и продлевать lease в той же
      транзакции (`internal/runtime/claim_run.go:85-93` и `:97-117`). Проверка:
      допуск проходит после паузы длиннее lease; чужой Run по-прежнему получает
      `claim_run_conflict`; непривязанный claim (`RunID == ""`) прежнюю защиту
      сохраняет.
- [ ] 1.2 Продлевать lease при выдаче задания и при приёме отчёта — интервал
      внутри шага (замер пилота: 10–18 минут работы исполнителя). Проверка:
      claim list показывает живой lease во время длинного шага; вторая
      транзакция authority на приёме отчёта не ломает атомарность записи.
- [ ] 1.3 Сверять право продлить lease по `claim.Actor`, а не по сессии часов
      процесса (`internal/runtime/worktrees.go:836`). Проверка: продление
      проходит из нового вызова CLI под тем же uid; чужой actor отвергается.
      Переформулировать `worktrees_test.go:285-291`: он моделирует «чужой
      процесс» через `newClock()`, то есть кодирует нынешний дефект как
      желаемое поведение.
- [ ] 1.4 Назвать путь восстановления в трёх отказах (`claim_run.go:91`,
      `claim_run.go:154`, `worktrees.go:837`). Проверка: каждый текст называет
      действие, а не только то, чего он не сделал.
- [ ] 1.5 Тест, воспроизводящий заход пилота: три шага, между ними пауза
      длиннее lease, четвёртый шаг допускается без отмены Run. Проверка: без
      правки 1.1 тест падает на `claim_owner_unproven`.

## 2. Рабочее окно и объявленные сроки

- [ ] 2.1 Перенести якорь рабочего окна ассистируемой попытки с создания на
      вручение (`internal/runtime/driver.go:579-583`), по той же схеме, что уже
      применяет timed-путь (`session_timing.go:57-60`), и **только** для
      ассистируемой ветки: у нативных попыток `verifyWorkspace`
      (`driver.go:842`) требует побайтового равенства конверта и записи.
      Проверка: окно не короче объявленного и не уменьшено на время подготовки;
      нативный путь не затронут.
- [ ] 2.2 Решить судьбу объявленного окна подхвата: либо проверять его при
      приёме отчёта (`session_timing.go:95-103`), либо перестать объявлять для
      ассистируемых шагов. Записать выбор и причину. Проверка: объявленный срок
      либо соблюдается, либо отсутствует; молчаливого приёма после истечения
      не остаётся.
- [ ] 2.3 Убрать дублирующий литерал окна подхвата (`driver.go:435` против
      константы на `driver.go:1061`). Проверка: значение объявлено один раз.
