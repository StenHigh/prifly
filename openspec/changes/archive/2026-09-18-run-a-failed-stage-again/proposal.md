## Why

Заход на опубликованной 0.13.33 (чужая сессия, отдельная машина) прошёл шесть
шагов, положил три коммита в рабочую копию — и упал на седьмом, программном,
по причине окружения: пароль БД программа не получила, потому что окружение
запечатано стартом. Работа цела, причина понятна и устранима за минуту. Дальше
инструмент не предлагает ничего: Run терминален, повторить стадию нечем.

Что проверено в коде, а не предположено:
- `run resume` продолжает **тот же** Run, но к терминальному неприменим.
- `run fork` создаёт **новый** Run из запечатанных ссылок источника и
  переиспользует объявленные неизменяемые артефакты; позицию в графе он не
  наследует — новый Run начинается с входа рабочего процесса.
- Внутри живого Run повторной попытки того же шага тоже нет: `retry_class`
  объявлен у эффектов и у ActionIntent, но ни одна команда и ни одна политика
  не создаёт вторую попытку для settled failed шага.

Цена этого сегодня — повторить plan и implement с нуля ради одной программы,
то есть выбросить работу, которая уже проверена и закоммичена, и заплатить за
неё второй раз моделью и временем.

Изменение затрагивает product runtime и модель жизненного цикла Run;
ownership источников не меняется.

## What Changes

- Стадия, упавшая технически (не предметным вердиктом), становится
  повторяемой: владелец может запустить её снова, не повторяя то, что уже
  сделано и запечатано.
- Граница остаётся честной: повтор не переписывает историю исходного Run и не
  выдаёт чужую работу за новую. Что именно повторяется — попытка внутри живого
  Run или стадия нового Run, наследующего запечатанные выходы предыдущих, —
  выбирается в design.
- Повтор не воскрешает права: одобрения, гранты и внешние эффекты исходного
  Run в него не переходят, как это уже установлено для fork.
