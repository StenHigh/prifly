# План уточнения наблюдения в Full и Light

- Дата подготовки — 2026-11-12.
- База планирования — `a8a7620c` в `main`. Фактическую базу реализации фиксирует Run.
- Change — [refine-monitor-run-observation](../../openspec/changes/archive/2026-11-12-refine-monitor-run-observation/proposal.md).
- Прогресс — [tasks.md](../../openspec/changes/archive/2026-11-12-refine-monitor-run-observation/tasks.md).

## Original Request

Подготовь OpenSpec change по этим макетам. Включи точные ссылки из наблюдения Full, компактный режим двух прогонов в Light и исправление мобильной прокрутки. Сохрани runtime, JSON-контракты и replay. Пока без правок кода.
А так же включи туда и план для карточки Run в Full: точная ссылка на вопрос, причина ошибки в деталях попытки и возврат к узлу дерева на телефоне. Сохрани runtime, JSON-контракты и replay. Пока без правок кода.

## Settings

- Тесты — целевые проверки представления и браузерные сценарии. Переиспользовать текущие native fixtures и проверку двух одновременно исполняемых Run.
- Логирование — трасса запросов, результаты браузерных сценариев и очистка временных процессов. Штатное логирование приложения сохраняется.
- Документация — существующий справочник оператора в задаче 4.2.
- Реализация — отдельный согласованный Run `prifly-run → aif-classic`. Владелец согласует план и запускает реализацию по обычному порядку проекта.

## Roadmap Linkage

Milestone — `none`. Срез уточняет интерфейсы. Действующая приёмка E6 и перенос источника требований Light остаются в [add-prifly-light-task-board](../../openspec/changes/add-prifly-light-task-board/tasks.md).

## Requirements Reconciliation

[Дельта Full](../../openspec/changes/archive/2026-11-12-refine-monitor-run-observation/specs/local-run-monitor/spec.md) уточняет действующий [local-run-monitor](../../openspec/specs/local-run-monitor/spec.md). Она сохраняет прежние точные ссылки, независимость закреплений и журнал.

[Дельта UX](../../openspec/changes/archive/2026-11-12-refine-monitor-run-observation/specs/control-security-ux/spec.md) уточняет браузерные действия Light. [Проекция и доступ Light](../../openspec/changes/add-prifly-light-task-board/read-contract.md) остаются в действующем change Light. Источники согласуются по [карте](../../openspec/SOURCE-OF-TRUTH.md).

| Сочетание | Правило | Проверка |
|---|---|---|
| Обзор или наблюдение Full и однозначный вопрос | Точный фрагмент содержит идентичность. Запись остаётся той же после ответа. Клиент сверяет цель с текущим Run | D1, F01 |
| Причина без однозначной связи | Переход открывает явно названный раздел. Нет дополнительных чтений ради подстановки точной цели | D1, F02/F05 |
| Ошибка Attempt, параллельные ветви и прямой вход на телефоне | Диагностика принадлежит выбранной Attempt. Возврат раскрывает её узел в нужной WorkflowInvocation | D2, F03/F04 |
| Два Full Run, прогресс или сбой одного | Закрепления и снимки независимы. Предыдущая причина помечена как последняя известная при сбое чтения | D1, F05/F06 |
| Один или два Light Run одной задачи или разных источников | Сохраняются точные идентичности и порядок. Одно ограниченное чтение на задачу. Общие признаки задачи не переносятся на Run | D3, L01/L02 |
| Отсутствие в странице, 503, 403 или переход в Full | Сохраняется выбор. Причина неполноты видна. Явный отказ скрывает содержимое. Ссылка сохраняет источник, Run и доступную цель | D3, L03/L04 |
| Узкая история и длинная строка Light | Значение переносится или раскрывается. Страница остаётся в ширине экрана | D4, L05 |

Все точные переходы используют браузерный адрес. Runtime, JSON и сохранённые ответы replay остаются в защищённой области. [Приёмка](../../openspec/changes/archive/2026-11-12-refine-monitor-run-observation/acceptance.md) связывает проверку с текущими native exports и двумя временными исполнениями.

## Tasks

### Этап 1. Эталон

- **1.1** Зафиксировать базу и воспроизвести четыре наблюдения аудита. Выполнить `make ui-check`, Full `board` и Light `baseline`/`stops` по приёмке.

### Этап 2. Full

- **2.1** Согласовать переходы обзора и наблюдения в `cmd/prifly/monitor.js`. Выполнить `make ui-check`, F01 и F02.
- **2.2** Показать диагностику Attempt и восстановить видимый узел дерева. Выполнить `make ui-check`, F03 и F04.
- **2.3** Добавить переходы от причин в закреплениях. Выполнить `make ui-check`, Full `observe`, F05 и F06.

### Этап 3. Light

- **3.1** Добавить выбор конкретных Run и компактный экран. Выполнить `make ui-check`, L01 и L02.
- **3.2** Подключить ограниченное чтение и точные переходы. Выполнить `make ui-check`, L02–L04.
- **3.3** Исправить перенос длинных значений в истории. Выполнить `make ui-check` и L05.

### Этап 4. Приёмка

- **4.1** Расширить существующие браузерные сценарии. Выполнить команды из приёмки и проверить F01–F06 и L01–L05.
- **4.2** Обновить существующий справочник оператора. Выполнить `git diff --check` и сверить действия с результатами сценариев.
- **4.3** Сверить защищённые пути с базовым SHA. Выполнить `openspec validate refine-monitor-run-observation --strict`, `make ci-check-once CHECK_CONTEXT=<actual-profile> CHECK_FOR_COMMIT=1` и проверку границ из приёмки.
