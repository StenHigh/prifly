## ADDED Requirements

### Requirement: Драйвер одного Run не блокирует другой Run проекта
Authority SHALL позволять одновременно исполнять работу разных Run: драйвер MUST держать исключительную блокировку только своего Run, а операции над всей authority (освобождение рабочей копии, очистка хранилища) MUST исключать любой драйвер. Второй драйвер того же Run MUST по-прежнему отказывать `driver_already_active`.

#### Scenario: Две программы разных Run
- **WHEN** у Run A исполняется шаг-программа, и владелец запускает `run drive` для Run B того же проекта
- **THEN** программа Run B стартует, не дожидаясь программы Run A

#### Scenario: Тот же Run дважды
- **WHEN** второй `run drive` запускается для Run, чей драйвер уже работает
- **THEN** он отказывает `driver_already_active`

### Requirement: Допуск попытки учитывает объявленные исключительные ресурсы
Run SHALL запечатывать при старте, какие стадии какие именованные ресурсы занимают; имена ресурсов MUST быть непрозрачны для движка. Попытка стадии SHALL допускаться, только если число активных попыток всех Run authority, занимающих каждый её ресурс, меньше лимита, запечатанного её Run; иначе допуск MUST отказывать `resource_busy`, называя ресурс, лимит и держателя, и MUST NOT создавать попытку, а попытка SHALL допускаться на следующем запуске драйвера после того, как место освободится, без решения владельца. Ресурсы стадии-вызова SHALL наследоваться всеми попытками внутри вызова. Держатели каждого ресурса MUST быть видны в `capacity show` и мониторе.

#### Scenario: Тесты двух Run не идут одновременно
- **WHEN** проект объявил ресурс `heavy` с лимитом 1 и стадии `tests` и `verify`, занимающие его, и у Run A идёт `tests`
- **THEN** допуск `verify` Run B отказывает `resource_busy`, называя ресурс `heavy` и держащий его Run A, попытка не создаётся, а после завершения `tests` Run A следующий `run drive` Run B её допускает

#### Scenario: Лимит больше одного
- **WHEN** лимит ресурса 2, и его занимают две попытки
- **THEN** третья ждёт, а первые две идут одновременно
