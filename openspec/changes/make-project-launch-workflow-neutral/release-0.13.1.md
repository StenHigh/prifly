# Выпуск Pri-Fly 0.13.1

Патч к 0.13.0. Одна правка, и она про то, что выпуск, открывший параллельную
работу, по умолчанию её же и запрещал.

## Отказ по вместимости называет число и команду

0.13.0 снял исключительность по репозиторию: два Run одной ветки в разных
worktree — разные ресурсы. Но авторитет по умолчанию допускает **одну** попытку
за раз, и второй Run получал:

```
capacity_conflict: the authority has no free admission slot
safe_next_actions: ["doctor", "run.status"]
```

Ни `doctor`, ни `run.status` не приводят к `capacity set`. Владелец, поставивший
0.13.0 ради параллельной работы, не мог отличить **«не поддерживается»** от
**«не настроено»** — а это ровно та разница, ради которой выпуск и делался.

Отказ теперь называет оба числа и команду, которая их меняет; безопасные
действия ведут в `capacity show` и `capacity set`, а не в диагностику состояния:
Run не в плохом состоянии, это авторитет настроен на одну попытку.

Найдено сессией пакетов на авторитете по умолчанию в течение часа после выпуска
0.13.0 — исполнением, а не чтением: она подняла предел и подтвердила, что два
Run одного репозитория живут одновременно с разными рабочими копиями.

## Закрытый открытый вопрос

Дайджест в `--step-ref` ни с чем не сверяется, и **дырой это сегодня не
является**: на пути компиляции ссылка берётся из запечатанного компонента
пакета (`project_compile.go:1481`), а пользовательская живёт только в
`project extend`, чей выход подать в прогон нечем. Вопрос перестаёт быть
закрытым в тот момент, когда у `project extend` появится выход, — и это стоит
учесть в том решении, а не в этом выпуске.
