## Context

См. proposal.md — Why. Факты на 2026-09-30: `internal/runtime` — 101 тестовый
файл, 656 тестов, 0 параллельных; 79 вызовов `t.Setenv`/`os.Setenv` в тестах; 7
файлов с `synctest`; глобальные переменные, которые тесты подменяют (например,
`monitorAuthorityCheckInterval`). `verify.yml` — одна задача: `make ci-check`,
затем `make e2e`. `race.yml` — ручной запуск. Кэш `.cache` в CI восстанавливается
по `go.sum`. Замер по тестам записывается в tasks.md, когда отработает.

## Goals / Non-Goals

**Goals:** push-проверка на GitHub и локальная проверка при разработке быстрее
в разы; предрелизная квалификация не слабее сегодняшней; ни одна проверка не
пропадает.

**Non-Goals:** ослабление ассертов, удаление тестов ради скорости, перенос
проверок на одну платформу.

## Decisions

1. **Параллелить по файлу, а не всё разом.** Тест помечается `t.Parallel()`, если
   не зовёт `t.Setenv`/`os.Setenv`/`os.Chdir`, не использует `synctest` и не
   пишет в глобальную переменную пакета. Помеченные прогоняются
   `-count=20 -race` локально на своём файле: гонку в тестах ловит race-детектор,
   а не удача. Проверка готовности: тест-страж перечисляет файлы, где
   `t.Parallel` и `t.Setenv` соседствуют в одном тесте, и падает.
2. **Шарды по списку тестов.** `go test -list . ./internal/runtime` → имена
   делятся детерминированно (хэш имени mod N) → каждый шард получает
   `-run '^(A|B|…)$'`. Страж CI проверяет, что объединение шардов равно
   полному списку: тест, не попавший ни в один шард, — это молча пропущенная
   проверка.
3. **Разбиение пакета — по графу, поэтапно (итог: не делаем, причины в tasks.md).** Кандидаты — области с узким
   входом: расчёт времени и телеметрия, вопросы/решения, опубликованные схемы и
   bundles. Перенос не меняет поведение и опубликованные JSON; каждое
   выделение — отдельный шаг с зелёными воротами. Что не выделяется без
   циклических импортов — записывается с причиной, а не форсируется.
4. **`make test-changed`**: `git diff --name-only origin/main` → пакеты →
   `go list -deps -test` обратно (кто импортирует изменённые) → плюс карта
   «каталог → стражи» (`examples/**` → тест индекса возможностей, `openspec/**`
   → `TestGlossaryBindings`, `schemas/**` → `schemas-check` и т. п.). Карта
   живёт в Makefile рядом с целью.
5. **`qualify` вместо ручного `race`.** Workflow по `workflow_dispatch` с SHA:
   `make race` и `make e2e` параллельными задачами. `scripts/tag-release.py`
   перед тегом запрашивает у GitHub успешные `verify` и `qualify` на этом SHA
   и отказывает иначе. Требование «tag workflow не повторяет verify/race»
   сохраняется.

## Risks / Trade-offs

- [Скрытая зависимость тестов друг от друга проявится при параллельности] →
  `-count=20 -race` по файлу до пометки; флаки не отключаются, а чинятся или
  тест остаётся последовательным с комментарием почему.
- [e2e только перед релизом — регресс e2e обнаружится позже] → это решение
  владельца; квалификация обязательна для тега, так что в релиз он не попадёт.
- [Разбиение пакета — большая правка] → поэтапно, каждый шаг отдельно
  зелёный; выгода измеряется после каждого шага.
