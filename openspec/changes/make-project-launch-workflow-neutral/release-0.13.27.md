# Выпуск Pri-Fly 0.13.27

Одна починка, блокирующая: первый боевой заход с `tests`-программой (#104,
0.13.26) — движок убил программу через 58,6 с со `stop_reason =
deadline_clock_rollback`, Run → failed; девять шагов до неё прошли штатно,
сама программа шла нормально.

## Что было

`remainingBudget` (`driver.go`) в одном clock-сеансе считает остаток по
монотонным часам и по wall-часам и отказывает `deadline_clock_rollback`, если
wall-остаток больше монотонного **более чем на 2 мс**. Допуск задумывался как
погрешность округления, а не поправка на дисциплину часов; на ноутбуке
wall-часы дисциплинируются NTP постоянно, несколько миллисекунд в минуту, и
сторожевой цикл драйвера (каждые 250 мс) поймал расхождение на 58-й секунде
получасового таймаута. Ассистируемые шаги проверяются в этой точке реже,
поэтому дефект всплыл только с программой.

## Что стало

Монотонный остаток правит, wall может его только укоротить — отставание
wall-часов ничего не покупает, проверка — сигнал о сбросе часов, и сигнал,
который срабатывает на штатной дисциплине, — шум. Допуск —
`deadlineClockSlewAllowance = 5 s`: сброс, который стоит отказа, двигает
часы на секунды. Отказ называет допуск. Тест: отставание на 100 мс —
остаток по монотонным; на 8 с при горизонте в минуту — `deadline_clock_rollback`.
Разрез: при 2 мс отставание в 100 мс — красный.

`utc_trust: local_wall_unqualified` — по замыслу: wall-часам движок не
доверяет и использует их только чтобы укоротить; именно поэтому отставание
не должно было рубить.

## Ворота

`make check` (race), `make e2e`, CI `verify`.
