# Как описать и выбрать запуск

Опишите назначение каждого запуска в `title` и `description` профиля проекта.
Исполнитель в ИИ-хосте — runner `prifly-run` — может предложить подходящий
запуск, но пользователь выбирает его явно. Совет необязателен.

Точка запуска, или launch, имеет постоянный ID в `.prifly/project.yaml`.
Выбор launch, ответы на вопросы сценария и подтверждение старта — отдельные действия.

```text
Список launch → совет (по желанию) → выбор ID → анкета → prepare
                                                        ↓
runtime-решения ← Run ← start ← подтверждение подготовленного итога
```

## 1. Объявите назначения запусков

Для этого достаточно профиля `prifly-project-profile/3`.
Ниже показан профиль с двумя уже подготовленными папками workflow:

```yaml
schema_version: prifly-project-profile/3
packages:
  csv-report:
    source: .prifly/workflows/csv-report
  blocked-condition:
    source: .prifly/workflows/blocked-condition
launches:
  report:
    title: Отчёт из CSV
    description: Проверить строки CSV и сохранить итоговый отчёт без ИИ и Git.
    kind: workflow
    workflow: .prifly/workflows/csv-report/workflow.yaml
  condition:
    title: Работа по условию
    description: Выполнить работу с ограниченными повторами при недоступном условии.
    kind: workflow
    workflow: .prifly/workflows/blocked-condition/workflow.yaml
```

Это пример конфигурации, а не установщик. Подготовка папок описана в
[CSV report](../workflows/csv-report/README.md) и
[Blocked condition](../workflows/blocked-condition/README.md).
Настройте локальные программы и входы по выбранному примеру.

Проверьте фактический список:

```sh
prifly project workflows --repository . --json
```

Runner читает ID, `title`, `description` и объявленные входы из этого списка.
Названия файлов и похожие ID не определяют назначение запуска.
Удалённый каталог не добавляет варианты, пока проект их не объявил.

У этих двух программных workflow нет зависимости от ИИ-хоста.
Поэтому в профиле нет `hosts`, а в командах не нужен `--host`.
Для использования `prifly-run` в ИИ-хосте явно установите нужный runner через
`project runners add --host HOST`, как показано в
[основном README](../../README.md#быстрый-старт).
Наличие хоста само по себе не делает его обязательным для программного workflow.

## 2. При необходимости задайте критерии совета

Положите `PROJECT.md` рядом с установленным `prifly-run/SKILL.md`.
Для Codex app это `.agents/skills/prifly-run/PROJECT.md`,
для Codex CLI — `.codex/skills/prifly-run/PROJECT.md`,
для Claude Code — `.claude/skills/prifly-run/PROJECT.md`.
Файл необязателен; существующие проектные правила нужно сохранить.

Например, добавьте такой текст:

```markdown
## Критерии совета при выборе запуска

Для получения итогового отчёта из CSV советуй report по его title/description.
Не советуй condition для обычного отчёта без условия готовности.
Сохраняй оба запуска доступными для явного выбора пользователя.
Если назначений недостаточно для совета, предложи ручной выбор.
```

Для полного отключения совета замените этот раздел следующим:

```markdown
## Выбор запуска

Не давай советов по выбору запуска в этом проекте.
Покажи все объявленные запуски и дождись явного выбора пользователя.
Точный объявленный ID ведёт прямо к его анкете.
```

Отключение совета не скрывает варианты и не разрешает автоматический старт.
Это инструкция runner, а не новый YAML-флаг.
`project runners update` обновляет общий skill и сохраняет соседний `PROJECT.md`.

## 3. Выберите точный ID

Можно сразу назвать runner точный объявленный ID: «Используй запуск `report`».
Повторный выбор и совет не нужны.
Неизвестный ID runner не заменяет похожим: сначала нужно проверить список.

Если ID не задан, runner показывает все объявленные запуски.
Он советует один из них только при нескольких вариантах, достаточном описании
задачи и разрешённом совете.
Обоснование использует `title`, `description` и применимые критерии `PROJECT.md`.
Совет не доказывает совместимость входов или готовность среды: это проверяет prepare.

Без описания задачи можно сразу выбрать ID или сначала описать задачу для совета.
Пользователь также может сказать «Без совета» и выбрать любой объявленный запуск.
Runner сохраняет исходный текст задачи и ссылки для объявленного входа выбранного workflow.
Он не заменяет задачу объяснением рекомендации и не придумывает обязательный brief.

При единственном запуске runner пропускает совет, но всё равно ждёт выбора.
При пустом списке он сообщает об этом и не устанавливает workflow автоматически.

Для конечного выбора runner использует применимый нативный инструмент хоста:

| Хост | Инструмент при его доступности |
|---|---|
| Codex | `request_user_input` или `request_user_input_async`, согласно текущему режиму и контракту инструмента |
| Claude Code | `AskUserQuestion`, согласно текущему контракту инструмента |
| Хост без применимого инструмента | Один явный текстовый вопрос и ожидание ответа |

Если варианты не помещаются, runner показывает страницы с переходами назад,
вперёд и возможностью отказаться. Каждый ID остаётся доступным.
Пути файлов и произвольный JSON передаются свободным вводом, а не вымышленными вариантами.

Показ асинхронного вопроса не является ответом.
Предвыбранный вариант, закрытие вопроса, таймаут и молчание также не являются выбором.
До фактического ответа runner не читает анкету выбранного launch,
не импортирует пакет, не захватывает рабочее дерево и не создаёт Run.
Он не переключает режим хоста ради получения другого инструмента вопросов.

## 4. Ответьте на объявленные вопросы и проверьте старт

После выбора `report` прочитайте его анкету:

```sh
prifly project questionnaire --repository . --launch report --json
```

Анкета показывает только вопросы, которые объявил выбранный сценарий.
Для собственного package форма объявления показана в
[справочнике решений Run](run-decision-authoring-reference.yaml):
`phase: preflight` действует до старта, `phase: runtime` — во время Run.
Постоянные ответы проекта задаются в
[`extend.yaml`](extension-authoring-reference.yaml), в `answers.preflight`
и `answers.runtime`; флаг переопределяет ответ для одного Run.
Совет при выборе launch не добавляет решение в этот каталог.

Исходный текст задачи передаётся только в объявленном формате входа.
У `report` вход файловый: ему нужен CSV, а не придуманное описание задачи.
После настройки Node и пути входа подготовьте итог:

```sh
prifly project questionnaire --repository . --launch report --prepare \
  --input csv=.prifly/workflows/csv-report/sample.csv --allow-execution --json
```

Prepare проверяет и компилирует выбранные параметры.
Он не импортирует пакет, не захватывает дерево, не создаёт Run и не исполняет программы.
В этой команде `--allow-execution` позволяет проверить программные привязки до старта.
Проверьте пакет, входы, ответы, программы, аргументы и supporting files в итоге.
Если нужны assisted-шаги или host-bound sources, проверьте также выбранный `--host`.

После отдельного подтверждения итога используйте те же параметры и его `review_digest`:

```sh
prifly project start --repository . --launch report \
  --input csv=.prifly/workflows/csv-report/sample.csv \
  --expected-launch-digest DIGEST --allow-execution
```

Замените `DIGEST` значением `review_digest` из проверенного итога.
`--allow-execution` разрешает объявленные программы этого запуска.
Выбор ID и согласие с советом этого разрешения не дают.
Если файлы, ответы или настройки изменились, повторите prepare и подтверждение.

Во время Run объявленные вопросы читаются через `run decisions RUN_ID`.
Runner ждёт требуемый ответ и следует `run next`.
При отсутствии активного хоста Run не получает автоматическое пробуждение.

## Граница проверки интерфейса

Наличие инструкции для native question tool не доказывает живую работу интерфейса.
Статус отдельных Claude UI-проверок — `DEFERRED` в
[verify-claude-launch-choice-ui](../../openspec/changes/verify-claude-launch-choice-ui/proposal.md).
Этот справочник не закрывает эти проверки и не меняет настройки провайдера.

Нормативное поведение описывает
[CLI protocol](../../openspec/specs/cli-protocol/spec.md#requirement-host-runner-условно-советует-объявленный-launch-перед-выбором).
