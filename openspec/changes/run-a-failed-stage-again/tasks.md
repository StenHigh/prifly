## 1. Стадия не убивает Run

- [x] 1.1 `internal/flow`, `internal/runtime`: стадия объявляет `technical_retries` (WorkflowRevision v5, 1..8); в его пределах создаётся новая попытка того же StepInstance, вне — прежнее поведение. Проверка: тест — программа, падающая один раз и проходящая со второй попытки, доводит Run до конца (две попытки, диагностика первой сохранена); программа, падающая всегда, даёт ровно две попытки и Run `failed`; `go test ./internal/runtime -run 'DeclaredRetry'`.
- [x] 1.2 Повторять можно только то, что разрешил автор шага: бюджет на шаге с `retry_class` вне {pure, idempotent} отказан компиляцией (`unsupported_retries`), а предметный вердикт повтором не отменяется — повтор разбирает только техническую неудачу. Проверка: тест компиляции на отказ и тест на то, что путь повтора лежит в ветке технической неудачи.

## 2. Упавший Run не выбрасывает работу

- [x] 2.1 `run reopen RUN --expected-version N --reason TEXT` возвращает сломавшуюся стадию в ready новой Attempt того же StepInstance; завершённые стадии остаются завершёнными. Проверка: тест — Run, упавший на программной стадии из-за пустого источника, после исправления источника и `reopen` доходит до конца, число завершённых стадий до и после равно; `go test ./internal/runtime -run 'Reopen'`.
- [x] 2.2 Повтор отказан Run'у, достигшему outcome. Проверка: тест — завершённый `succeeded` Run отказывает `not_a_broken_run`.
- [x] 2.3 Повтор отказан, пока есть неразрешённый эффект, активная попытка, stop или запрошенная отмена; права берутся заново при следующем admission. Проверка: тест — устаревшая ожидаемая версия отказана, повторный вызов на уже открытом Run отказан `not_a_broken_run`. Охрана stop'а из этого состояния недостижима (терминальный Run нельзя ограничить вовсе) и стоит для Run, сломавшегося при уже действующем stop.
