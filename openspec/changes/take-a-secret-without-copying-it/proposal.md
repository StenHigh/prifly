## Why

Программа шага получает окружение из machine-local `local.yaml`, и задать его
можно только литералом: `project local set --env NAME=VALUE`. Пароль базы,
токен, ключ — всё это приходится скопировать в файл руками. Замер холодного
захода: хост разработчика отказался выполнять такую команду («копирование
секрета из `.env` в другой файл»), и заход встал перед шагом `tests`, потому
что программа проекта без пароля падает на аутентификации, а `fail` у этого
шага ведёт в `abandoned`. Обхода не нашлось: `--env` принимает только
литерал. То же самое встретит любой проект, чьи программы ходят в базу.

Сейчас секрет, попавший в `local.yaml`, ещё и печатается в предстартовом
итоге (это закрывает change `let-a-clone-join-an-existing-project`), но сам
способ «скопируй значение сюда» остаётся единственным.

Изменение затрагивает product runtime и machine-local конфигурацию; на
опубликованные контракты Run оно не влияет. Ownership источников не меняется.

## What Changes

- `local.yaml` получает вторую форму объявления переменной окружения
  программы: значение берётся **из окружения вызывающего** или **из файла**,
  а не записывается в файл конфигурации. Имя переменной объявлено, значение
  разрешается при запуске программы.
- `project local set` получает соответствующие флаги, чтобы форму не писать
  руками.
- Отсутствие источника — именованный отказ до запуска программы, а не падение
  программы на аутентификации: запуск отказывается, называя переменную и
  место, где её ждали.
- Значение по-прежнему не печатается ни в итоге, ни в задаче, ни в
  диагностике.
