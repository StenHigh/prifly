## Context

Разбор глобальных флагов даёт `--project` умолчание `.`, поэтому команда,
запущенная вне проекта, открывает несуществующую authority и падает в общий
`not_found`; тот же код возвращает `SessionTask`, когда Run жив, но передачи
нет. `--help` обрабатывается только на верхнем уровне, поэтому у подкоманды
флаг уходит в flag-парсер после открытия authority; `--version` глобальным
флагом не является. `PublicSchema` ищет имя в списке bundles и отдаёт первый
совпавший, списка имён не публикует, declared reference (`core:schema/...`)
не принимает. Закреплённый контекст пишется как `context/skills/00`, `01` в
порядке ссылок, и `LocalPort.Ref` для этих записей пуст. Сводка Run считает
`len(v.Run.Outputs)`. `nextKind` пропускает attempt, ожидающий host, и
возвращает `idle`. Мотивация и полный список замеров — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Форма вызова и множество публичных контрактов читаются из инструмента.
- Отказ называет, чего именно нет, и не утверждает отсутствие того, что есть.
- Handoff самодостаточен: раскладка контекста и выходов видна из bundle.

**Non-Goals:**
- Новые значения enum и новые обязательные поля в опубликованных контрактах.
- Источник контекста в виде каталога для `references/**` (отдельный change).
- Внешняя запись, доставка действий и веха P2-09.

## Decisions

1. **Справка и версия разбираются до открытия authority.** Разбор глобальных
   флагов возвращает признак «запрошена справка/версия», и команда печатает
   строку использования своей подкоманды из одной таблицы, из которой
   собирается и общая справка; `help TOPIC` фильтрует ту же таблицу. Так
   справка и реальные флаги не расходятся. Альтернатива — отдельные тексты у
   каждой команды — расходится при первой же правке.
2. **`authority_not_found` отделён от `not_found`.** Открытие authority
   различает «каталог есть, authority нет» и прочие ошибки чтения; первое
   даёт `authority_not_found` с полученным путём в `violations` и советом
   назвать `--project`. `not_found` остаётся для объектов внутри существующей
   authority.
3. **`no_active_handoff` вместо `not_found` у `SessionTask`.** Если Run
   загружен и не держит ожидающего host attempt, отказ называет это, а
   `safe_next_actions` называет `run.explain` и `run.drive`. Отказ «нет такого
   Run» сохраняет прежний код.
4. **`waiting_host` не добавляется в enum.** `action` остаётся `idle`, но
   `safe_next_actions` для Run с ожидающим host attempt получает
   `session.task`, и `explain` называет ожидание словами. Так read-only вид
   перестаёт вводить в заблуждение, не создавая новую версию bundle
   `CoreNextView`: enum закрыт границей версии, а `safe_next_actions` уже
   свободный список строк. Альтернатива — новая versioned NextView — стоит
   отдельного slice ради одного слова.
5. **`schema` без аргумента печатает имена, а не отказ.** Список собирается
   из тех же bundles, из которых читает `PublicSchema`, плюс baseline
   `flow.ProtocolSchema`; declared reference принимается через таблицу
   соответствия `core:schema/step-result` → `StepResult`, построенную из
   builtin definitions, а не из захардкоженного списка.
6. **Идентичность записей контекста — через имя файла.** Записи пишутся как
   `context/skills/<sanitized ref id>` вместо `%02d`, и `LocalPort.Ref`
   заполняется ссылкой. Это меняет пути внутри attempt workspace, а не
   опубликованный контракт; sealed context manifest перечисляет те же записи
   с их ссылками. Раскладка выходов сообщается тем, что handoff уже несёт
   `workspace_trees`: host заполняет слоты, для которых нет binding.
7. **Счётчики сводки называются по тому, что считают.** Строка печатает
   выходы Run и отдельно число запечатанных выходов шагов, взятое из принятых
   результатов attempt-ов, а не из выходов Run.
8. **Описания полей добавляются в generated schemas.** `description` — только
   аннотация, validation не меняется, но байты bundles меняются, поэтому
   `make schema-check` и immutability-тесты перегенерируются в том же
   изменении.
9. **Authoring schemas публикуются через тот же индекс.** Девять файлов
   `schemas/authoring/*.schema.json` встраиваются рядом с bundles обмена и
   отдаются по имени документа (`extension`, `step`, `workflow`, …). Их форма
   уже поставляется файлами для редактора; вопрос только в достижимости из
   инструмента. Альтернатива — ссылка на файлы в справке — не помогает тому,
   кто ищет по имени, а именно так их и искали.
10. **Справка называет каталог примеров, а отказ — применимую команду.**
   Строка про `examples/authoring/` в общей справке и упоминание
   `project compile` в отказе `validate` на пути вне authority. Полный пример
   вставки в ребро уже лежит в `extension-authoring-reference.yaml`, поэтому
   писать нечего — нужно на него указать.
11. **Отказ по имени компонента перечисляет известные имена.** Множество
   имён у обеих проверок уже под рукой — карта шагов и имя workflow, — поэтому
   отказ печатает его целиком. Полный `id` не принимается и дальше: короткое
   имя папки остаётся единственной формой, меняется только читаемость отказа.
12. **Разрешение запечатанного package называет предмет.** Поиск идёт по
   точному ref и статусу `trusted`; при промахе тот же проход запоминает
   запись с тем же id и версией, поэтому отказ различает «не установлен»,
   «не доверен» и «другие bytes» без второго запроса. Отсутствующая папка
   объявленного package уже названа (`project_profile_invalid: package source
   does not exist`), поэтому там менять нечего.
13. **Diagnostic получает тот же stable code, что и Problem.** Драйвер
   распознавал только `*local.Rejection`, поэтому refusal, поднятый голым
   кодом, записывался под общим fallback фазы. Признаются также `*flow.Problem`
   и голый код; nil-ошибка по-прежнему даёт fallback.
14. **Read view перестаёт вычищать reported text.** Убраны две очистки —
   `Accepted.Summary` и `Report.Summary`/`Limitations`; token hashes, envelope,
   candidate bytes, определения, исполнители и workflow вычищаются как прежде.
   Владелец authority читает собственные данные, а прежняя защита работала
   только против пересылки вида целиком, не против чтения владельцем, и при
   этом делала пустое поле неотличимым от отсутствия текста. Telemetry строит
   свой отчёт отдельно, поэтому её граница не затронута.
15. **`project local set --executable PATH`** переписывает единственное поле
   `.prifly/local.yaml`, сохраняя `authority_root`, и отказывает, если файла
   нет: создание остаётся за `project init`.

## Risks / Trade-offs

- [Переименование файлов контекста ломает host-скрипты, читавшие `00`/`01`] →
  порядок никогда не был контрактом, и оба pilot-исполнителя предупреждены;
  sealed manifest перечисляет записи явно.
- [Перегенерация bundles ради `description` меняет байты всех схем] → байты
  сверяются гейтом, изменение видно в diff целиком, validation не меняется.
- [`action` остаётся `idle` при ожидании host] → слово по-прежнему неточное;
  честная замена требует новой версии NextView и делается отдельно, когда
  версия будет подниматься по другой причине.

## Migration Plan

Persisted state, admission и sealing не меняются. Пути внутри attempt
workspace меняются только для новых attempt-ов; прогоны, начатые прежней
версией, дочитываются как есть.
