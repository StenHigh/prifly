## Why

В подробностях завершённого Run с `outcome: partial` раздел «Сейчас» сообщает лишь «Активная работа и ожидания не записаны». Это выглядит как пробел наблюдения или ожидание агента, хотя внутри этого Run работа уже закончена; пользователь не видит, почему маршрут завершился частично и требуется ли его решение.

## What Changes

- Для терминального Run показывать явную границу: работа внутри него завершена и сама не возобновится. Не подменять это сообщение текстом об отсутствии записанной активности.
- Для `partial` рядом с итогом показывать записанную причину, когда её можно однозначно связать с завершающим маршрутом, и давать переход к соответствующей стадии, результату или артефакту. Если связь неоднозначна или данных нет — честно указать это, не сочиняя диагноз.
- Отличать записанную рекомендацию следующего действия от состояния исполнения: работа в чате вне Attempt или другого Run не означает, что исходный Run активен. Не превращать проектную рекомендацию вроде `/aif-fix` в универсальную команду Pri-Fly.
- Не менять сохранённые Runs, `outcome`, authority, публичный JSON или маршрутизацию workflow.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `local-run-monitor`: терминальный частичный итог объясняет завершение и подтверждённую причину, отдельно от текущей активности.

## Impact

Локальный read-only монитор и его UI-проверки. Product runtime, API, схемы, исполнители и закреплённые Runs не меняются. Ownership нормативного source set остаётся у `openspec/specs/local-run-monitor/spec.md`.
