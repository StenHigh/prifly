## Why

Выпуск держит работу пилота, ради которого сделан Pri-Fly: между готовым
изменением и релизом уходят часы. Причины измеримы. Из 656 тестов пакета
`internal/runtime` ни один не помечен `t.Parallel()`: пакет идёт строго по
одному тесту (~280 с локально). Весь движок — один пакет на 74 тыс. строк,
поэтому любое изменение запускает его целиком, и кэш тестов Go не помогает. На
каждый push GitHub в одной задаче гоняет `make ci-check`, а следом полный e2e.
Во время разработки агент прогонял полные ворота после каждой правки.

## What Changes

- **Параллельность.** Независимые тесты помечаются `t.Parallel()`. Тесты с
  `t.Setenv` (79 вызовов), `synctest` и подменой глобальных переменных остаются
  последовательными — Go сам отказывает `t.Setenv` в параллельном тесте.
- **Только затронутое.** `make test-changed` запускает пакеты, чьи файлы
  изменены относительно `origin/main`, и пакеты, которые от них зависят, плюс
  тесты-стражи, читающие файлы по пути (карта «каталог → стражи»: такие тесты не
  называют файл, который читают, и выбор по имени их пропускает). Пакет
  `internal/runtime` разбивается на подпакеты там, где граф зависимостей это
  позволяет, чтобы изменение в одной области не перезапускало весь движок; где
  не позволяет — это записывается с причиной.
- **Разбиение в CI.** `verify` делится на параллельные задачи: тесты
  `internal/runtime` на несколько шардов по списку тестов, остальные пакеты,
  статические проверки (vet обеих платформ, staticcheck, vuln, схемы, fmt,
  refusal).
- **Уровни.** На каждый push — быстрый набор (тесты и статические проверки).
  Race-детектор и полный e2e — только перед релизом: один workflow `qualify`
  на конкретном коммите, и тег ставится только на коммит с успешным `qualify`.
  Локально: `make check-fast` для разработки, `make qualify` перед релизом.
- Попутный дефект с 0.13.69: поле верхнего уровня отчёта сессии, положенное
  внутрь `result`, отклоняется с указателем `/result/<поле>` и подсказкой, а не
  голым `schema_invalid`.
- Цифры до и после записываются в change: время `internal/runtime`, `cmd/prifly`,
  push-проверки на GitHub и предрелизной квалификации.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `release-distribution`: проверки делятся на повседневные и предрелизные;
  тег выпускается только с коммита, прошедшего предрелизную квалификацию.

Затрагивает процесс репозитория; в runtime — текст одного отказа и ожидание при взятии двух блокировок.

## Impact

- `Makefile`, `.github/workflows/verify.yml`, `race.yml` → `qualify.yml`,
  новые `scripts/tag-release.py` (тег только на квалифицированный коммит),
  `scripts/test-changed.py`, `scripts/test-shard.py` и их тесты;
  `test/e2e/verify-release-ci.py` проверяет, что разбиение не потеряло проверку.
- `internal/runtime/engine.go`, `config.go`: окно повторов для блокировок
  драйвера и authority — ложные `driver_already_active`/`storage_busy`,
  найденные параллельными тестами.
- `*_test.go` в `internal/**`, `cmd/**`: `t.Parallel()`; перенос кода в
  подпакеты `internal/runtime/...` с тестами.
- `AGENTS.md`: как запускать проверки во время разработки и перед релизом.
