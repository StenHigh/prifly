## Purpose

Определяет единый локальный интерфейс наблюдения за всеми сохранившимися Run пользователя ОС: полноту обнаружения, понятную навигацию и отображение записанных фактов без вмешательства в исполнение.

## Requirements

### Requirement: Общий список охватывает сохранившиеся локальные Run
Монитор SHALL объединять Run из обнаруженных и зарегистрированных локальных хранилищ текущего пользователя ОС, включая старые и тестовые. Поиск MUST выполняться фоном с видимой областью, прогрессом и ошибками; неполное обнаружение не называется полным. Один физический источник не дублируется из-за альтернативного пути. Недоступный, повреждённый либо несовместимый источник MUST быть видим отдельно и не скрывать здоровые источники. Удалённые Run восстанавливать не требуется. Источник истины — существующая authority; каталог монитора не создаёт право управления.

#### Scenario: Несколько проектов и старые запуски
- **WHEN** пользователь открывает монитор с несколькими локальными authority, в том числе нестандартно расположенными
- **THEN** найденные Run доступны в одном списке, новые источники появляются по мере поиска, а область и неполнота поиска видны

#### Scenario: Источник недоступен
- **WHEN** один источник не удаётся прочитать
- **THEN** монитор показывает ошибку этого источника и продолжает показывать остальные

### Requirement: История имеет поиск и постраничную навигацию без общего предела
Монитор SHALL предоставлять поиск по задаче, Run и сценарию, фильтры проекта, состояния, исполнителя и периода, сортировку и постраничную загрузку. Число Run больше 200 MUST NOT приводить к отказу либо скрытому обрезанию. Прямая ссылка SHALL восстанавливать выбранные источник, Run и узел. Фильтрация применяется ко всей доступной истории, а неполный индекс отмечается.

#### Scenario: История больше одной страницы
- **WHEN** в хранилище есть более 200 Run и искомый запуск не находится на первой странице
- **THEN** он доступен поиском и переходом по страницам без обхода лимитов полного telemetry scan

### Requirement: Обзор и схема отражают закреплённый сценарий Run
Обзор SHALL показывать задачу, проект/рабочую область, сценарий, состояние, итог, причины ожидания, решения и диагностику. Схема SHALL показывать узлы и соединения закреплённого workflow, развилки, параллельные пути и предстоящие стадии, а дерево — реальные WorkflowInvocation, StageActivation, StepInstance и Attempt. Выбор узла SHALL открывать его подробности. Будущий узел определения не является созданной Attempt; невыбранная ветвь отличается от предстоящей, ошибочной и завершённой работы. Неизвестное число будущих итераций не изображается выполненной работой.

#### Scenario: Сценарий изменили после старта
- **WHEN** установленная версия сценария изменилась после создания Run
- **THEN** схема Run по-прежнему строится из его закреплённых определений

#### Scenario: Вложенные сценарии и параллельные попытки
- **WHEN** Run содержит несколько включений, ветвей или попыток
- **THEN** их identities сохраняются в дереве и выбранные подробности не смешиваются

### Requirement: Подробности показывают переданное задание и сохранённые результаты
Монитор SHALL человекопонятно показывать записанное задание попытки, инструкции и контекст, входы, сведения об исполнителе, полученный кандидат и принятый результат, проверки, выходные артефакты и журнал Pri-Fly. Полные структурированные данные остаются доступны для разбора. Просмотр содержимого артефакта SHALL явно сообщать объём и обрезание предпросмотра. Список файлов SHALL опираться только на сохранённые manifests/evidence и не выдавать текущие изменения рабочей папки за исторический результат шага. Diff, переписка чатов, вызовы инструментов и stdout/stderr не входят в этот срез.

#### Scenario: Задание выдано, результат не поступил
- **WHEN** Attempt передана внешнему исполнителю
- **THEN** пользователь видит переданное задание и ожидание результата, без утверждения о живом процессе агента

#### Scenario: Список файлов не записан
- **WHEN** сохранённые данные не позволяют установить изменения файлов
- **THEN** интерфейс обозначает сведения как недоступные, а не показывает ложный пустой список

### Requirement: Метрики и обновления сохраняют достоверность и место чтения
Монитор SHALL показывать записанные время, стоимость, tokens/model/reasoning, когда такие сведения действительно присутствуют. Неизвестное не заменяется нулём, а сообщения стоимости разных источников/валют не складываются в выдуманный счёт. Русский интерфейс SHALL поддерживать системную светлую/тёмную тему, клавиатурную навигацию и явные состояния загрузки/ошибки. Изменения доступного источника SHALL проверяться каждые 1–2 секунды; длительная загрузка обозначается, запросы не накладываются бесконечно. Обновление MUST сохранять выбор, раскрытые подробности и позицию чтения.

#### Scenario: Пользователь читает подробности работающего Run
- **WHEN** источник обновился во время чтения
- **THEN** данные обновляются без сброса выбранного шага и места чтения

### Requirement: Монитор остаётся локальным наблюдателем
Монитор MUST слушать только loopback, проверять Host, не давать CORS-доступ произвольным сайтам и не исполнять содержимое Run/артефактов как HTML. HTTP endpoints SHALL принимать только операции чтения. Произвольный путь из HTTP запроса не открывается как новый источник. Разрешения чтения и проверка владельца authority сохраняются; опубликованные контракты и историческое evidence не переписываются.

#### Scenario: Посторонняя web-страница или вредоносный текст
- **WHEN** приходит запрос с чужим Host либо записанное задание содержит HTML/script
- **THEN** запрос отклоняется либо данные отображаются текстом без выполнения и внешних запросов
