## ADDED Requirements

### Requirement: Список Run различает созданные шаги и попытки исполнения

Колонка исполнения SHALL отдельно и явно подписывать количество фактически созданных StepInstance и общее количество Attempt. Она MUST NOT показывать эти два числа безымянной дробью или представлять их как выполненную долю Workflow, число всех Stage либо прогноз оставшейся работы. Для Attempt SHALL отдельно показываться число с зафиксированным Settlement и число ещё не учтённых попыток; известное ожидание хоста SHALL обозначаться своим состоянием. Settlement MUST NOT называться успешным результатом шага или outcome Run. Краткое пояснение SHALL быть доступно без знания внутренних имён и с клавиатуры: один созданный шаг может иметь несколько попыток, а будущие или невыбранные узлы не входят в эти счётчики. Отсутствующие либо недоступные значения MUST отображаться как неизвестные, не как ноль.

#### Scenario: Хост ещё не ответил
- **WHEN** RunSummary содержит четыре созданных StepInstance, четыре Attempt, три учтённые Attempt и одну ожидающую хоста
- **THEN** список показывает отдельно «4 шага создано», «4 попытки», «3 учтены» и «1 ожидает агента», не создавая впечатления «4 из 4 выполнено»

#### Scenario: Повтор исполнения одного шага
- **WHEN** один StepInstance получил вторую Attempt после допустимого повторного допуска
- **THEN** список сохраняет один созданный шаг и две попытки, а пояснение объясняет различие

#### Scenario: Ветвь ещё не выбрана
- **WHEN** закреплённый Workflow содержит будущие и невыбранные Stage, для которых StepInstance или Attempt не создавались
- **THEN** список не включает их в фактические счётчики и не вычисляет процент завершения

#### Scenario: Run завершился с отклонённым outcome
- **WHEN** все Attempt учтены, а Run завершён с outcome `rejected`
- **THEN** счётчики остаются фактическими и не окрашиваются или не описываются как успешное выполнение Run
