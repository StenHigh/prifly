## Why

Отчёт пилота по work item 155: обязательный gate вернул `broken`, потому что
PostgreSQL был временно недоступен. `new_failures_total=0` — ни одной
подтверждённой регрессии. Движок отработал по графу, но у gate не было способа
сказать «я не смог вынести суждение», отличный от «работа не прошла». Дальше
граф повёл Run по маршруту исправления, и последняя fix-попытка вернула
`needs_revision` без изменений кода: исправлять было нечего.

Стоимость названа в отчёте прямо: следующему оператору нужен диагноз
«инфраструктура недоступна», а не призыв повторно править код.

Сегодняшний словарь — `pass`, `fail`, `needs_revision`, `no_work` — весь про
работу. Отсутствие суждения о работе в нём не выражается, и gate вынужден
занять чужую клетку.

## What Changes

- Новый вердикт шага, означающий «суждение не вынесено»: не оценка работы, а
  заявление о том, что оценить её не удалось. Рабочее имя — `blocked`.
- Автор, которому нужен повтор по этой причине, объявляет для него маршрут —
  например, обратно на ту же стадию. Автор, которому не нужен, получает точный
  диагноз вместо ложного маршрута исправления.
- **BREAKING по форме, не по поведению:** требование полноты маршрутов
  действует для ревизий 4 и 5, и расширение общего списка вердиктов сделало бы
  каждый уже запечатанный граф неполным на компиляции. Поэтому набор вердиктов,
  который проверяет полнота, становится свойством версии ревизии: 4 и 5
  отвечают за прежние четыре, новый вердикт обязателен только с новой ревизии.
- Для запечатанного графа без маршрута новый вердикт ведёт себя как сегодня
  ведёт себя неотвеченный: принятый результат сохраняется, Run падает с
  `unhandled_verdict`. Это уже проверенное поведение, а не новое.

## Capabilities

### Modified Capabilities

- `domain-execution`: словарь исходов шага различает суждение о работе и его
  отсутствие.
- `cli-protocol`: полнота маршрутов проверяется набором вердиктов своей ревизии.
- `workflow-and-context`: новая версия WorkflowRevision и её требование полноты.

## Impact

- `internal/flow/compile.go`: `StepVerdicts`, `checkVerdictCoverage`,
  `Plan.Next`, новая константа версии ревизии.
- `internal/runtime/`: маршрутизация исхода, `RoutedVerdicts` в задаче хоста.
- `schemas/`: новая версия WorkflowRevision; опубликованные бандлы не меняются.
- `examples/authoring/`, `examples/troubleshooting.md`.
- Пакет: чтобы это заработало у пилота, его gate должен начать возвращать новый
  вердикт, а его граф — объявить маршрут. Без этого движок только перестаёт
  вести в ложный цикл исправления.

## Чего этот change не делает

Не добавляет состояние ожидания внешней зависимости в жизненный цикл Run: это
был третий вариант того же вопроса, и владелец выбрал словарь. Не превращает
`broken` gate-скрипта в вердикт автоматически — источник различия там, где
решение принимается, то есть в самом gate.
