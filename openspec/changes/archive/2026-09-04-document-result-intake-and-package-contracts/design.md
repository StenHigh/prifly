## Context

`renderRun` печатает состояние Run, стадии и счётчики, но не вердикты шагов;
`RunView` их несёт (`run.steps[<id>].verdict`), поэтому данные есть, а
текстовый читатель их не видит. `contractSchema` ищет имя в embedded bundles,
в baseline и среди authoring documents — всё это встроено в binary; schema,
объявленная package, лежит в `PackageEntry.Components` установленной authority
и по имени не разрешается. Дамп отдаёт bundle целиком с `$ref` на корень.
Форма публикации не-древесного выхода проверяется в `readResultOutputs`
(identity slot, digest файла slot), но нигде не объявлена: host выводит её из
`context.json` и устройства storage. `ValidateDecisionDefinition` принимает
`Required` при любой фазе, а enforced он только в `project start` и только для
`preflight`. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Исход собственной работы читается обычной сводкой.
- Форма публикации выхода и schema обязательного выхода читаются из
  инструмента, а не из хранилища.
- Каталог не обещает обязательности там, где её нет.

**Non-Goals:**
- Новые команды-синонимы для чтения Run: данные уже есть у `run status`.
- Пустые `violations` у `package_not_resolvable` и позиционный ID у
  `run status` — следующая порция диагностики.
- Изменение того, как выход публикуется: меняется только его описанность.

## Decisions

1. **Вердикты печатаются строкой на шаг.** `renderRun` добавляет по строке
   `step <id> status=… verdict=… outputs=…` для шагов с известным вердиктом,
   после счётчиков и до дерева времени. Альтернатива — отдельная команда
   `run steps` — добавляет имя, которое надо угадать, при уже доступных
   данных.
2. **Компонент package читается командой package, а не командой схем.**
   `package inspect` получает `--component ID` рядом с существующим `--ref`:
   он ищет компонент с этим declared ID среди установленных trusted packages
   и отдаёт его bytes. Так команда схем остаётся чистой функцией от binary —
   она отвечает за контракты обмена и authoring documents, которые встроены, —
   а чтение того, что принёс package, остаётся в команде про packages.
   Альтернатива, разрешать declared ID в команде схем, делала бы один и тот же
   вызов зависящим от того, открыта ли authority и что в неё установлено.
3. **`--def NAME` отдаёт одно определение с его закрытием.** Селектор
   переиспользует уже существующий проход по `$ref` внутри bundle, а не режет
   JSON текстом: определение без своих зависимостей нечитаемо.
4. **Форма публикации записывается в handoff.** `SessionTask` уже несёт
   `Context` с путями слотов; к нему добавляется описание в published contract
   и строка в authoring reference. Поля reported result не меняются — меняется
   то, что они объявлены.
5. **`required` отклоняется для runtime-фазы при валидации определения.**
   Проверка живёт в `ValidateDecisionDefinition`, то есть отказ приходит при
   компиляции package, а не при старте Run. Ни один поставляемый package так
   не объявляет, поэтому существующие пакеты не ломаются.

## Risks / Trade-offs

- [Сводка становится длиннее на число шагов] → строка на шаг короткая, а
  альтернатива — читатель, который лезет в SQLite.
- [Читатель ищет форму пакета не там] → команда схем при неизвестном ID может
  назвать команду чтения package, чтобы поиск не заканчивался тупиком.
- [Отказ на `required` в runtime-фазе может удивить внешнего автора] → таких
  каталогов сегодня нет, а сообщение называет, какая фаза поддерживает флаг.

## Migration Plan

Persisted state, admission и sealing не меняются. Package, объявляющий
`required` у runtime-решения, перестанет компилироваться и потребует правки
одной строки в своём каталоге.
