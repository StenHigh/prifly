# Продолжение от незамерженной Implementation

**Дата:** 2026-09-23 15:40
**Файлы:** `cmd/prifly/project_continuation.go`, `cmd/prifly/project_start.go`, `cmd/prifly/main.go`
**Серьёзность:** medium

## Проблема

После terminal `partial` исходная Implementation могла остаться только в claim-ветке. `project continue` читал HEAD выбранного Project checkout, поэтому чистая базовая ветка отказывала с `project_continue_unrelated_head`. Выбор прежнего claim-worktree внутри authority нарушал границу Project и authority.

## Причина

Continuation связывала два разных выбора: Project checkout с профилем и машинной конфигурацией и Git commit реализации. В обычном старте они совпадают; в продолжении до merge — нет.

## Решение

`--implementation-head` принимает полный доступный commit ID. Prepare проверяет его ancestry и включает в digest; start создаёт новый worktree claim от точного commit. Основной checkout и прежний Run остаются на месте. `checkout` mode с отдельным commit отказывается.

## Предотвращение

Для продолжения проверять отдельно источник профиля и exact Git head реализации. Тест закрепляет незамерженную ветку, материализацию нового claim и неподвижность базы; read-only pilot на SMSPlace проверил partial Run и реальный SHA.
