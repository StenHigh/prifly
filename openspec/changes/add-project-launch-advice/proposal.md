## Why

Когда пользователь передаёт задачу без точного launch ID, `prifly-run` показывает список, но не помогает сопоставить задачу с назначением сценариев. [Issue #3](https://github.com/StenHigh/prifly/issues/3) требует краткого совета до ручного выбора, общего для любых объявленных project workflows.

В показанном пользователем диалоге Codex выбор остался текстовым списком. Указание на native question tool сейчас находится в разделе runtime-решений; предстартовый выбор должен явно использовать доступный инструмент host, независимо от применимости совета.

## What Changes

- Общий generated `prifly-run` условно помогает выбрать launch по исходной задаче, существующим `title` / `description` и критериям соседнего `PROJECT.md`. Если такой выбор применим и обоснован, runner рекомендует один launch; если оснований недостаточно, сообщает об этом без выдуманного совета.
- Рекомендация не становится обязательной стадией каждого workflow. Точный ID, единственный launch, отказ от совета и проектное отключение обходят подбор; `PROJECT.md` может уточнять применимость для проекта или отдельных launch, не скрывая варианты и не меняя границы исполнения. Новые обязательные metadata или настройки не требуются.
- Совет выполняет текущая host-сессия до создания Run. Пользователь видит все объявленные варианты, может пропустить совет или выбрать альтернативу; до явного выбора runner не создаёт package, claim или Run.
- Выбор launch и другие применимые конечные выборы до запуска показываются через доступный и допустимый для этого вопроса native question tool Codex или Claude. Проверяются ограничения режима, асинхронное ожидание ответа и страницы для большого списка; текстовый вопрос используется при отсутствии применимого инструмента. Свободный ввод и подтверждение выполнения сохраняют свои правила.
- Точный объявленный launch ID сразу ведёт к его анкете без повторного подбора; неизвестный ID не заменяется похожим. Отсутствие задачи, неоднозначные описания, один launch и пустой список имеют явное поведение.
- После выбора сохраняется исходная задача, упакованная по объявленному input выбранного workflow, и действующий questionnaire → typed validation → read-only prepare → reviewed start.
- Обновление runner доставляет поведение поддерживаемым hosts, распознаёт прежние exact generated bytes и сохраняет `PROJECT.md`. Фактический диалог проверяется отдельно от наличия текста в template.
- По дополнительному запросу владельца от 2026-10-12 обновить установленный Go и project/CI baseline до последней стабильной Go 1.27.2. Baseline `ci-check` на Go 1.27.0 уже остановился на уязвимостях стандартной библиотеки; исправленная версия проверяется теми же воротами без ослабления `vuln-check`.

## Capabilities

### New Capabilities

Нет: изменение расширяет существующие требования к project entry point и host runner.

### Modified Capabilities

- `cli-protocol`: условная рекомендация, явный вызов применимого native question tool до запуска, сохранение задачи и безопасный upgrade host instructions.
- `control-security-ux`: различие между советом и явным выбором исполняемого launch, доступность native UI и ожидание реального ответа.
- `workflow-and-context`: рекомендация host до запуска допускается, а исполнительная точка входа по-прежнему принимает только явно выбранный exact launch ID.

## Impact

Меняется продуктовое поведение host entry point, а не только процесс разработки репозитория. Runtime authority, admission, графы workflow, model selection и execution effects не меняются. Основные точки реализации — текущая генерация runner в `cmd/prifly/project.go`, runner/CLI tests и справочники project launch в `README.md` / `examples/`.

Новые schema fields, DTO, команды, числовой confidence, classifier, отдельный triage Run и правила AI Factory не добавляются. Версии опубликованных контрактов, сохранённые JSON-поля и ранее созданные Runs сохраняются.

Сопутствующее обновление Go касается локального toolchain, `go.mod` и совместимых точных pins анализаторов в `Makefile`; workflows CI уже читают `go-version-file: go.mod`. Новых нормативных требований к runtime или ownership оно не вводит; historical build/release evidence сохраняет фактически использованные тогда версии.

Нормативная ownership не меняется ни у одной capability: source set остаётся в `openspec/specs/{cli-protocol,control-security-ux,workflow-and-context}/spec.md` по `openspec/SOURCE-OF-TRUTH.md`; delta этого change задаёт целевое поведение до archive/sync. Исторические evidence, archived changes и frozen runner bytes защищены. Отдельный пакет `aif-fix` из [связанного issue](https://github.com/StenHigh/prifly-aif-workflows/issues/4) в этот change не входит.
