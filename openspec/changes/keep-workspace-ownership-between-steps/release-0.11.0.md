# Выпуск Pri-Fly 0.11.0

Версия утверждена владельцем 2026-09-06. Исходная ветка —
`codex/workflow-neutral-plan`, базовый commit подготовки — `5f46427`.
Нормативный порядок выпуска остаётся в `release-distribution/spec.md`.

Минорная, а не патч-версия: меняется модель владения рабочей копией и момент,
от которого отсчитывается рабочее окно шага. Это поведение продукта, а не
исправление формы поля.

## Scope

**Владение рабочей копией переживает паузу владельца.** Истёкшая аренда больше
не отказывает Run, к которому claim привязан, если работу просит тот же actor;
допуск продлевает аренду в той же транзакции. Живой заход пилота терял три
отработавших шага, потому что единственным выходом была отмена прогона.
Замеры, определившие выбор механизма: работа исполнителя одного шага 10–18
минут, пауза владельца 90 минут в замеренном случае и часы в ночном сценарии;
наблюдаемых действий в паузе нет по построению, поэтому перезахват стал
основным путём, а продление — вспомогательным.

Границы не сдвинулись: чужой Run и чужой actor получают отказ как прежде,
непривязанный claim сохраняет прежнюю защиту, брошенная копия по-прежнему
освобождается.

**`claim heartbeat` впервые исполним.** Он сверял идентификатор сессии часов
процесса, новый у каждого запуска CLI, поэтому не мог сработать ни у кого
никогда. Сверяет actor.

**Три отказа называют путь восстановления**, включая явное указание, что на
освобождении аренда не читается — там отказ вызван неулаженным Run.

**Рабочее окно ассистируемого шага открывается вручением**, а не созданием
попытки: подготовка перестала списываться с исполнителя. Объявленное окно
подхвата у ассистируемых шагов равно рабочему и проверяется; расхождения
«объявлено, но не соблюдается» не осталось.

**Задание без объявленных `session_limits` не несёт срока.** Прежде там лежала
строка настенного времени, которую движок сам метит `local_wall_unqualified`,
а сверить её получатель не мог. Timed-контракт по-прежнему несёт срок вместе с
полным наблюдением в `delivery`. Пустой срок означает «проверяемого не дано»,
а не «ограничений нет»: движок продолжает проверять свой срок при приёме
отчёта.

**Ответ на решение о package profile виден в карте решений** под
зарезервированным ключом `core:package_profile`; прежде он не попадал в неё
вовсе, и инструкция «читать всю карту» его теряла.

**Из подготовленного 0.10.1:** анкета `project-questionnaire/4` с единым `id`
во всех трёх списках и `project-launch-summary/3`. Отдельный выпуск ради
переименования поля владелец делать не стал, и эта правка выходит здесь.
Запись `release-0.10.1.md` сохранена как evidence того, что кандидат был
подготовлен и проверен.

**Версии контрактов не поднимаются** сверх названных: ни одна правка владения и
сроков не меняет форму записи и не переинтерпретирует сохранённые Runs.
`decision_context` был и остаётся свободной картой, `deadline` объявлен строкой
без шаблона.

Что в выпуск не входит: признак доверия к сроку для legacy-контракта (вместо
него срок не передаётся), живые UI observations, живой AIF pilot, формальные
P1/P2 gates. Известное ограничение из 0.10.0 переносится без изменений: при
отказе допуска уже после подготовки input tree созданные подготовкой файлы
могут остаться в рабочей папке (`workspace-tree-preparation-rollback`).
