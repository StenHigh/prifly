## Why

Инструмент задумывался под параллельную работу: одна ветка `development`, много
независимых задач, каждая в своём worktree, каждая — свой Run. Ради этого Run и
сделаны отдельными.

Сегодня это невозможно. Второй `project start` по тому же репозиторию получает
`claim_conflict`, даже если он берёт **другой** worktree, с другим путём, другой
веткой и другим рабочим деревом.

Установлено чтением, а не предположением: в решении о конфликте участвует
**единственное** сравнение — общий каталог git (`worktrees.go:344` и `:217`):

```go
if existing.Repository.CommonDir != identity.CommonDir { continue }
if existing.active() { … claim_conflict … }
```

Режим рабочей копии в решении **не участвует вовсе**. Он записывается в команду
и в запись клейма, но на отказ не влияет. Линкованные worktree одного
репозитория делят `--git-common-dir`, поэтому для движка они неотличимы —
зависимая сессия это измерила.

Правило написано одно на два режима, и спецификация это утверждает намеренно:
«using the same canonical physical repository identity, owner, generation and
lease conflict rules». Для режима `checkout` оно необходимо: там рабочее дерево
буквально одно. Для `worktree` оно строже, чем требует предмет, и стоит нам
ключевой функции продукта.

## What Changes

- Отношение конфликта становится **общим рабочим деревом**, а не общим
  репозиторием.
- Два клейма `worktree` по разным путям одного репозитория — разные ресурсы,
  оба допускаются.
- Клейм `checkout` конфликтует с другим `checkout` того же репозитория: это
  одно и то же дерево.
- `checkout` и `worktree` рядом не конфликтуют: первый работает в первичном
  дереве, второй его не трогает по определению режима.
- **BREAKING** для требования `runtime-resources`: «Both modes MUST block a
  conflicting Workspace claim» перестаёт быть верным дословно и заменяется на
  правило про разделяемое дерево.
- Отказ `claim_conflict` называет **отношение**: конфликт по общему каталогу
  git, а не по рабочему дереву, с командой, которой читатель это проверит.
  Читатель в линкованном worktree сегодня видит другой путь, другую ветку и
  другое дерево и заключает, что отказ не про него.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `runtime-resources`: исключительность рабочей копии определяется деревом, а
  не репозиторием.

## Impact

- `internal/runtime/worktrees.go` — два места решения о конфликте (`:217`
  одиночный и множественный захват, `:344`), текст отказа.
- `internal/runtime/claim_run.go:175` — освобождение завершённого клейма уже
  перебирает все клеймы репозитория и остаётся верным: оно освобождает только
  завершённые.
- Требование `Workspace claim сохраняет exclusivity в обоих Git режимах`
  (`openspec/specs/runtime-resources/spec.md:625`).
- Зависимые стороны: пилот (ради этого и заводилась работа), сессия пакетов
  (их четверо ворот исключительности не пинят — проверить).
