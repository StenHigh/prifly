## Context

См. [proposal.md](proposal.md). Сейчас `RunSummary` и каталог монитора не включают `Run.Fork`; `/api/runs` фильтрует, сортирует и режет плоский список по 50 строк, после чего `monitor.js` рисует таблицу. Связь видна только в подробностях выбранного Run. У #154 сохранилась цепочка с тремя уровнями: исходный Run → несколько `project continuation` → `recover_failed_stage`; рядом есть независимые корни с тем же заголовком.

## Goals / Non-Goals

**Goals:** восстановить точное происхождение Run в общем списке, не потеряв читаемость колонок и доступ к большой истории.

**Non-Goals:** объединять независимые Run одной GitLab-задачи, вычислять общий outcome группы, менять fork/recovery lifecycle или строить новое дерево WorkflowInvocation.

## Decisions

1. Добавить в локальную компактную проекцию только сохранённые `fork.source_run_id` и `fork.reason`. Ключ узла — `(source, run_id)`; parent ищется только в том же authority. `recovery.source_run_id` подтверждает вид восстановления, но не является дополнительным ребром. Без parent запись остаётся отдельным корнем с явной ссылкой на отсутствующий source ID. Альтернатива — группировать по `subject`/GitLab номеру — создаёт ложные причинные связи.
2. Для иерархического режима каталог строит parent-first порядок из всех индексированных summaries до разбиения на страницы. Страница содержит ограниченное число корней; дочерние строки загружаются ограниченными порциями при раскрытии, чтобы большая ветвь не создала неограниченный ответ. Корни и sibling Run сортируются по собственному времени создания от раннего к позднему по умолчанию либо от позднего к раннему по выбору пользователя, с устойчивым ID tie-break; предок остаётся выше потомков, соседние ветви не смешиваются в глобальную временную шкалу. Плоский режим использует нынешнюю сортировку и пагинацию. Альтернатива — отступать только строки текущих 50 результатов — разрывает ветви на границе страницы.
3. Фильтры применяются ко всему каталогу до групповой пагинации. Возвращаются группы с совпавшими Run; путь предков включается как `context`, не как дополнительное совпадение. При раскрытии группы совпадения видны, в том числе через свернутые промежуточные ветви; счётчик показывает число совпавших Run, не контекстных строк. Отсутствие исходного Run в каталоге отличается от его присутствия только как контекст фильтра.
4. Сохранить нативную таблицу со ссылками на Run. В первой ячейке использовать chevron-кнопку с `aria-expanded`, отступ по глубине, соединительные линии и текст «Продолжение»/«Восстановление»; остальные колонки не сдвигать. Не задавать `role=treegrid` без реализации полного клавиатурного контракта: нативные ссылки/кнопки доступны Tab, Enter и Space. Раскрытие хранить по `(source, run_id)` и восстанавливать при опросе/возврате к списку. На узком экране первая колонка сохраняет прокрутку и явную подпись связи, а не полагается на один цвет.
5. В локальной проекции строки ветви передавать только identity, status, outcome и `last_observed` самого нового доступного производного Run (по `last_observed`, затем ID). Выводить его как отдельно подписанный факт рядом с собственным статусом строки и ссылкой на точный Run. Это не агрегированный outcome семьи. Выбор делается по всему каталогу, а не только по совпадениям фильтра или уже загруженной странице дочерних строк.

## Risks / Trade-offs

- Каталог во время фонового сканирования неполон → показывать область обнаружения и временно отсутствующего родителя, пересобрать дерево после обновления без скачка позиции.
- Очень глубокая или ветвящаяся цепочка → порционная загрузка, вертикальные направляющие и горизонтальная прокрутка; не обрезать происхождение без подписи.
- Ручной ARIA `treegrid` дал бы ложное обещание навигации стрелками → использовать нативную таблицу и кнопки, либо внедрять полный паттерн отдельно. Ориентиры: [GitLab Pajamas Tree](https://design.gitlab.com/components/tree/) (chevron, отступ, connector) и [W3C Treegrid APG](https://www.w3.org/WAI/ARIA/apg/patterns/treegrid/) (контракт для полного treegrid).

## Migration Plan

Сохранённые Runs и published schemas не мигрируют. Иерархический режим — новая локальная read projection; плоский режим и существующие прямые ссылки продолжают работать. При откате UI старые данные остаются читаемыми плоским списком. Нормативный source set — `openspec/specs/local-run-monitor/spec.md`.
