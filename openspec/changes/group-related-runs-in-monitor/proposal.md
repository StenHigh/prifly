## Why

Список монитора сортирует каждый Run отдельно. У задачи #154 исходный Run, несколько прямых продолжений и повторные восстановления перемешаны с независимыми запусками: по таблице нельзя быстро восстановить записанное происхождение и отличить ветви друг от друга.

## What Changes

- По умолчанию показывать Run группами по сохранённой связи `fork.source_run_id`: исходный Run выше производных, каждое следующее поколение — с большим отступом и видимым соединителем. Подпись связи различает продолжение и восстановление по записанной причине fork; `recovery.source_run_id` не создаёт второго родителя.
- Внутри иерархии переключать порядок корней и соседних ветвей: ранние сверху или ранние снизу, сохраняя порядок предок → потомок.
- Дать свернуть/развернуть производные Run, показывать их количество и сохранять состояние раскрытия, выбор, фильтры и место чтения при обновлении. Оставить переключение в плоский хронологический список.
- Каждая строка сохраняет собственные status/outcome, время и ссылку на подробности. Общая группа не получает выдуманного «итогового статуса»; совпадение названия задачи без provenance не означает родство.
- Свёрнутая ветвь отдельно показывает факт самого нового производного Run с его status/outcome и ссылкой: успешное восстановление остаётся заметным рядом с ошибкой родителя, но не переписывает её.
- Поиск, фильтры и пагинация не должны терять совпавший производный Run или показывать его без контекста исходного Run. Если исходный Run удалён/недоступен, производный остаётся видимым с явным указанием недостающей связи.
- Не менять закреплённые Runs, смысл fork/recovery, WorkflowInvocation и публичные versioned contracts.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `local-run-monitor`: общий список представляет записанную цепочку происхождения Run как доступную иерархию с корректными фильтрацией и пагинацией.

## Impact

Локальный read-only монитор, его компактная проекция Run и UI/каталожные тесты. Это изменение поведения продукта, не процесса репозитория; нормативный source set остаётся `openspec/specs/local-run-monitor/spec.md`. Authority, запуск workflow, сохранённые данные и опубликованные JSON-схемы не меняются.
