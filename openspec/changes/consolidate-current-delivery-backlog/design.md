## Context

См. `proposal.md`. Постоянный `delivery-roadmap` уже содержит полный формальный
порядок P1/P2 и короткую текущую очередь. Подробности оставшихся работ
разбросаны между этой очередью, active changes и архивным каталогом будущих
идей.

## Goals / Non-Goals

**Goals:**

- Дать владельцу один читаемый список всей незавершённой работы.
- Сохранить разницу между обязательной поставкой, текущей работой и идеями
  после P2.
- Сделать дальнейшее обновление списка простой правкой одного OpenSpec source.

**Non-Goals:**

- Не переносить исторические отчёты, hashes или уже завершённые срезы.
- Не менять scope P1/P2, статусы их приёмки или runtime Pri-Fly.
- Не создавать второй формат управления задачами рядом с OpenSpec.

## Decisions

### Backlog живёт в `delivery-roadmap/spec.md`

Добавляется один раздел с тремя уровнями: active changes, формальная P1/P2
последовательность и post-P2 catalogue. Это один файл текущего нормативного
источника, а не новая папка, CSV или список, который нужно синхронизировать.

Альтернатива — восстановить `docs/roadmap/roadmap.md` — отклонена: она вернула
бы второй редактируемый источник и прежнюю проблему расхождения.

### История остаётся указателем, а не задачей

Проверка crosswalk определяет, какие исторические записи были evidence, а не
планом. В backlog попадает только будущая работа или ссылка на незавершённый
active change. Точная история остаётся доступна через Git и archived changes.

Альтернатива — переписать весь старый progress log в OpenSpec — отклонена:
dated evidence нельзя превращать в текущую спецификацию.

### Последовательность не заменяет отдельные OpenSpec changes

Backlog показывает порядок и входные условия. Перед реализацией конкретной
работы создаётся отдельный change с proposal, design, specs и tasks; ссылка на
него становится evidence progress записи.

## Risks / Trade-offs

- [Список снова устареет] → в requirement закреплена ссылка на change/release
  при закрытии и правило добавлять новую работу только через OpenSpec change.
- [Future ideas будут приняты за обещания] → они вынесены в отдельную группу с
  явным prerequisite и отсутствием committed scope.
