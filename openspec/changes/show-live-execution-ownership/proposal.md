## Why

У карточки шага сейчас видны технические данные, но не ясна роль исполнения: это управляющий узел workflow, локальная программа, выданная host Attempt или вложенный workflow. Во время работающего Run также приходится вручную сопоставлять дерево, Attempt и ожидания, чтобы понять, кто занят и какая причина блокирует дальнейшее движение.

## What Changes

- Показывать у выбранного узла его записанную роль исполнения, исполнителя/адаптер и состояние выдачи без предположения о живом процессе внешнего агента.
- Добавить в экран Run компактную live-сводку: активная работа, выданные и ожидающие отчёта Attempt, готовые к выдаче узлы, решения и сигналы, которых Run действительно ждёт.
- Явно показывать provenance fork Run и переходить к доступному исходному Run; не выдавать вложенный workflow или обычную host-сессию за fork.
- Оставить монитор read-only: изменение не добавляет pause, cancel, повторную выдачу или управление host.

## Capabilities

### New Capabilities

_Нет._

### Modified Capabilities

- `local-run-monitor`: экран Run получает достоверную навигацию по ролям исполнения, ownership и текущим ожиданиям.

## Impact

Изменяется локальный Web monitor (`cmd/prifly/monitor.js`, возможно его API-проекция и тесты) и его OpenSpec capability. Runtime не будет создавать новые действия или переписывать сохранённые Run; если нужная роль не записана, UI обозначит её как неизвестную.
