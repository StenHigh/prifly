## 1. Объявление в запечатанном плане

- [ ] 1.1 `internal/flow`: `StepDefinition` получает необязательное
  `model_profile` — `requested` (имя профиля работы) и `reason` (зачем он
  этому шагу). Новая авторская версия шага; пакет без объявления компилируется
  и ведёт себя как прежде. Профиль едет в `WorkflowRevision`, как
  `technical_retries` в 0.13.34: объявление — свойство шага, а не Run, и в
  состоянии ему делать нечего. Проверка: тест —
  пакет без поля компилируется байт-в-байт как раньше; с полем оно доезжает до
  плана.

- [ ] 1.2 Имя профиля — требование к работе, не провайдер. Отказ на значении,
  похожем на имя площадки или модели, с текстом, который называет разницу.
  Проверка: красный-до-правки тест на таком значении.

## 2. Задача

- [ ] 2.1 `SessionTask` несёт объявление, спроецированное из запечатанного
  плана при чтении, как `routed_verdicts`. Проверка: тест — задача шага с
  объявлением называет его; шаг без объявления отдаёт документ прежней формы.

- [ ] 2.2 Объявление не дублируется в `SessionHandoff`: оно уже в
  запечатанном плане, а вторая копия — второе место, где оно может разойтись.
  Проверка: тест на то, что форма handoff не изменилась.

## 3. Отчёт

- [ ] 3.1 `SessionSubmission` принимает заявление хоста: исполнил (и чем), не
  умеет, выбрал другое (и почему). Отчёт без заявления по шагу с объявленным
  профилем отказывается типизированным кодом. Проверка: три принимаемых
  формы и одна отказываемая, каждая своим тестом.

- [ ] 3.2 Заявление хранится типизированным полем попытки: исход, названная
  модель (когда хост её назвал) и причина (когда он отступил). Ни один ответ
  движка не называет его подтверждённым выбором модели. Проверка: тест — ни
  `run status`, ни `session task`, ни `next` не содержат формулировки,
  утверждающей проверенный выбор.

- [ ] 3.3 По сохранённому полю считается то, ради чего всё делается: сколько
  попыток с объявленным профилем его исполнили. Проверка: тест на Run с тремя
  попытками — исполнена, не умеет, выбрал другое — даёт три разных исхода, а
  не три строки текста.

## 4. Контракты

- [ ] 4.1 Новое семейство опубликовано рядом со старым, а не вписано в него:
  пять digest-пиннутых бандлов не меняются. `make schemas-check` сходится
  прежними sha256 на всех прежних бандлах. Измерено заранее: правка `maxItems`
  на месте даёт «Immutable invocations schema hash changed; version the new
  contract separately» — guard работает и должен остаться.

- [ ] 4.2 Потолок `state_versions`/`read_versions` поднят **в новом
  семействе**; старые бандлы байт-в-байт прежние. Проверка: новый бандл
  принимает 33 записи, любой прежний — нет, и тест это показывает обеими
  сторонами.

- [ ] 4.3 Пять утверждений против четырёх исторических бандлов
  (`CoreCapabilitiesV2`, `V12`, `V15`, `V31`) перенаправлены на текущий бандл,
  а не удалены. Рядом записано: совместимость capability-документа со старыми
  бандлами отозвана 2026-09-19 решением владельца, потому что движком
  пользуемся только мы. Проверка: тест против текущего бандла зелёный, и в
  change назван каждый из пяти.
