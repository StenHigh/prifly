## Исследование и точки интеграции

Три read-only Explore исследования выполнены в этом worktree для local/runtime, CLI/runner и contracts. Существенные выводы:

- local.Store.Apply уже связывает Run с primary ControlMutation; claims и standing grant занимают этот путь. Queue нужен отдельный keyed pure reducer со scoped task/intent CAS, а не global queue pin или переиспользование claims key.
- local.ApplyAuthority не имеет Run pins: добавить их без использования PruneRuns. Release reducer сравнивает весь актуальный association set с доказанным набором, иначе новый concurrent Run останется незамеченным.
- New callbacks проводить через transform_guard/applyControlMutation и purity.Enter. Validation/UTF-8 parsing, Run reads и process probe до write transaction. Durable reducer refusal использует local.Reject; внешний runtime API сохраняет typed Fault.
- `project_start.go` preflight выполняется до compilation/review. Queue-only path сначала строит pure exact review, резервирует intent, затем исполняет preflight и повторно проверяет accepted digest; legacy ordering сохраняется. Queue replay lookup предшествует текущим file/source/workspace checks и Drive.
- Intended Run ID выдаёт runtime-owned helper на базе startRunID; не копировать hash/owner алгоритм в CLI. Сохранённый exact result печатается без повторного Drive; admitted без result возвращает восстановленный факт, не fabricated original success.
- Plain questionnaire принимает/валидирует selection readonly, но его /4 shape не расширяется: Task показывается queue show, новая metadata попадает в prepared summary/4. Выбор /4 result после AuthorPackage branch не должен быть перезаписан /3.
- Raw Fork обходит Start через CreateLinkedRun: ранняя явная queue-source refusal закрывает этот bypass в первой версии. Legacy Fork unchanged. Project continue/recover остаётся positive supported route.
- Reopen находится в engine.go, retention pruning — retention.go. Queue guard нужен при оживлении, а queue-referenced Runs защищаются от удаления, которое уничтожило бы required history/terminal proof. Полное явное удаление authority остаётся прежней owner operation.
- ProbeProcess требует PGID==PID и не подходит обычному CLI dispatcher. Добавить local read-only exact PID/start/boot identity/probe для Linux/Darwin; неизвестное не трактовать как death. Child/external effects устанавливает explicit owner resolution, не PID.
- Sealed binding invariant чистый и локальный: нельзя читать current queue из load/decode или запрещать historical Run после update/release/done. Queue guard относится к новым admissions/reopen.
- Новое поле нельзя добавлять в closed RunStart/V2: использовать conditional durable startPayload wrapper с сохранением fork/recovery. При nil queue legacy digest/bytes остаются прежними.
- Schema generator находится в cmd/schema-gen/main.go: исключить queue field ДО recursion для прежних профилей; new state/read44 требует binding, Next42 и StepRead35 наследуются. Embed bootstrap и publicBundles/check-schema должны быть согласованы. Audit всех прежних schema paths, встроенный make schemas hash guard защищает только первые пять.
- Summary/start /3 сейчас private CLI DTOs без canonical reflected schemas. Для новых /4 нужны явные canonical document definitions и actual CLI-byte schema tests; discriminator сам не публикует contract.
- Новые tests отдельно от файлов с package-state mutations; t.Parallel только при отсутствии global/env/counter effects.
