## MODIFIED Requirements

### Requirement: Run возобновляется тем же workflow с точки остановки
Authority SHALL создавать новый Run того же workflow, продолжающий исходный
Run с точки возобновления, если исходный Run технически отказал без исхода,
либо его workflow объявил `resumable` и Run завершился объявленным исходом
или был отменён при объявленном `from_cancelled`. Точкой возобновления MUST
быть: у технического отказа — доказуемо упавшая стадия корневого вызова; у завершённого — стадия корневого
вызова, по чьему принятому результату Run пришёл в finish; у отменённого —
стадия корневого вызова, на которой он был остановлен; либо указанная
оператором завершённая стадия корневого вызова, исполненная раньше этой
точки. Точка возобновления MAY быть `step`, `call` или `repeat`; вложенный
вызов MUST исполняться заново целиком.


При техническом отказе authority MUST различать один исходный сбой и его
распространение через родительские вызовы. Единственная доказуемая цепочка
вложенного отказа MUST давать корневую точку `call` или `repeat`; несколько
независимых отказов либо недостаток evidence для этой связи MUST оставаться
отказом, в том числе при явном выборе более ранней стадии. Settled отказ
подготовки до admission MUST NOT требовать невыданную Attempt и MUST NOT
создавать или перепроверять её предполагаемый результат. Стадия в точке
такого восстановления исполняется заново при обычном допуске.

Новый Run MUST переносить только стадии, принятые до точки возобновления, —
включая принятые программные шаги, — при совпадении эффективного контракта,
входов, решений и профиля модели, как при восстановлении. Стадии после точки
MUST NOT переноситься. Пустой префикс MUST отказываться: это новый запуск.
Claim исходного Run MUST передаваться новому Run целиком; исходный Run, его
исход и история MUST оставаться неизменными. Исходный Run с активной или
неразрешённой execution MUST давать отказ до создания Run.

#### Scenario: Возобновление после partial
- **WHEN** Run объявившего `resumable` workflow завершился `partial`, потому что
  стадия `verify` вернула `blocked`
- **THEN** новый Run переносит принятые стадии до `verify`, начинает с
  `verify` в том же дереве и не исполняет перенесённые стадии снова

#### Scenario: Возобновление с более ранней стадии
- **WHEN** оператор указывает завершённую стадию, исполненную раньше точки
  остановки
- **THEN** новый Run начинает с неё, а она и все стадии после неё исполняются
  заново

#### Scenario: Workflow не объявил возобновление
- **WHEN** Run workflow без `resumable` завершился `partial`
- **THEN** authority отказывает, называя недостающее объявление

#### Scenario: Изменился контракт перенесённой стадии
- **WHEN** в новой редакции пакета эффективный контракт стадии до точки
  возобновления изменился
- **THEN** возобновление отказывает, называя стадию, как восстановление


#### Scenario: Вложенный preparation failure без Attempt
- **WHEN** один settled отказ подготовки вложенного шага до admission распространяется через записанную цепочку родительских `call/repeat`, а source Run не содержит активных либо неопределённых obligations
- **THEN** read-only prepare выбирает соответствующую корневую стадию для нового исполнения и переносит только доказанный префикс до неё, без фиктивной Attempt или revalidation

#### Scenario: Корневой шаг отказал до admission
- **WHEN** settled технический отказ подготовки корневого `step` не создал Attempt и есть непустой совместимый accepted prefix
- **THEN** prepare принимает этот `step` как точку нового исполнения без результата невыданной Attempt

#### Scenario: Ранее принятая root стадия перед вложенным отказом
- **WHEN** после доказуемого nested failure оператор выбирает ранее принятую root стадию
- **THEN** новый Run переносит только префикс перед выбранной стадией, берёт текущий source claim целиком и исполняет выбранную стадию и всё после неё заново

#### Scenario: Независимая неоднозначность
- **WHEN** записаны независимые failed activations либо нельзя доказать единственную цепочку исходного сбоя и его распространения
- **THEN** prepare отказывает без создания Run или изменения claim; указание более ранней стадии не отменяет отказ

#### Scenario: Неверный выбор и пустой prefix
- **WHEN** оператор называет nested, непринятую, более позднюю стадию либо точку с пустым переносимым префиксом
- **THEN** prepare отказывает; текущие source files, принятые inputs/answers и история сохраняются

Source set остаётся `openspec/specs/domain-execution/spec.md`; до sync действует
эта delta. Public identifiers, сохранённые JSON/schema editions и история
source Run не меняются. Проверки drift, effects и текущих прав сохраняются.
