## Context

Исключительность проверялась одним сравнением — общий каталог git
(`worktrees.go`, оба места решения). Режим рабочей копии записывался в команду и
в запись claim, но на отказ не влиял. Линкованные worktree одного репозитория
делят `--git-common-dir`, поэтому для движка они были неразличимы; зависимая
сессия измерила это исполнением.

## Goals / Non-Goals

- Goal: два Run одной ветки в разных worktree идут одновременно.
- Non-Goal: ослаблять `checkout`. Там движок работает в дереве репозитория и
  радиус последствий не ограничивает.
- Non-Goal: разрешать одному атомарному захвату называть репозиторий дважды.
  Это другой вопрос — один Run с двумя деревьями одного репозитория, — и он не
  нужен ни одной из сторон.

## Decisions

### Решение 1: ресурс — рабочее дерево, и оно уже названо

`claim.Path` и есть занимаемое дерево: у `worktree` это собственный каталог под
`.prifly/work/claims/`, у `checkout` — `Toplevel` репозитория. Заводить новое
поле не понадобилось; отношение конфликта переехало на то, что запись уже
несла.

### Решение 2: `checkout` сохраняет прежнюю широкую исключительность

Правило было одно на два режима. Для `worktree` оно строже предмета: два дерева
делят объекты и ссылки, которые git сериализует своими блокировками, а `git
worktree add` пишет в `.git/worktrees/<имя>` и создаёт ветку — имена выводятся
из идентификатора команды и не сталкиваются.

Для `checkout` то же рассуждение не проходит: Run работает **в** дереве
репозитория, и что он там делает, движок не ограничивает. Поэтому `checkout`
исключает и исключается всем на этом репозитории — ровно как раньше.

### Решение 3: счётчик поколений остаётся по пути

Поколение считает повторные захваты **одного дерева**. `checkout`, который лишь
исключает этот claim, не является более ранним поколением его дерева, поэтому
сравнение по пути сохранено отдельно от отношения конфликта.

### Решение 4: столкновение двух worktree по одному пути недостижимо

Путь выводится из идентификатора команды, поэтому «взять то же дерево дважды» —
это та же команда, и она упирается в идемпотентность раньше конфликта. Проверка
в тесте поставлена на достижимый случай: `checkout` при активных worktree.

## Risks / Trade-offs

- Общий стенд проектом не объявляется, и движок про него не знает. Раньше
  исключительность защищала от одновременных прогонов по одной тестовой базе —
  **по совпадению границ, а не по замыслу**. Теперь эта защита снята, и проект,
  которому она была нужна, обязан развести стенд сам. Названо здесь, потому что
  зависимый проект на это опирался, не зная того.
- Освобождение завершённого claim осталось по репозиторию: claim нового дерева
  освобождает завершённые claim соседних. Они завершены, каталог одноразовый,
  вреда нет; сужение до дерева оставило бы мусор до следующего захвата того же
  дерева.

## Migration Plan

Обратно совместимо: запись claim не меняется, историческая запись без режима
читается как `worktree`, как и раньше.
