## Context

[Предложение](proposal.md) фиксирует проблемы, воспроизведённые на развёрнутом Full v0.13.92. Исходный аудит не проверял два одновременно работающих Run. Он проверил два завершённых Run во вкладках и живой прогресс программы в изолированной authority.

Нормы Full принадлежат [local-run-monitor](../../../specs/local-run-monitor/spec.md). Дельта уточняет существующие правила каталога, достоверности, прямых ссылок и обновления. Общие нормы [control-security-ux](../../../specs/control-security-ux/spec.md) применяются и дальше. Источник Light остаётся указанным в [карте источников](../../../SOURCE-OF-TRUTH.md).

## Goals / Non-Goals

**Цели.** Сделать наблюдение доступным с первого экрана. Сохранить глубину разбора и точные ссылки. Дать оператору два независимых снимка на одном экране.

**Границы.** Не переносить классификацию Run в браузер. Не менять Go, runtime, HTTP-контракты, JSON Schema, историю Run или replay. Не добавлять управления Run, режима сравнения артефактов или синхронизации закреплений между устройствами.

## Decisions

### D1. Короткий обзор над историей

Начало каталога показывает до двух текущих Run. Для обзора достаточно первых страниц существующего `/api/runs` по `running` и `stopping` в плоском виде. Плоский вид уже сортирует по последнему наблюдению, если порядок не задан. Объединяем только первые результаты этих двух выборок. Пары источника и Run объединяем без дубликатов. При смене состояния выбираем целую запись с большей версией и номером события. При равном времени используем устойчивый порядок источника и Run ID.

Поиск, проект, исполнитель и период действуют и в обзоре. Фильтр состояния управляет историей отдельно. Переход «Текущие» открывает плоский отбор с доступными состояниями «В работе или ожидании» и «Остановка выполняется». Каждое использует свою серверную пагинацию. Обзор сообщает, если показана только часть. При сбое одного чтения он сохраняет доступную часть с явной отметкой неполноты. Отбор «Недавние» открывает плоский вид по последнему наблюдению. «С ошибкой» выбирает `failed`. Связанный вид остаётся исходным для истории.

Счётчик `active` описывает Run с активными Attempt во всём прочитанном каталоге. Он не заменяет число совпадений `running` и `stopping`. Для этих состояний подписываем счётчики отдельно. Сумму двух независимых чтений не показываем как точный общий счётчик. Пагинация видна сверху и остаётся снизу. Каталог восстанавливает из query существующие параметры поиска, фильтров, вида, порядка и страницы. Проверяем допустимые значения, сохраняем префикс установки и используем страницу, возвращённую API. Состояние `ready` не входит в текущий отбор. Его по-прежнему можно найти в истории, включая случаи ожидания допуска.

Альтернатива с перестановкой строк текущей страницы скрывает Run с других страниц. Полная выгрузка истории ради клиентского отбора создаёт лишние чтения. Отдельный обзор сохраняет прежний порядок связанной истории.

### D2. Экран Run показывает то, что читает

Основной блок и вкладки находятся перед техническими раскрытиями. Обзор показывает записанный статус и исход Run, текущие стадии, известное ожидание и источник причины. При `awaiting_host` пишем, что задание выдано и принятие не записано. Статус отдельной Attempt остаётся отдельным от статуса Run. Сохраняем объяснения действующих причин и различия между отказом вложенной работы и неизвестной первопричиной.

| Сведение | Источник | Отображение |
|---|---|---|
| Последнее успешное чтение | Время принятия браузером ответа выбранного `/api/run` | На экране Run. При сбое прежний снимок помечен устаревшим |
| Последнее наблюдение Run | `run.last_observed.utc` | Отдельная подпись. Не используем вместо времени отдельного события |
| Активность драйвера | `driver_live` из чтения Run | Подтверждена либо не подтверждена. Без догадки о хосте |
| Прогресс программы | `/api/progress` для соответствующей Attempt | Фаза и счётчик при наличии. Возраст и исторический отчёт обозначены отдельно |
| Позиция журнала | `seq` из `/api/events` | Последовательность. Время события только при наличии в самой записи |

Отказ вспомогательного чтения не стирает основной снимок. При смене Run отбрасываем опоздавшие ответы. Для прогресса дополнительно сверяем Attempt. Вкладки «Обзор», «Схема и шаги», «Результаты и решения» и «Журнал» ведут к прежним данным. Время, ресурсы, входы и служебные поля остаются доступны по раскрытию.

### D3. Видимый выбор и недавний журнал

Прямые ссылки со старыми `source`, `run`, `tab`, `node` и `invocation` продолжают работать. Ссылка без вкладки с узлом или исполнением открывает схему. Новая ссылка из каталога без узла ведёт в обзор. При явном выборе шага на телефоне показываем панель шага и переносим фокус к её заголовку. Возврат открывает прежнее дерево и строку. Опрос не переносит фокус. Выбранный закреплённый план сохраняем в адресе только как добавочный параметр клиента. Некорректный параметр приводит к доступному плану.

Журнал получает недавнюю часть через существующий `after`, начиная с ограниченного окна перед `event_sequence` выбранного Run. Один запрос возвращает до 200 событий. В обзоре показываем до трёх недавних записей. Если хвост не достигнут или часть недоступна, обозначаем границу чтения. Полная хронология начинается с существующего курсора и подгружается по страницам. Следование за новыми событиями включается явно. Когда оно выключено, видимая запись не сдвигается.

Ссылка к причине выбирает записанный узел, Attempt или однозначную запись журнала. В браузерный фрагмент можно добавить номер события. Номер используется только в выбранном источнике и Run. Для ссылки на событие достаточно существующего чтения после предыдущего номера с проверкой найденной записи. При неопределённой связи открываем названную область, например журнал. Переход к области сохраняет выбор и ставит фокус на её заголовок даже при уже открытой вкладке.

Альтернатива с новым API для хвоста или времени событий меняет контракт. Ограниченный запрос и честные подписи используют доступные записи.

### D4. Два закрепления и независимые циклы чтения

Храним до двух пар `source + run_id` в `sessionStorage` вкладки. Если хранилище недоступно, сохраняем выбор до конца жизни страницы. Повторное закрепление той же пары не создаёт карточку. Третье закрепление отклоняем с подсказкой снять одну из двух. Терминальный Run остаётся в паре. Прямая ссылка на Run не включает закрепления. Для названия используем уже прочитанную строку этой пары или доступное название задачи из чтения Run. Если после перезагрузки название отсутствует в этих данных, явно показываем, что оно не прочитано.

Экран наблюдения читает каждый закреплённый Run независимо. Читаем не более одного `/api/run` и одного `/api/progress` для него за цикл. Прогресс запрашиваем при известной программной Attempt. Если работает несколько программ, их отчёты остаются привязаны к своим Attempt. Общий процент не вычисляем. После завершения сохраняем последний доступный отчёт как исторический. На этом экране не опрашиваем скрытый каталог, журнал или артефакты. При одиночных подробностях сохраняем отдельные чтения видимой области. Для каждого запроса допускаем одно чтение в полёте. Смена выбора отменяет ожидание или отбрасывает ответ прежнего запроса. Один сбой не задерживает публикацию успешного снимка другого Run.

На широком экране показываем карточки рядом, на узком друг за другом. У каждой свой статус, текущая стадия или ожидание, последнее наблюдение и подпись свежести. Прогресс отображаем только по данным соответствующей Attempt. Общего времени чтения или исхода для двух Run нет.

Альтернатива с отдельными вкладками сохраняет ссылки, но вынуждает переключаться. Общий снимок двух authority потребовал бы новый контракт. Ограниченный экран работает через существующие чтения.

## Risks / Trade-offs

| Риск | Проверка и ограничение |
|---|---|
| Связанный вид и отбор текущих Run расходятся | История остаётся связанной. Текущий отбор плоский и показывает область счётчиков |
| Поздний ответ перезаписывает другой Run | Проверяем пару источник и Run, поколение запроса и выбранную Attempt |
| Опрос скрытых панелей увеличивает нагрузку | Считаем запросы при двух закреплениях и при открытии одного Run |
| Курсор показывает только часть истории | Обозначаем границу окна и сохраняем ручную постраничную навигацию |
| Новый интерфейс скрывает доступные данные | Проходим вкладки, раскрытия, сохранённый артефакт и вывод программы в браузере |

## Migration Plan

Миграция хранения не требуется. Ссылки с прежними параметрами продолжают читаться. Закрепления живут в текущей вкладке и не входят в состояние authority. При откате прежний Full игнорирует добавочные параметры клиента.
