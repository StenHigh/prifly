## ADDED Requirements

### Requirement: Локальная проверка повторно используется только для тех же входов

Процесс разработки репозитория SHALL разрешать повторное использование
успешного локального результата только при совпадении полного снимка входов,
состава команд, toolchain и применимого контекста исполнения. Снимок MUST
учитывать содержимое файлов, добавления, удаления, режимы и применимые
untracked/ignored inputs; отсутствие Git diff само по себе недостаточно.
Evidence MUST называть источник, время и границы результата. Неуспешный,
неполный, устаревший, повреждённый либо непроверяемый результат MUST NOT
заменять исполнение проверки. Изменение входов во время проверки MUST
запретить сохранение результата как пригодного для повторного использования.
Явный принудительный повтор MUST выполнять команды заново.

#### Scenario: Verify и commit проверяют один снимок

- **WHEN** итоговый снимок уже прошёл полный локальный состав и его входы и контекст не изменились
- **THEN** следующая стадия использует проверяемый результат, называет источник и не повторяет дорогие детерминированные проверки

#### Scenario: Изменился вход проверки

- **WHEN** изменён исходник, test, fixture, схема, читаемый документ, состав команд, toolchain, значимый environment либо применимый untracked input
- **THEN** прежний результат не подходит, причина видна и обязательная проверка выполняется заново

#### Scenario: Дерево изменилось во время исполнения

- **WHEN** команда завершилась успешно, но снимки до и после неё различаются
- **THEN** её наблюдаемый исход сохраняется в отчёте с ограничением, а пригодный для повторного использования успех не записывается

#### Scenario: Содержимое изменено без изменения Git status

- **WHEN** уже dirty файл изменился повторно либо добавился ignored input, используемый проверкой
- **THEN** сравнение фактических входов запрещает прежний результат; одинаковый список modified paths не доказывает эквивалентность

#### Scenario: Свежесть зависит от внешних данных

- **WHEN** обязательная проверка уязвимостей использует актуальную внешнюю базу
- **THEN** совпадение исходников не заменяет свежую проверку этой базы; её неуспех блокирует общий результат даже при пригодных остальных результатах

### Requirement: Обычный Run сохраняет обязательный состав без релизного batch

Во время правок репозиторий SHALL использовать затронутые проверки, а перед
commit MUST иметь полный успешный локальный состав для итогового снимка,
полученный исполнением или пригодным повторным использованием. Стандартный
проектный Run MUST NOT дополнительно запускать полный race/e2e batch,
предназначенный для релизного `qualify`. Явно объявленная дополнительная
проверка конкретной задачи либо запрос владельца сохраняет силу. Повторное
использование команд MUST NOT подменять semantic verify/review плана,
принимать StepResult или продвигать Run вне объявленного графа.

#### Scenario: Обычная реализация дошла до verify

- **WHEN** текущий проектный `gate_checks` применяется к обычному Run
- **THEN** он обеспечивает полный локальный состав, OpenSpec validation и diff check, без неявного добавления release race/e2e

#### Scenario: Требуется проверка конкретного e2e поведения

- **WHEN** план или владелец явно требует воспроизвести затронутый пользовательский сценарий
- **THEN** этот сценарий проверяется и отражается отдельно; отсутствие полного релизного batch не отменяет целевую приёмку

Source set остаётся `openspec/specs/quality-and-acceptance/`; до sync действует
delta этого change. Термин Reuse сохраняет значение словаря. Public identifiers,
runtime contracts и historical evidence не изменяются.
