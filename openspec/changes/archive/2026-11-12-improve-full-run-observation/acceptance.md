# Приёмка наблюдения в Full

## Основание

Расширенный аудит v0.13.92 проверил открытие шагов и Attempt, все 12 секций результатов, журнал, артефакт, вывод программы, переключение вкладок и повтор чтения. В развёрнутом Full был один Run с активной Attempt. Два завершённых Run проверены во вкладках. Изменение прогресса проверено отдельно на изолированных Run.

Приёмка ниже относится к будущему кандидату. Она добавляет проверку одновременного исполнения двух Run.

## Сценарии

Chromium проверяет Full на 1440×900 и 390×844 при масштабе 100%. На репрезентативном коротком наборе название и состояние обоих закреплений читаются без горизонтальной прокрутки. Мобильные и клавиатурные сценарии используют реальные действия в интерфейсе. Сетевые отказы помечаются как имитация.

| ID | Сценарий | Наблюдаемый результат |
|---|---|---|
| O01 | В первой странице истории только завершённые Run. Текущий производный Run расположен дальше | Текущий Run найден без ID. Его название и состояние доступны с первого экрана. Предки остаются в связанном виде |
| O02 | Каталог на странице 2 с поиском, проектом, видом и порядком | Адрес открывает тот же отбор в новой вкладке. Верхняя навигация доступна. Возврат сохраняет строку и фокус |
| O03 | Отбор текущих Run, один ответ недоступен либо приходит поздно | Успешная часть остаётся видимой. Источник неполноты обозначен. Отсутствие данных не показано как ноль |
| O04 | Список успешно прочитан, а чтение Run не удалось. Отдельно недоступен прогресс или ресурс | Подпись относится к открытому Run. Повтор восстанавливает чтение. Сбой вспомогательного запроса не стирает состояние Run |
| O05 | Хост ещё не принял задание. У программы есть отчёт о прогрессе | Список и обзор различают ожидание хоста и работу программы. Прогресс обновляется при прежней версии Run |
| O06 | Оператор выбирает Attempt, WorkflowInvocation или закреплённый план | На телефоне виден заголовок выбранной панели. Возврат сохраняет фокус. Старая точная ссылка и новая ссылка на план открывают правильные сведения |
| O07 | Журнал содержит более 200 событий, открыта старая запись | Есть недавняя часть и доступ к полной хронологии. При выключенном следовании новая запись не сдвигает старую |
| O08 | Однозначная причина указывает на Attempt или событие. Другой Run не даёт точной связи | Первую запись видно после одного перехода. В другом случае подпись точно называет область и переход меняет фокус |
| O09 | Длинное название, артефакт, исходный текст, вывод программы и переход из Light | Название и состояние читаются вместе. Технические сведения доступны. Прежние ссылки, темы и возврат работают |
| O10 | Два Run работают одновременно. Первый публикует новый прогресс | Обе карточки видны в одном экране наблюдения. Прогресс меняется только у правильной Attempt. Обе ссылки открывают свои Run |
| O11 | Чтение первого Run прерывается, второй Run завершается | Первый снимок помечен устаревшим. Второй показывает записанный исход. Восстановление первого не меняет второй |
| O12 | Повторное закрепление, третий Run, перезагрузка, одинаковый Run ID в разных источниках | Предел равен двум парам. Состав и порядок сохранены. Совпадение ID между источниками не смешивает карточки |

## Обязательная проверка двух одновременно работающих Run

```text
Запустить A и B → подтвердить одновременную работу → закрепить обе пары
    → изменить прогресс A → прервать чтение A и завершить B
    → восстановить чтение A → сверить оба исхода
```

1. Используйте два временных authority с отдельными рабочими каталогами. Переиспользуйте `test/fixtures/foundation/create-demo.py` и протокол программы из `test/e2e/verify-progress.py`. Возьмите также штатный экспорт истории Full для O01 и O09.
2. Запустите два Run с помощью собранного кандидата. Программы публикуют разные фазы и счётчики через штатный дескриптор. Каждая ждёт отдельного сигнала от теста.
3. До подачи сигналов подтвердите перекрытие исполнений. Оба `/api/run` показывают `running` и `driver_live=true`. Оба `/api/progress` возвращают отчёт незавершённой Attempt. Зафиксируйте пары источник и Run, Attempt ID, версии и номера событий.
4. В одной вкладке браузера найдите и закрепите оба Run. Проверьте расположение карточек на широком и узком экране. Откройте каждую ссылку и вернитесь к той же паре.
5. Дайте первой программе опубликовать вторую фазу без завершения. Проверьте новый счётчик при прежней версии Run. Вторая карточка должна по-прежнему показывать собственную фазу.
6. Верните HTTP 503 для чтения первого Run только в контексте браузера. Завершите второй Run штатным результатом. Проверьте независимые подписи и сохранённый исход.
7. Восстановите чтение первого Run и завершите его с другим исходом. Проверьте обе карточки и исторический прогресс. Запишите фактические исходы и очищенные временные процессы.

Сигналы теста действуют только в принадлежащих ему временных каталогах. Используйте ожидание наблюдаемых условий с конечным тайм-аутом. Последовательные запуски, терминальные снимки и подменённый JSON не доказывают перекрытие исполнений. Имитация 503 проверяет только поведение браузера.

## Команды и неизменность контрактов

- `make ui-check` проверяет представление, ссылки, состояние запросов и раздельные снимки. Включает существующие тесты Full и Light.
- `python3 -B test/e2e/verify-monitor-board.py --binary "$PRIFLY_BIN" --playwright-module "$PLAYWRIGHT_MODULE" --chromium "$CHROMIUM"` запускает прежние браузерные сценарии.
- Та же команда с `--scenario observe` запускает новый сценарий после его реализации. Опция относится только к тестовому скрипту.
- `make test-changed` или `make check-fast` запускайте во время работы. Перед коммитом выполните `make ci-check-once CHECK_CONTEXT=<actual-profile> CHECK_FOR_COMMIT=1` и `git diff --check`. Race и полный e2e относятся к релизу.

Сохраните базовый SHA. Сверьте по нему байты `internal/`, `schemas/`, `test/fixtures/`, `openspec/changes/archive/`, исходников HTTP Full и активного source set Light. Учитывайте новые файлы и индекс. Проверка схем и прежних Go-тестов replay входит в полные ворота. Существующий сценарий браузерного воспроизведения продолжает выполняться.

В браузерной трассе наблюдения разрешены GET и HEAD. Для двух закреплений за цикл допустимы до двух чтений Run и до двух чтений прогресса. Скрытые каталог, журнал и артефакты не опрашиваются. Запишите реальные запросы, переходы, размеры экрана, результат каждой проверки и очистку слушателей.
