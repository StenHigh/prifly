# Проверять форму аргументов в эксплуатационных примерах

**Date:** 2026-11-02 17:53
**Files:** examples/operations/authoring.md и generated host copies
**Severity:** medium

## Проблема

Пример project extend передавал путь вместо inline JSON в --step-ref.
Он также описывал обязательный --step-source как необязательный.
Команда возвращала project_extension_invalid_step_ref.

## Причина

Проверка inventory подтверждала наличие flags, но не форму их значений и зависимость аргументов.
Новый текст не сверили с parser и существующим успешным fixture.

## Решение

Пример передаёт ImmutableRef через STEP_REF_JSON и обязательный парный source.
Scratch fixture исполняет аргументы из Markdown до и после правки.
До правки: exit 2. После правки: exit 0, ref и binding сохранены.
Диагностика scratch проверки использует [FIX]; runtime logging не меняется.

## Предотвращение

Проверять значения и пары flags по parser, а runnable fragments исполнять с минимальным fixture.
Не считать AST coverage доказательством семантики команды.
Следующее полезное расширение: исполнять representative installed example commands без Core checkout.
