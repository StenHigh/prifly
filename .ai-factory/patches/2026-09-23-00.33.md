# Успешный потомок скрыт за ошибочным родителем Run

**Дата:** 2026-09-23 00:33 UTC
**Файлы:** `cmd/prifly/monitor_list.go`, `cmd/prifly/monitor.js`, `cmd/prifly/monitor_catalog_test.go`, `cmd/prifly/monitor_ui_test.cjs`
**Серьёзность:** средняя

## Проблема

У задачи #154 последний восстановительный Run завершился с `outcome=succeeded`, но свёрнутая строка его ошибочного родителя показывала только `failed`; читатель не видел успешное продолжение. Соседние Run шли от новых к старым.

## Первопричина

Иерархический API передавал количество потомков, но не факт о последнем из них. UI не мог показать итог скрытой ветви, а сортировка каталога по убыванию `last_observed` затрудняла чтение истории сверху вниз.

## Решение

Локальная read-only проекция передаёт status/outcome и ссылку на последнего доступного производного Run отдельно от статуса родителя. Иерархические соседи упорядочены по `created` от ранних к поздним. Равное время разрешается по ID; фильтр не меняет выбор последнего потомка. Диагностика `[FIX:run-lineage]` включается только при `LOG_LEVEL=debug`.

## Предотвращение

- Проверять ветвь, где ранние Run ошибочны, а поздний успешен.
- Проверять свёрнутую ветвь, фильтр и равное время; не выводить общий outcome семьи.
- Для иерархического списка отличать собственный статус строки от состояния её потомков.
