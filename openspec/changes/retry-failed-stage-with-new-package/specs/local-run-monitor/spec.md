## ADDED Requirements

### Requirement: Монитор объясняет восстановление Run

Монитор SHALL показывать source и новый Run как разные записи с явной связью. На схеме и в карточке стадии он MUST отличать reused evidence, повторно оценённый candidate, новое исполнение и стадию, до которой маршрут ещё не дошёл; причину отказа от reuse MUST показывать из сохранённого решения authority, не выводить по цвету или имени стадии.

#### Scenario: Продолжение после tests schema failure
- **WHEN** владелец открывает восстановленный Run
- **THEN** он видит `verify` и `review` как перенесённые с источником, `tests` как повторную приёмку либо повторное исполнение и ссылку на исходный failed Run

#### Scenario: Старый Run открыт отдельно
- **WHEN** владелец открывает source Run
- **THEN** его исторический failed статус и диагностика сохраняются без перекраски в успех нового Run
