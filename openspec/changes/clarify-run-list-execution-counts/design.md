## Context

См. proposal.md и delta spec. `RunSummary` уже отдаёт `step_instances`, `attempts`, `settled_attempts`, `active_attempts` и `awaiting_hosts`. `MonitorSummary` считает созданные `Run.Steps` и `Run.Attempts`, а не узлы определения Workflow. Сейчас `monitor.js` превращает первые два числа в `N / M`, а третье подписывает как «попыток завершено». Канонические смыслы StepInstance, Attempt и Settlement закреплены в словаре. Нормативный source set — `openspec/specs/local-run-monitor/`.

## Goals / Non-Goals

**Goals:** исправить прочтение существующих счётчиков в общей таблице без изменения данных или поведения Run.

**Non-Goals:** вычислять общий процент Workflow, подсчитывать будущие Stage, вводить новые поля read API или новую телеметрию.

## Decisions

### Вместо дроби — две подписанные величины

В ячейке показывать «Создано шагов: N» и «Попыток: M» отдельными фразами. Следующая строка показывает «Учтено попыток: S» и, если `M > S`, «Ещё не учтено: M−S»; при `awaiting_hosts > 0` рядом указывать «ожидает агента: H». Это не progress bar и не отношение `N/M`: повторная Attempt увеличивает только M. Альтернатива — переименовать заголовок колонки, сохранив дробь — оставляет её ложное чтение «из общего числа».

### Смысл доступен без hover

Дать короткое текстовое пояснение в заголовке/подписи таблицы, доступное с клавиатуры и на узком экране: «Шаги — созданная работа; попытки — отдельные исполнения этих шагов. Это не доля всего сценария». Не полагаться только на `title` или цвет. Outcome и status остаются в своей колонке, чтобы учтённая попытка не выглядела успешной. Альтернатива — отдельная справочная страница — хуже помогает в момент чтения строки.

### Не расширять read projection

Использовать те же `RunSummary` поля, не менять `MonitorSummary` и не мигрировать старые Runs. Перед вычислением разности проверять, что оба числа присутствуют и `0 ≤ settled_attempts ≤ attempts`; при неконсистентном/недоступном ответе показывать «неизвестно», а не отрицательное число. Обновление списка сохраняет фильтр и позицию чтения по действующему механизму.

## Risks / Trade-offs

- [Ячейка станет выше] → короткие строки и CSS для узкой ширины; не возвращаться к безымянной дроби.
- [«Учтено» можно принять за успех] → пояснение Settlement и раздельная колонка исхода; не использовать зелёный цвет у самого счётчика.
- [Старый/частичный источник не даёт все поля] → явное «неизвестно» вместо выдуманного нуля или отрицательной разности.
