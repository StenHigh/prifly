Проверки адресные по затронутым packages, с записью команд и счётчиков. Дорогие
ворота один раз на собранном кандидате. Внешняя проверка на трёх видах захвата —
за сессией пакетов, она её предложила и подтвердила обязательство.

## 1. Манифест несёт объявленную привязку

- [ ] 1.1 Установить фактом, где собирается рабочий манифест и какие поля в него
      попадают сегодня; записать место в коде. Проверить, что привязка шага в
      этот момент доступна, а не восстанавливается из плана заново.
- [ ] 1.2 Манифест несёт привязки того шага, для которого подготовлен: имена
      портов и политику захвата целиком. Форма — тот же объект, что объявлен в
      шаге, без выборки полей. Проверка: шаг с `direct_child_tree` показывает
      вид, путь и точку входа.
- [ ] 1.3 Шаг без объявленных привязок получает манифест прежнего содержания.
      Проверка: сравнение с манифестом до правки отличается только строкой
      версии.

## 2. Версия контракта манифеста

- [ ] 2.1 `local-context/1` → `/3` и `local-context/2` → `/4` согласованно:
      запись, обе константы схем и их читатели, включая фикстуры на Python,
      сверяющие строку равенством. Проверка: проверки продолжают читать
      свой манифест, а не отказывают на собственной версии.
- [ ] 2.2 Прежние бандлы не сдвинулись; новый бандл, если он появляется,
      закреплён. `make schemas-check` зелёный, счётчик бандлов записан.

## 3. Неверный ответ соседнего поля

- [ ] 3.0 У порта, чей результат захватывается, манифест не называет путь слота
      как место записи. Проверка: у шага с привязкой в `outputs.<slot>` нет
      адреса, по которому писать нельзя; у обычного порта поле не изменилось.

## 4. Отказы, которые перестают быть единственным источником

- [ ] 4.1 `workspace_tree_output_host_supplied` и
      `workspace_tree_capture_conflict` сохраняют свои коды и тексты: манифест
      сообщает контракт, но не отменяет его проверку. Проверка: оба отказа
      воспроизводятся после правки.

## 5. Завершение

- [ ] 5.1 Синхронизировать дельту с основными спеками; проверка:
      `openspec validate --all --strict --no-interactive`, `git diff --check`,
      пустой `git diff --name-only <база> -- openspec/changes/archive`.
- [ ] 5.2 Evidence: один раз `make check` и `make e2e` на собранном кандидате,
      результаты записать здесь. Обе зависимые сессии предупреждены до начала
      работы; предупредить повторно, если форма изменилась против объявленной.
- [ ] 5.3 Внешняя проверка сессией пакетов на профилях `fast`, `full`, `ultra`:
      содержимое привязок из манифеста дословно, сверка байт в байт с
      объявленным в скомпилированном шаге, и манифест шага без захвата. Записать
      их вывод как есть. Закрытие roadmap milestone или product gate не
      объявляется.
